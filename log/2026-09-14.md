# 2026-09-14 — Agent Pattern Scan

## TL;DR
Three concrete patterns today, all mechanism-level. Amp's event-driven orbs (July 23) turn coding agents into webhook-woken services — an "external HTTP event resumes the agent's context" skeleton that generalizes past coding. Perk's outbound SDR ran on Salesforce's new long-horizon runtime and built 60% of North American pipeline in two weeks. And the community-intent-mining pattern from an Indie Hackers roundup shows a distinct twist on Reddit scraping: not to create products (already logged 4/22) but to find and reply to buyers of a product that already exists.

## Patterns

### 1. The webhook that wakes a coding agent with its context intact
**Source:** [Amp event-driven orbs, July 23 2026](https://ampcode.com/news/event-driven-orbs) + [Digital Applied writeup](https://www.digitalapplied.com/blog/amp-event-driven-orbs-self-scheduling-agents-2026) — Sourcegraph's Amp coding agent gained event-driven "orbs" (persistent agent threads) that wake on external HTTP calls. Amp's own docs call the webhook URL a credential.

**Mechanism:** A developer creates an "orb" (a long-lived agent thread with a codebase, tools, and memory attached). Inside the orb, the developer asks Amp to listen for a specific event; Amp calls `amp.createWebhook`, which registers a durable HTTPS endpoint bound to that thread. When any external system POSTs to the URL (CI job failed, Linear issue opened, monitor tripped, arbitrary internal service), the orb wakes with all prior context intact, reads the payload, runs whatever plan it was given, edits/commits code, and returns to sleep. Replaces the human step of "notice the alert → open a session → paste the context in → start typing" plus the reboot cost of a stateless agent.

**Why agentic:** The trigger is arbitrary external state, not a fixed rule. The agent decides which of its tools to call, whether to consult the human, whether to open a follow-up thread. Context persists across wakes, so it can pursue a multi-step debugging or triage without starting over. A dashboard would show that CI failed; this fixes it.

**Generalizable core:** external HTTP event → wake a stateful agent thread with retained context → agent reads payload + prior state → acts → hands result back to human or another thread.

**Deployability:** Available today on Amp; the underlying skeleton is trivially reproducible in Claude Code + a durable job queue (Cloudflare Workers, Inngest, Temporal, or a simple Postgres+cron with a resumable state blob), or n8n's webhook trigger firing into a Claude/OpenAI agent runner. Weekend build for one flow, week build for the platform pieces (auth, replay, dead-lettering). Replaces: the "someone has to notice and start the fix" step in ops. Scale caveat: it's most useful when the agent has real context to keep — for a stateless "call an LLM on this payload" flow, plain automation is cheaper.

### 2. The outbound SDR that works the same lead for eight weeks without a human plan
**Source:** [Perk case study, Salesforce customer stories](https://www.salesforce.com/customer-stories/perk/) + [Applied.co breakdown](https://theapplied.co/use-cases/how-perk-sdr-team-built-60-percent-of-north-american-pipeline-using-agentforce-prospecting-agent) — Perk's SDR team deployed Salesforce's Agentforce prospecting agent (now branded "Hunter") on the new long-horizon runtime announced 2026-09-11. Two weeks from setup to live; call volume 3x, email reply rates 2x, agent-attributed share reached 60% of North American pipeline.

**Mechanism:** A goal is set once ("qualify N accounts in this ICP against this offer this quarter"). Instead of a Zap-style if/then chain, the agent maintains a per-prospect state — what it's read, what it's sent, what came back, what to try next — across days and weeks. It researches the account from CRM + external sources, chooses a channel (email, call, LinkedIn), drafts and sends, records the reply verbatim in the CRM, decides whether to wait, escalate, hand off to a human closer, or archive. Human SDRs review the queue and steer with plain-English instructions ("stop sending to VPs of Eng at fintechs, focus on Data leads"); the agent updates its plan accordingly. Replaces the SDR's daily list-planning, cadence management, and CRM upkeep — humans move to conversations that require judgment.

**Why agentic:** The behavior isn't a workflow that fires on triggers; it's a plan that survives across sessions. The agent decides what to do next based on the state of the pursuit, not on which webhook just fired. Steering is verbal, not code changes. It fails softly (asks the human) rather than crashing on unhandled cases.

**Generalizable core:** goal defined once → agent maintains per-target state and memory across weeks → agent chooses next action from state → human steers verbally, not by editing the workflow → hand off to human on defined thresholds.

**Deployability:** Full-stack Agentforce is enterprise-priced. The pattern reproduces at SMB scale on Claude/OpenAI + a persistent state store (Postgres, Firestore) + a scheduler that periodically re-invokes the agent with its state loaded. Month build to do it well; the hardest parts are memory hygiene (what to keep, what to summarize) and steering primitives (letting the human change the plan without breaking prior state). Replaces or augments the SDR's list-management and cadence work. Scale caveat: it's overkill unless the pursuit really takes weeks; short cycles are still better served by a standard sequenced workflow.

### 3. The subreddit scanner that finds buyers for products you already sell
**Source:** [Indie Hackers roundup: "5 AI agent workflows actually making money in 2026"](https://www.indiehackers.com/post/5-ai-agent-workflows-actually-making-money-in-2026-with-real-numbers-ea266790ba) — solo operators running Reddit-intent workflows generating $2K–$10K/month in pipeline value. *Variation of 2026-04-22 entry (Felix agent) — new angle: this pattern finds buyers for an existing product, not build new products from Reddit pain points.*

**Mechanism:** A worker watches 15–20 target subreddits on a short interval (5–15 min). For each new post/comment, it filters against a buyer-intent keyword set specific to a product ("looking for a tool that…", "does anyone know a way to…", "alternatives to X"). The agent classifies each hit by intent level (high / medium / low) using the surrounding context, drafts a non-promotional reply that leads with genuine help and mentions the product only when relevant, and — separately — writes the poster's handle, subreddit, and inferred use case into a lead database with the source link. High-intent posts get flagged for immediate human review before the reply is posted; lower-intent posts get auto-drafted for daily batch approval. Replaces the "someone on the team lurks Reddit and screenshots leads to Slack" habit that most SaaS companies never actually staff.

**Why agentic:** The reply is not a template — it reads the whole thread, matches the poster's problem to specific product features, and phrases things in the vernacular of that community. The lead-database entry is not a form submission; it's an enriched record with an inferred use case. A dashboard listing all mentions of a competitor's name would be a search alert; this actually decides whether to talk.

**Generalizable core:** continuous community scan → classify each hit by buyer intent → dual output: helpful public reply + private enriched lead record → human approves the sensitive half.

**Deployability:** n8n or Make + Reddit API (or a scraper) + Claude/OpenAI for classification and drafting + Airtable/HubSpot for the lead DB + Slack for approvals. Weekend build for a single-subreddit MVP, week build for the intent-classifier and reply approval flow. Replaces the manual "watch Reddit for us" role that mostly doesn't get done. Scale caveat: reply cadence has to stay well under Reddit's spam thresholds — one careless auto-post gets the account banned; approval-before-send is not optional early on.
