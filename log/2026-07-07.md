# 2026-07-07 — Agent Pattern Scan

## TL;DR
Three patterns worth logging today. The most novel is Bylaw's pre-write source-agreement check, which sits between an agent and its next tool call and blocks the write if the underlying evidence disagrees across systems — a middleware pattern for anyone deploying other agents. Also concrete: Whitespace's multi-channel B2B order intake to ERP and Browserbase's cron-scheduled catalog validation using Claude Managed Agents with vault-injected credentials.

## Patterns

### 1. Cross-source truth check before an agent writes
**Source:** [Bylaw (YC S26)](https://www.usebylaw.com/) — runtime enforcement layer for agent tool calls, targeting teams shipping agents into CRM/finance/ops systems.
**Mechanism:** trigger is another agent about to call a write tool (create record, send message, post entry). Bylaw intercepts the proposed action, collects the evidence trail the agent built its argument on — chat context, retrieved docs, CRM fields, prior tool results — checks source, freshness, whether the fact was observed or inferred, and whether sources agree at the moment of the write. Reads span whatever knowledge sources the agent touched. Action: if evidence passes, the write proceeds; if it fails, Bylaw blocks the call, restricts it (partial write with fields dropped), or routes it to a human queue. Replaces the "post-hoc eval + human audit" loop that catches mistakes only after they've hit production data.
**Why agentic:** it's an agent whose trigger is another agent's proposed action and whose output is a decision that changes control flow. Not a report of what an agent did — an intervention in what an agent is about to do.
**Generalizable core:** proposed write from any agent → verifier agent enriches with source lineage/freshness/agreement → blocks, restricts, or routes to human → replaces post-hoc eval and manual QA of agent output.
**Deployability:** ships as an SDK/proxy that wraps tool calls, so integration is at the agent framework layer (LangChain, MCP tool registries, Claude Skills, custom LangGraph). Complexity is a week build if you already have an agent stack with structured tool calls — you're adding a middleware hop, not building a new pipeline. Replaces the reviewer role for agent-generated writes and augments any operator deploying agents into systems of record. Scale caveat: only pays off once you have an agent doing real writes, so it's a pattern to bundle into an agent proposal, not a standalone sell.

### 2. Multi-channel B2B order intake to ERP
**Source:** [Whitespace (YC S26)](https://www.ycombinator.com/companies/whitespace) — AI OS for wholesale distributors; connects to ERP and inboxes to automate order entry, stock-check replies, and inventory planning.
**Mechanism:** trigger is an inbound order arriving in any channel — supplier email with a PO attached, PDF forwarded from a rep, an entry submitted through a distributor portal, or a WhatsApp/text with a shopping list. Agent reads the message + attachments, extracts line items, validates each SKU and quantity against the ERP catalog and current inventory, resolves ambiguous product names ("2x4x8 SPF" → the specific SKU the customer has ordered before), then posts a validated order into the ERP (NetSuite/SAP/Sage/Epicor). Same agent also handles inbound stock-check and delivery-date questions by reading from ERP + WMS + CRM and replying in whatever channel the question came in on. Replaces the inside-sales/CSR job of manually keying purchase orders and answering "when's my order shipping" over the phone.
**Why agentic:** trigger is an unstructured message in an arbitrary channel; the agent has to resolve entity/quantity ambiguity against a live catalog and only posts to the ERP once validation passes. It's not a form.
**Generalizable core:** inbound request in any channel + any format → agent extracts and resolves against system-of-record catalog → posts validated transaction → replaces the clerk keying it in.
**Deployability:** stack is an email/portal ingestion webhook, an OCR/parse step (Reducto, LlamaParse, or Claude's native PDF), a catalog-resolution loop over the ERP, and a validation policy that decides auto-post vs. human queue. Week-to-month build depending on how messy the customer's catalog is. Replaces junior order-entry clerks and augments customer service reps. Scale caveat: works at any volume, but ROI is proportional to how many SKUs and how much catalog ambiguity you have — same pattern in a restaurant with a fixed menu is trivial; in an industrial distributor with 50k SKUs and regional naming variants, it's most of the job.

### 3. Cron-scheduled catalog/site validation with vault-injected credentials
**Source:** [Browserbase, via Anthropic's Claude Managed Agents launch](https://claude.com/blog/whats-new-in-claude-managed-agents) — Anthropic shipped scheduled deployments + vault env vars for Managed Agents on June 9, 2026; Browserbase runs a scheduled deployment that periodically validates their public catalog of browser skills.
**Mechanism:** trigger is a cron schedule (nightly/weekly). At fire time, a new agent session starts with API keys and credentials injected from a vault at the network boundary — the model context never sees the secret, only a placeholder, and outbound calls are restricted to allowlisted domains. The agent walks a catalog (Browserbase's case: a list of browser-skill entries with URLs and expected behavior), exercises each item via a CLI tool, records what worked, what broke, what drifted (a login flow changed, a selector rotted, a page 404s), and writes the delta to a report/PR/queue. Replaces the QA engineer who manually re-tests a catalog of external integrations after upstream sites change.
**Why agentic:** the agent picks which items to test, decides when a failure is a real regression vs. a transient error, and produces a structured diff — not a fixed script running on a runner. The vault + allowlist boundary is what makes it deployable against production credentials without giving the model the secret.
**Generalizable core:** cron trigger → agent gets ephemeral scoped credentials via vault → exercises a list of external endpoints/records → writes deltas + regressions to a queue → replaces recurring manual QA/audit.
**Deployability:** Claude Managed Agents public beta on Claude for Work/enterprise plans, no separate cost beyond usage. Weekend build if you already have a catalog somewhere structured (Notion DB, Airtable, GitHub file). The pattern generalizes to link checkers, price monitors, inventory feed validators, compliance-page audits, and any recurring "is this external thing still shaped the way we expect" task. Scale caveat: needs vault-style credential handling to be safe against prompt injection on the pages being validated — don't run this pattern with plaintext creds in the model context.
