# 2026-11-17 — Agent Pattern Scan

## TL;DR
Four concrete patterns surfaced today. The standout is Token's "Rehearsal" agent, which answers questions inside its own product by driving the UI rather than returning text — a template for turning any SaaS app into a do-it-for-me surface.

## Patterns

### 1. Cloud session following a pull request
**Source:** [Anthropic — Claude Code auto-fix for PRs](https://x.com/noahzweben/status/2037219115002405076) and [`/autofix-pr` command reference](https://claudcod.com/blog/claude-code-autofix-pr/) — a Claude Code cloud session that subscribes to a specific pull request and pushes fixes when CI fails or reviewers leave comments.
**Mechanism:** Developer runs `/autofix-pr` (or flips the Auto Fix toggle on a cloud session). The session subscribes to GitHub webhook events for that PR. On a CI failure event, the agent reads the failing job logs and the current diff, writes a patch in the branch's worktree, commits, and pushes. On a review-comment event, it reads the comment thread with the file/line it anchors to, edits, commits, pushes, and replies on the thread.
**Why agentic:** Each event is a distinct trigger (log vs. inline comment) and the context the agent has to assemble differs per event. Choosing where to localize a fix, or whether to push back on a reviewer, is judgment, not a scripted response.
**Generalizable core:** Long-lived artifact receives streamed feedback from multiple actors → agent reads the full current state plus the new feedback → applies the smallest corrective change → writes back to the artifact's system of record.
**Deployability:** Claude Code cloud sessions + Claude GitHub App on the repo. Weekend build for any team already on Claude Code; it's mostly configuration. Augments the PR author, doesn't replace reviewers. Caveat: parallel sessions share rate limits, and path-scoped restrictions still require community config or a gateway layer.

### 2. Webhook-triggered record triage with draft response
**Source:** [Hookdeck — Zendesk + Claude ticket triage](https://hookdeck.com/webhooks/platforms/building-ai-ticket-triage-with-zendesk-and-claude) for the mechanism, [Anthropic's Zendesk case study](https://claude.com/customers/zendesk) for scale evidence (1M custom-agent executions in 7 weeks).
**Mechanism:** Zendesk's "Ticket Created/Updated" trigger fires a webhook into a handler. The handler enriches the ticket with the requester's past tickets and any linked account data, sends everything to Claude with a strict output schema, and parses back priority, group assignment, tags, and a drafted first reply. Those fields are written back onto the ticket via the Zendesk API in under a second. The human opens a ticket that's already classified, routed, and comes with a draft to approve or edit.
**Why agentic:** The classification isn't rule-based. The same phrasing is urgent for one account tier and routine for another, so the enrichment + model call is what makes it land in the right bucket. The draft reply is conditioned on the pulled history, not a template.
**Generalizable core:** Inbound record created in a system of record → agent pulls prior-record history for the same actor → emits structured fields plus a human-readable draft → writes both back onto the record.
**Deployability:** Any system that emits record-creation webhooks (Zendesk, Freshdesk, HubSpot, Intercom, Jira, Shopify order flags) + a webhook handler on Vercel/Cloudflare Workers + Claude API. Week build. Replaces the tier-1 triage task, not the tier-1 role.

### 3. In-app agent that operates the UI, not the API
**Source:** [Token — "We Built An Agent That Broke All of Our Security Rules"](https://thehackernews.com/2026/11/we-built-agent-that-broke-all-of-our.html) (Nov 11, 2026). Token's internal "Rehearsal" agent, embedded in the Token platform.
**Mechanism:** User types a question into Token's UI. Rather than answering in text, the agent opens pages, sets filters, fills forms, and clicks through to produce the actual outcome the user asked for. It runs inside the user's existing authenticated browser session, so no backend API changes are required to extend it to new workflows. The replaced task is the user learning which screens to visit and which filters to apply to get the data or action they want.
**Why agentic:** The sequence is composed per question. The agent decides from the request which screens, filters and form fields apply, then plans and executes a multi-step UI traversal on the fly. It's not a shortcut; it's a per-question policy.
**Generalizable core:** User states an outcome in natural language → agent plans a UI traversal of the host app → performs clicks/typing inside the user's session → outcome achieved without the user navigating.
**Deployability:** Playwright-in-browser or the host app's own event dispatch + Claude API. Month build for most teams because UI selectors drift and recoveries are subtle. Important caveat Token calls out directly: the agent inherits the user's full permission scope, which is almost always wider than the task needs. Production deployments should pair with a scoped service identity for the agent itself.

### 4. Call-transcript coaching feed
**Source:** [Gumloop — AI sales agents](https://www.gumloop.com/blog/ai-sales-agent). A Gumloop template where a sales-call transcript triggers coaching extraction to Slack.
**Mechanism:** When a transcript lands (webhook from Fathom/Gong/Fireflies, or a poll), the agent reads the transcript against the current deal record pulled from the CRM, then emits a short message with specific coaching points: missed objections, discovery questions not asked, pricing surfaced too early, next-step quality. The message posts into the rep's Slack DM or a shared channel with the manager tagged. Replaces the manager's task of listening to post-call recordings for coaching material.
**Why agentic:** Output isn't aggregate talk-ratio stats. It's a per-call, per-rep critique that cites specific moments. The judgment is picking what's coachable in this particular call for this particular rep at this stage of this deal.
**Generalizable core:** Long-form human artifact lands (transcript, document, email thread) → agent reads it against actor context (who produced it, what stage they're in) → writes a narrow, cited critique to a human-facing channel → replaces the "review and give feedback" task.
**Deployability:** Transcript source + CRM + Slack + Claude API. Can be built as a Gumloop/Lindy template or in n8n for more control. Week build. Augments a sales manager role. The skeleton copies cleanly to QA review of support calls, contractor safety-briefing reviews, onboarding call reviews, and similar "someone should have listened" tasks.
