# 2026-07-24 — Agent Pattern Scan

## TL;DR
The strongest pattern today is the payer-side clinical-action agent Optum and UST are rolling out on Claude: a new claim triggers the model to reconcile clinical history, guidelines, and payer rules into a single "next best action" that a human approves before it reaches a member. The pattern travels cleanly into insurance and property-management collections work where the same review-then-act loop lives with humans today.

## Patterns

### 1. Payer-side "next best action" agent for claims and care
*(tags: `insurance`, `home-health`, `dental-and-vet-clinics`, `property-management`, `accountants`)*

[Optum's partnership with Anthropic](https://hitconsultant.net/2026/07/13/optum-partners-anthropic-healthcare-ai/) and the parallel [UST-CarePath integration](https://www.fiercehealthcare.com/health-tech/tech-services-company-ust-integrates-anthropic-claude) put Claude behind everyday claim and care events at UnitedHealth scale. When a claim or care event arrives, the agent reads the patient's medical history, active payer formularies, applicable clinical guidelines, and social-determinants context. It then surfaces one recommended action — approve, deny with rationale, request specific missing docs, or route for utilization review — with citations. Every recommendation queues to a human for approval before it touches the member. What gets replaced is the multi-hop coordination between the claims adjuster, the utilization nurse, and the outreach coordinator. Not the decision itself; the assembly of everything the decision needs.

The mechanism copies almost verbatim into small insurance brokerages, where inbound carrier correspondence (a denial letter PDF, a coverage-change notice, a renewal quote) hits the agency inbox and a broker spends an hour reconstructing the client's policy history to draft a reply. An agent triggered by a new email in a shared Gmail label could read the letter, pull the client's file from AMS360 or HawkSoft, cross-reference the specific policy language, and draft a client-ready response the broker reviews and sends. Stack is realistic — Gmail plus the vertical AMS plus Claude API plus DocuSign for anything needing a signature — and it replaces the account manager's daily two-hour "what did this letter mean and what do we owe the client" ritual. Pitch: "Every carrier letter arrives already researched, with a draft reply ready for you to send."

In property management the same shape works for accounts-receivable dispute letters, HOA violation notices, and lease-renewal correspondence — a Buildium or AppFolio event fires an agent that reads the tenant's payment and communication history, drafts the response, and flags the ones that need the owner's judgment. Pitch: "Your assistant reads every tenant letter, does the file work, and gives you a draft to approve — you only make the calls that actually need a person."

### 2. Scoped single-job voice and chat agents with pre-launch simulation
*(tags: `home-health`, `restaurants`, `dental-and-vet-clinics`, `gyms`, `professional-services`)*

[OpenAI's Presence launch on July 22](https://venturebeat.com/orchestration/openai-unveils-presence-a-new-platform-that-lets-enterprises-launch-and-manage-realtime-voice-agents-and-chatbots) is less interesting for the voice-agent capability, which is now table stakes, than for the deployment model it codifies. Each Presence deployment is built around one specific job — resolving a billing dispute, processing an insurance claim, handling a specific class of IT ticket — with only the system access and knowledge that job requires, plus explicit policies for what the agent can do autonomously, when it needs approval, and when to hand off. Before it ships, the agent is run through a simulation harness that scores outcomes against approved company policy. Post-launch, ongoing evals catch drift as products and rules change. What gets replaced is the "throw a general-purpose voicebot at the phones and hope" mode of deployment, and the human QA sampling that follows.

The transferable idea for SMBs is the scoping and simulation discipline more than the voice channel. For a multi-location dental practice, that means one voice agent scoped only to insurance-verification callbacks — it reads the day's appointments in Dentrix, calls the payer, updates the verification field, and only escalates when the payer's IVR asks something the policy doesn't cover. Stack is Vapi or Retell plus the practice management API plus Claude for reasoning, plus a scripted simulation set of the fifty most common verification calls the front desk actually handled last month. Pitch: "One agent, one job, tested against your last month of real calls before it takes a live one — not another bot that tries to do everything and answers every hard question with 'let me transfer you.'"

The same shape drops into gyms doing membership-freeze requests, home-health agencies doing shift-swap coordination, and small law firms doing client intake — narrow the job, simulate against a real transcript library, and ship. Pitch: "We build you a phone agent that does exactly one thing exactly right, and prove it works against your own call history before it ever picks up."

### 3. Repo-event-triggered coding agents that open pull requests
*(tags: `professional-services`, `accountants`, `small-construction`, `restaurants`, `dental-and-vet-clinics`)*

[GitHub Agentic Workflows](https://github.blog/changelog/2026-06-11-github-agentic-workflows-is-now-in-public-preview/) hit public preview in June and are now widespread — issues, PR comments, or scheduled crons dispatch a coding agent that reads the repo, makes changes, runs tests, and opens a PR that a human reviews. GitHub reports Copilot alone processing 60 million reviews. The interesting bit isn't code generation; it's the trigger being a normal repository event, so the workflow feels like "the agent is a team member who reacts to what's in the tracker" rather than a chat you have to start.

That trigger-shape moves out of software into any operator business that lives in a shared task list or ticket queue. For a small accounting firm, the "issue tracker" is client tasks in Karbon or a shared Google Sheet — a new "gather Q3 documents" task fires an agent that emails the client the specific list based on last year's return, follows up on a schedule, and marks the task ready-for-preparer once every requested doc is in Google Drive. Stack is Karbon plus Gmail plus Claude plus Google Drive; what it replaces is the associate's Monday morning "chase clients for docs" hour. Pitch: "Every new client task in your practice starts working itself the moment you file it."

The same "queue event kicks off the work" model fits small construction (a new punch-list item in Buildertrend triggers an agent to gather sub availability, order the materials, and schedule the fix), veterinary clinics (a new "call owner about lab results" task pulls the results, drafts the plain-English explanation, and calls at the owner's preferred time via Retell), and restaurants (a new maintenance ticket in the manager log triggers vendor outreach, quote comparison, and appointment booking). Pitch: "Your task list stops being a to-do — it starts being the trigger for the work to actually happen."

### 4. Field-level CRM write-back from sales-call transcripts
*(tags: `professional-services`, `home-health`, `insurance`, `real-estate`, `trades`)*

The [2026 shift Cirrus Insight and others describe](https://www.digitalapplied.com/blog/conversation-intelligence-sales-calls-crm-2026-guide) is that tools like Gong's AI Data Extractor, Fireflies, Otter, and Sybill no longer attach a transcript link or a summary paragraph — they read the call and write structured values directly into specific CRM deal fields on their paid tiers. When the call ends, the agent extracts stage, next step, budget signal, competitor mentioned, decision-maker sentiment, timeline, and writes each into its corresponding Salesforce or HubSpot field, then creates the follow-up task and drafts the recap email. What gets replaced isn't the rep's summary — it's the twenty minutes of end-of-day CRM hygiene the rep does badly or not at all.

For solo insurance brokers and independent real-estate agents who have no admin, the same pattern is close to life-changing. A missed-call-follow-up or client-review Zoom, recorded and transcribed via Fathom or Otter, triggers an agent that updates the client record in AgencyZoom or Follow Up Boss with the fields that actually got discussed — renewal concerns, referral mentions, coverage gaps, listing-price expectations — and drafts a follow-up email that references the specific things said. Stack is a recorder plus the vertical CRM's API plus Claude for extraction plus Gmail. Pitch: "Your CRM finally reflects what you actually talked about, without you touching it."

The same pattern lifts a huge weight off home-care agency owners running family intake calls, HVAC estimators doing site walkthroughs on speakerphone, and residential contractors doing punch-walks with clients — every conversation writes itself into the system of record, and the person on the call gets to be present in the call.
