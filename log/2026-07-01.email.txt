# 2026-07-01 — Agent Pattern Scan

## TL;DR
The single most interesting pattern today is the autonomous carrier check-call voice agent (Tai TMS Track & Trace, HappyRobot, others), which places outbound voice calls to truckers on schedule or geofence triggers, holds a real conversation to extract location/ETA/exceptions, and writes the update directly to the TMS. It compresses a $165K/year dispatcher headcount problem into an outbound voice loop with a structured write-back, and the same skeleton — "chase status from a human via voice/SMS and write the answer to the system of record" — copies into any coordination-heavy job. Second-most interesting is Lassie's remittance-posting agent for dental and medical practices, which is notable less for the AI and more for the local Windows bridge that finally lets agents automate against the on-prem software most SMBs actually run.

## Patterns

### 1. Autonomous carrier check-call voice agent
Source: Tai TMS Track & Trace Agent (April 2026) and debales.ai carrier check-calls automation writeups — freight brokerages and small-to-mid carriers running Tai, McLeod, Turvo, or similar TMS platforms.
Mechanism: A trigger fires when a load's status is stale in the TMS or the truck crosses a geofence (pickup ETA, halfway, delivery ETA). The agent looks up the driver's phone from the TMS load record, places an outbound voice call, holds a real conversation ("Hey, this is a dispatch check-in on load 40218 to Dallas — where are you and what's your ETA?"), parses the free-form answer, retries via SMS if the driver doesn't pick up, and writes the parsed location/ETA/status back to the TMS load record. It escalates to a human dispatcher only when the driver reports an actual problem. Replaces the dispatcher task of manually calling every active truck every few hours.
Why agentic: The agent has to conduct a real voice conversation with variable outcomes and decide whether the answer resolves the check or reveals an exception. A rule-based system fails on the 60% of calls where the driver says something the script didn't anticipate.
Generalizable core: scheduled or geofence trigger → agent identifies contact via the system of record → agent runs voice/SMS conversation → parses free-form response → writes structured update to system of record → escalates only on exception.
Deployability: Voice stack (HappyRobot, Vapi, or Retell) + TMS webhooks/API + Twilio SMS + Claude API for parsing. Week build for one TMS, two to four weeks across several. Replaces 0.5–1.0 FTE per medium brokerage. Same skeleton copies into field service, delivery dispatch, tour operators tracking bus arrivals, and construction subcontractor coordination — anywhere a human's daily job is "ping X for status and update the schedule."

### 2. On-prem remittance-posting agent (Lassie)
Source: Lassie $35M Series A, June 3 2026, a16z-led — deployed in 700+ independent dental and medical practices across 49 states.
Mechanism: Trigger is the arrival of an ERA (electronic remittance advice) from a payer plus the matching EFT in the practice's bank. A local Windows agent installed on the office PC bridges the on-prem EHR (Dentrix, Eaglesoft, Open Dental) to Lassie's cloud. The cloud agent parses the payer remittance, matches each line to the correct patient/claim in the practice management system, applies practice-specific contractual adjustment logic per payer, and posts payment + adjustment + write-off directly into the PMS. Plaid/MX confirms the EFT hit the bank. Clean matches post silently; underpayments, mismatched EFTs, and ambiguous write-offs get filed into a staff review queue. Replaces the biller's daily job of manually keying payer statements into the PMS.
Why agentic: Reconciliation crosses three data sources (payer ERA, bank deposit, PMS claim record) with payer-specific contract logic. The exceptions — which are the whole point — need reasoning about whether a mismatch is a legitimate write-off, a payer error, or a keying mistake.
Generalizable core: multi-source inbound event → agent reconciles against system of record with entity-specific rules → auto-posts on clean match → routes only exceptions to a human queue.
Deployability: The novel piece is the local Windows bridge. Most SMBs run on-prem verticalSaaS with no cloud API — Cornerstone/AVImark for vets, Mitchell/ShopKey for auto repair, TABS3 for small legal, QQCatalyst for insurance agencies, Top Producer for realtors. A lightweight bridge process on the office PC unlocks automation against systems no cloud tool can reach. Month-plus build per vertical. Replaces one back-office biller per practice; scales to a "one agent, N practices" service model.

### 3. Natural-language markdown as workflow definition (GitHub Agentic Workflows)
Source: GitHub Agentic Workflows public preview, June 11 2026; Carvana using it for multi-repo engineering changes at scale.
Mechanism: An operator writes an .aw.md file — plain-English markdown describing what should happen on an event ("when an issue is labeled `bug`, look up related PRs, estimate severity from the stack trace, draft a repro plan, post it as a comment, apply a `triaged` label"). GitHub compiles the markdown into standard Actions YAML at commit time. When the underlying event fires, the compiled workflow spins up a coding agent inside Actions, the agent reads relevant context via the GitHub MCP server, and writes the action back to GitHub. Replaces the manual triage/routing/first-response layer of a bug tracker.
Why agentic: The reasoning happens at run time, not at author time. The markdown says "estimate severity" — the agent decides how based on the actual stack trace in the actual issue. One workflow file handles novel inputs it was never explicitly coded for.
Generalizable core: platform-native webhook event → agent authored in natural language → agent reads related context via the platform's MCP server → agent writes an action back to the same platform.
Deployability: Weekend build for a single workflow anywhere the platform has an MCP server — as of mid-2026 that includes HubSpot, Notion, Linear, Stripe, Slack, Intercom, Zendesk, Shopify. Replaces the manual first-response/triage layer in any inbox-shaped system: HubSpot lead assignment, Linear ticket triage, Zendesk first-touch, Shopify order-flag routing. Because the workflow is markdown, not code, it's actually deployable by non-engineering operators. Caveat: agents that write to production systems need a governance layer.

### 4. Claim-intake triage agent with immutable audit trail (Allianz + Anthropic)
Source: Allianz + Anthropic partnership; Anthropic financial services agent templates, May 2026. Claude scored 88% human-expert accuracy on insurance claims out of the box.
Mechanism: New FNOL arrives via email, portal upload, or intake form. The agent classifies the claim type, pulls the customer's policy from the underlying system, extracts incident facts from unstructured attachments (photos, PDFs of police reports, medical bills), runs the coverage check against policy terms, and drafts a first-pass decision — pay, deny, request more info — with the payment amount if payable. Every decision, rationale, data source, and prompt version logs to an immutable audit trail. Sensitive or complex cases route straight to a human adjuster; routine sub-limit claims can auto-approve first payment. Replaces the adjuster's intake-and-first-decision workflow.
Why agentic: The agent reads unstructured inputs (photos of damage, scanned police reports, doctor's handwritten notes) that no fixed schema handles, applies policy rules to what it extracts, and produces an actionable first-pass decision.
Generalizable core: inbound claim/case/request in any format → agent normalizes to structured intake → agent runs entitlement/eligibility check → produces first-pass action + immutable audit trail → routes ambiguous cases to a human.
Deployability: Allianz is enterprise, but the skeleton copies to SMB scale in any regulated-decision domain: small insurance brokerages, PT clinics filing prior-auth appeals, benefits administrators handling FSA/HSA reimbursements, warranty admins triaging appliance claims, HOA management companies handling maintenance requests against covenant rules. Month-plus build. The real gate is the audit trail — Postgres append-only table plus an immutable object-store bucket for source docs is enough at SMB scale. Skip the audit layer and you can't defend automated decisions when they're questioned later.
