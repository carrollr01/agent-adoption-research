# 2026-08-10 — Agent Pattern Scan

## TL;DR
Most interesting today: Claire Vo's "Merge Mommy" agent, which scores every PR across six explicit risk dimensions and auto-approves the low-risk ones. The scoring-rubric-as-gate is the generalizable idea — the same skeleton works for any approval workflow where a human currently rubber-stamps most things and only needs to look at edge cases. Also captured: Google's outbound consumer voice agent (search intent triggers a real phone call to a store), General Mills' shipment-exception handler that acts inside a governance envelope, and Ramp's per-swipe accounting coder that eliminates the month-end coding batch entirely.

## Patterns

### 1. Risk-scored auto-approval agent (Merge Mommy)
**Source:** [Lenny's Newsletter — Build an AI code review bot in 30 minutes](https://www.lennysnewsletter.com/p/build-an-ai-code-review-bot-in-30) — Claire Vo built "Merge Mommy" on Vercel's Eve platform in a single Codex session; demoed on the How I AI podcast.
**Mechanism:** New PR checks pass in GitHub → agent reads the diff and its context (files touched, tests, deploy target) → scores against six explicit risk dimensions (blast radius, reversibility, data security, ops impact, verification gap, change surface) → auto-approves and merges if all dimensions are low, or posts a Slack message to a human with the specific dimension that failed and why. Runs against every PR, not just AI-generated ones. Replaces the human-as-default-reviewer for low-stakes changes.
**Why agentic:** The scoring isn't a checklist — the agent reads the actual code and reasons about each dimension. And the output is an action (merge or route), not a rendered risk score for a human to interpret.
**Generalizable core:** Any "one human rubber-stamps everything" queue → agent reads the item + context → scores against a named rubric → auto-clears the safe ones and only surfaces the failing dimension for the exceptions.
**Deployability:** Vercel Eve + Codex in the demo, but the pattern is stack-agnostic — Claude API with a scoring prompt plus a webhook receiver is a weekend build. Transfers to invoice approvals, refund requests, contract redlines, hire-yes-no, expense escalations, PTO requests. The core work is naming the dimensions honestly for the specific queue; the code is thin. Replaces the reviewer/approver seat for the ~80% of items that don't actually need judgment.

### 2. Outbound consumer voice agent for retail inventory (Google "Let Google Call")
**Source:** [Google blog — Agentic checkout and holiday AI shopping](https://blog.google/products-and-platforms/products/shopping/agentic-checkout-holiday-ai-shopping/), [TechCrunch coverage](https://techcrunch.com/2025/11/13/google-expands-ai-shopping-with-conversational-search-agentic-checkout-and-an-ai-that-calls-stores-for-you), how-to page updated July 24, 2026, rolled out across most of the U.S. for toys, health & beauty, electronics.
**Mechanism:** Shopper searches for a product "near me" and taps "Let Google Call" → answers a short questionnaire the agent uses to know exactly what to ask (color, size, model number, price ceiling) → Duplex + Gemini calls multiple nearby stores, asks a store employee about stock and pricing, hangs up → sends the shopper a text or email summary comparing what each store said. Replaces the errand of phoning four hardware stores to find out who has the part.
**Why agentic:** The trigger is a search intent, the action is a real phone conversation with a stranger, and the agent adapts mid-call to whatever the store person actually knows. No dashboard involved; the output is a natural-language summary sent to a channel the shopper picked.
**Generalizable core:** User states an information need that only exists in a human's head → agent conducts a real conversation to extract it → returns a structured summary to the user's preferred channel. Also flips the whole "AI voice agent" pattern that most SMB tooling assumes: instead of businesses fielding AI callers, consumers now dispatch them.
**Deployability:** Google-scale for the consumer-facing version, but the outbound-voice-on-behalf-of pattern is week-build territory now — Vapi, Bland, Retell, ElevenLabs conversational, or Twilio + a voice model. The interesting SMB variant: a procurement agent that calls three vendors to check part availability before the buyer picks one; a recruiter's agent that pre-screens candidates by phone; a paralegal agent that calls the county clerk for filing status. Replaces the "boring phone calls a human dreads" seat.

### 3. Autonomous shipment-exception handler inside a governance envelope (General Mills ELF)
**Source:** [Köerber-Stellium — The Autonomous Supply Chain in 2026](https://koerber-stellium.com/agentic-ai-in-supply-chain/), [CIO Dive on the General Mills / Palantir deployment](https://www.ciodive.com/news/General-Mills-AI-cost-saving-strategy/740416/). Assesses 5,000+ shipments/day, $20M+ savings since FY2024.
**Mechanism:** Shipment event (delayed truck, missed pickup, capacity change, weather flag) crosses a threshold → agent reads the constraint rules (customer SLA, cost ceiling, greenhouse-gas budget, warehouse capacity) and the backup-supplier list → issues a purchase order to the preferred alternative, updates the downstream production schedule, notifies customer service — all within minutes and without waiting for human approval. Only genuine outliers get escalated. Replaces the supply-chain analyst who used to work through exception queues each morning.
**Why agentic:** The agent takes irreversible-ish actions (issuing POs, rewriting production schedules) autonomously; a dashboard would just show the deviations and wait for a human. The "governance envelope" — the pre-agreed rules the agent must stay inside — is what makes this safe at scale, and it's the interesting design idea to steal.
**Generalizable core:** Real-time deviation from plan → agent reads the constraint set → picks the least-bad recovery from a pre-defined option set → executes and notifies affected parties. Only true edge cases wake a human.
**Deployability:** Enterprise scale — this specific implementation runs on Palantir Foundry and years of clean data, not something you build over a weekend. But the pattern shrinks: an SMB version could handle rescheduling missed appointments, reassigning overbooked resources, or rerouting orders when the primary vendor is out. The design lesson is the envelope: name the constraints explicitly, name the option set explicitly, and only escalate when both fail. That part is a week-build in any workflow tool with an LLM step.

### 4. Per-transaction accounting coder that dissolves the month-end batch (Ramp Accounting Agent)
**Source:** [Ramp — How Ramp's Accounting Agent automates swipe to sync](https://ramp.com/blog/accounting-agent-launch), [PRNewswire launch](https://www.prnewswire.com/news-releases/ramp-launches-accounting-agent-to-automate-bookkeeping-with-real-time-close-302686214.html). 90%+ auto-coding accuracy, 3.5× more auto-coding than legacy tools, customers reporting 40+ hours/month saved and month-end close in a third of the time.
**Mechanism:** Card swipe or bill received → agent reads the merchant, memo, receipt image, past coding behavior for this vendor and this employee, plus the customer's chart of accounts → assigns GL code, department, class, location, and any custom field; splits line items on multi-item bills; accrues transactions that aren't ready to sync so they land in the right period, then reverses the accrual next month → flags only the transactions where a human should look. Replaces the controller's weekly "code the transactions" chore and the month-end review batch.
**Why agentic:** Event-driven, not calendar-driven — the coding happens at swipe time, not at close time. And each action writes to the ERP, not to a "for review" queue. The batch that used to define month-end just isn't there anymore.
**Generalizable core:** High-volume decision that today gets deferred into a periodic batch → shift the decision to the moment the event happens → let the agent decide the routine cases and route only the true ambiguity to a human. The batch dissolves.
**Deployability:** Ramp built this on their own transaction data, so the specific product is theirs — but the pattern is a week-build in any domain with a lot of small, similar decisions that pile up: pharmacy pre-auth coding, expense report line-items, procurement PO routing, inbound-email triage, ticket categorization, claims coding. The technique: bring the human review to the moment of decision (with a suggested code the human can accept in one click), stop letting the queue accumulate.
