Agent Pattern Scan — 2026-06-30 — 3 patterns | Rejection-event recovery agent for law firm e-billing

https://github.com/a3-dev/agent-adoption-research/blob/main/log/2026-06-30.md

Three concrete mechanisms emerged after a long gap since the last scan. The standout is rejection-event recovery: an agent that watches for an inbound rejection (e-billing kickback, denied claim, returned filing) and drafts a data-informed appeal before anyone on the team notices. The other two — Lassie's portal-scraping payment reconciliation for medical practices, and Metabase's Reprobot reproducing user-reported bugs in ephemeral environments — both replace specific human triage roles rather than augmenting them.

1. Rejection-event recovery agent (Aderant Appeals Agent)
Source: Aderant Agent Center, launched at Momentum Global 2026 on the Stridyn platform.
Mechanism: A client e-billing system rejects a submitted invoice with a coded reason. The agent picks up the rejection event, reads the rejection code plus matter context plus the original time entries plus a history of successful appeals for similar codes, then drafts a data-informed appeal and queues it for a billing partner to approve before resubmission.
Generalizable core: Inbound rejection event → agent reads rejection reason plus original submission context plus history of successful appeals → drafts response → human approves and resubmits. The shape works wherever an external system can reject a submission with a coded reason — clearinghouses, permitting portals, tax filings, content moderation queues. Week-build for a single rejection type; month-build for a portfolio. Replaces the AR clerk or paralegal handling rejection queues and recovers revenue that gets written off because nobody had time to appeal.

2. Portal-scraping payment reconciliation agent (Lassie)
Source: Lassie's $35M Series A from Andreessen Horowitz, announced June 3 2026; the agent runs in 700+ medical and dental practices.
Mechanism: On a schedule (and probably on EFT/ERA webhooks where supported), the agent logs into each payer's insurance portal, retrieves EOBs and remittance data, matches each payment line to the right claim and patient in the practice management system, posts the payment plus adjustments into the PMS, and verifies the bank deposit. Claim follow-ups and appeals run from the same loop. Lassie reports up to 80 hours per practice per month eliminated, with some recovering 190.
Generalizable core: Scheduled poll of an external portal → agent extracts unstructured-ish payment data → matches against system-of-record → posts the reconciliation → flags exceptions for human review. Distinct from the 5/25 invoice-chase pattern, which is outbound dunning — this is inbound money the practice already earned but couldn't get into the PMS without manual effort. Same shape generalizes to wholesale distributors reconciling supplier rebates, agencies reconciling ad-platform payouts, contractors reconciling card processor deposits.

3. Bug-reproduction agent on every new GitHub issue (Metabase Reprobot)
Source: Metabase's engineering blog, "Meet Repro-Bot, our GitHub issue triage agent."
Mechanism: A new issue on metabase/metabase fires the agent. Reprobot parses the description, extracts the purported steps to reproduce, and provisions an ephemeral Metabase instance the way a developer would (Docker plus DB config). It uses Playwright for browser steps and REPL access for state inspection, and has full read access to the codebase plus existing tests. If it reproduces the bug, it writes a failing test, attaches the test plus stack trace plus exact environment state to the issue, and hands the human engineer something concrete to fix.
Generalizable core: Inbound bug/issue/complaint with prose-described state → agent assembles a matching execution environment → runs the described steps → produces a reproducible artifact → attaches to the originating record. Works for any SaaS support org with a sandboxable test environment, and for QA-heavy products in regulated verticals (medical device firmware, fintech flows). Month-build minimum — the sandbox provisioning is where teams underestimate the work. Replaces the first-pass triage engineer.
