# 2026-09-05 — Agent Pattern Scan

## TL;DR
The strongest new pattern of this run is Rocket Money's Rowan (Sept 3): a background finance agent that proactively SMS-texts the user with an actionable proposal and executes the action on a plain-language reply. It's the cleanest example this year of "proactive outbound to the human, same-channel authorization back, then agent acts." Four other qualifying patterns behind it, mostly from the flood of Anthropic customer stories and the Salesforce-Anthropic Claudeforce announcement in August.

## Patterns

### 1. Proactive-SMS-then-execute finance agent (Rowan / Rocket Money)
**Source:** [fintech.global writeup, Sept 3](https://fintech.global/2026/09/03/rocket-money-launches-ai-agent-to-manage-finances/), [Rocket Companies press release](https://www.rocketcompanies.com/press-release/rocket-moneys-rowan-rewrites-what-ai-can-do-in-personal-finance/) — consumer fintech, Premium Plus tier, built with Anthropic.
**Mechanism:** Continuous background monitor over the user's linked bank/card accounts and known subscriptions. When it detects a specific event class (free trial approaching its first billing date, recurring charge increase, forgotten dormant subscription, savings opportunity), it composes and sends a plain-language SMS to the user proposing an action. The user replies in natural language ("yes cancel it", "renegotiate that one", "move $200 to savings"), and Rowan executes: initiates the cancellation flow, opens a bill-renegotiation session, or triggers a scheduled savings transfer. Replaces the human doom-loop of periodically auditing statements, calling providers, and remembering to move money.
**Why agentic:** The trigger is an event class detected across a stream of transactions, not a dashboard view; the agent decides which events are worth interrupting the user for; and the outbound-then-execute loop replaces navigation. A dashboard would show the same data and require the user to act.
**Generalizable core:** Continuously watched data stream → threshold/pattern detected → outbound message to human on their preferred channel with proposed action → plain-language authorization → agent executes and reports back. Works anywhere the user has a small set of decisions they'd make if only they were reminded at the right moment.
**Deployability:** Weekend-to-week build. Bank/data ingest via Plaid or a vertical connector; detection is straightforward LLM classification over enriched transactions; outbound via Twilio SMS; action execution is the hardest part (each vendor's cancellation/renegotiation API differs; Rocket Money bootstrapped on years of concierge relationships). Rowan's own scale advantage is real, but the pattern itself works with 1–2 downstream integrations. Replaces the personal-CFO or executive-assistant "watch this for me" role. Scale caveat: the specific negotiation actions need real API surface or a browser-agent fallback per counterparty.

### 2. Autonomous monthly close (Pilot Meridian)
**Source:** [CPA Practice Advisor, June 23](https://www.cpapracticeadvisor.com/2026/06/23/pilot-says-new-ai-accounting-platform-meridian-runs-monthly-close-from-start-to-finish/185541/), [Accounting Today](https://www.accountingtoday.com/news/pilot-launches-fully-autonomous-ai-bookkeeper) — Pilot, SMB bookkeeping-as-a-service, thousands of clients.
**Mechanism:** Trigger is the calendar (month-end), plus the arrival of the last bank feed of the period. The agent pulls bank feeds, credit-card statements, invoice/AP records, payroll runs, and the prior month's chart-of-accounts state, then runs the full close sequence: categorization, reconciliation, accrual entries, inter-account transfer matching, generation of P&L, cash-flow, and balance-sheet statements. Escalates only for judgment calls with material impact ("this $18K wire has no matching invoice — is it a capex or a refund?"). Writes back into the client's ledger (QuickBooks, Xero) and produces the deliverable PDF. Replaces the human bookkeeper's monthly close.
**Why agentic:** Multi-hour, multi-tool sequential workflow with branching decisions and self-corrections mid-run. A dashboard would just show open exceptions and wait for a human.
**Generalizable core:** Periodic trigger → agent assembles state from multiple systems of record → runs a domain-specific multi-step sequence → escalates only above a materiality threshold → writes final artifact back into system of record. Pattern transfers to any "period-close" process: property-management monthly rent close, insurance-agency monthly commission reconciliation, professional-services timesheet-to-invoice roll-up.
**Deployability:** Month-plus build for the general case; the hard parts are exception classification and the bank/ledger connector surface. Realistic stack: Claude Opus for reasoning, Plaid or Rutter for financial data, direct QBO/Xero APIs, a workflow orchestrator (LangGraph, Inngest, or a custom state machine). Scale caveat: needs a decent labeled corpus of past closes to calibrate the escalation threshold, so it's easier as a productized offering than a first client build.

### 3. Sales-agent embedded on top of the CRM with tunable-autonomy write actions (Claudeforce)
**Source:** [Salesforce press release, Aug 27](https://www.salesforce.com/news/press-releases/2026/08/26/salesforce-and-anthropic-announce-claudeforce/), [TechNode Global writeup](https://technode.global/2026/08/27/salesforce-anthropic-launch-claudeforce-connect-claude-crm-workflows/) — Salesforce + Anthropic, pilot customers now, open beta September.
**Mechanism:** A Claude plugin reads a seller's Salesforce records, connected Slack, email, and any other configured connectors, and generates on-the-fly interactive dashboards for their live pipeline instead of using the CRM's static UI. Ships with 37 prebuilt "skills" (meeting prep, deal-health review, pipeline review, follow-up drafting, etc.). Write actions are permissioned per action type: the operator sets whether the agent asks before sending each external email or auto-sends once trust is established, and every field-level write is constrained to the specific field the agent said it would touch. Replaces the "AI CRO / sales-ops analyst" role plus a chunk of manual CRM hygiene.
**Why agentic:** Reasoning is per-request (deal health computed live, not cached), it acts on the CRM instead of just displaying it, and autonomy is per-action-type tunable rather than binary.
**Generalizable core:** System-of-record + adjacent-channel data → agent-generated interactive view instead of static dashboard → per-action-type autonomy controls (ask-before / auto-send / auto-write) → field-scoped mutation guarantees. Transfers to any operational software where users currently split time between "look at dashboard" and "click into records to update them."
**Deployability:** Enterprise scale in its Salesforce form, but the pattern (Claude Skills + MCP + a schema-constrained write layer) is a weekend build on top of any CRM, ATS, PMS, or job-management system. The interesting engineering is the per-action-type autonomy control, not the LLM part. Replaces or augments the RevOps analyst, sales manager, or account coordinator.

### 4. Vertical drafting agent that reasons over unstructured source records (EvenUp)
**Source:** [EvenUp customer story via Claude by Anthropic](https://claude.com/customers) (published Aug 26; secondary confirmation via [EvenUp's own writing](https://www.evenuplaw.com/blog/claude-for-personal-injury-firms/)) — personal-injury law firms, US-wide.
**Mechanism:** Trigger is a new case's document bundle arriving (medical records, billing records, police reports, treatment notes — thousands of pages, mostly PDFs). Agent ingests everything, reasons across the full long-context set, and drafts a demand letter or settlement package end-to-end. Every draft ships with its inputs, assumptions, and contextual signals surfaced inline, so the attorney can review the reasoning trail without re-reading the source records. Cuts a 15-hour attorney task to 15 minutes; the attorney's job becomes reviewing rather than drafting.
**Why agentic:** Long-context multi-document reasoning with domain-specific rules (injury valuation heuristics, jurisdiction-specific precedent) baked in, and its output is a decision-ready artifact, not a summary or a search result.
**Generalizable core:** Unstructured document bundle arrives → long-context reasoning across all of it with vertical rules → drafts the terminal artifact (report, letter, plan, proposal) → transparency layer surfaces cited inputs so a human can spot-check. Transfers to insurance claim workups, M&A first-pass diligence memos, grant applications from research bundles, disability determinations from medical files, complex tax positions from receipt bundles.
**Deployability:** Month-plus if you're building the vertical from scratch (the domain rules and evaluation harness are the hard part); a weekend build if you're using a general model against a narrow subdomain you already know cold. Realistic stack: Claude with long-context (Opus 4/5), a document ingestion layer with OCR (Reducto, Unstructured), and a citations/trace layer showing which source page justified each drafted claim. Replaces the junior attorney/analyst drafting a first cut. Scale caveat: vertical builds need labeled feedback from senior practitioners to get past 80% acceptance.

### 5. Autonomous contract lifecycle in a per-negotiation workspace (Spellbook)
**Source:** [Vaquill analysis](https://www.vaquill.ai/blog/spellbook-autonomous-contract-management-in-house) — Spellbook Autonomous Contract Management, launched June 30, 2026; runs multiple models including Claude and OpenAI under the hood.
**Mechanism:** Three chained workflows. Intake fires when a contract arrives via connected channels (Salesforce, HubSpot, Google Drive, email); the agent classifies it, triages by risk, and produces a first-pass redline. Review spins up a dedicated per-negotiation workspace holding all history of that specific counterparty deal — every version, every comment, every counter-proposal — and the agent drafts responses inside that isolated workspace. Insight runs continuously after signature, monitoring the executed agreement against triggers like renewal dates, price-adjustment clauses, and covenant compliance. Replaces contract manager + junior in-house counsel review + calendar-based obligation tracking.
**Why agentic:** Each negotiation has its own persistent workspace with memory across rounds; the agent is not a one-shot classifier but a stateful actor across days or weeks of a back-and-forth. Post-signature monitoring is a separate scheduled agent tied to extracted deadlines.
**Generalizable core:** Inbound artifact arrives → agent triages and drafts response → dedicated per-instance workspace persists all state through the interaction lifecycle → post-completion monitor watches the artifact for time-based or event-based obligations. Same skeleton fits RFP responses, insurance-claim negotiations, purchase-order back-and-forth with vendors, or any multi-round document exchange with downstream monitoring.
**Deployability:** Week-to-month build. The per-negotiation workspace is the interesting architectural piece — most agent stacks default to a single global context, but here each deal is a namespaced memory + tool set. Stack: Claude + OpenAI as a multi-model router, a workspace/memory layer (Mem0, LangGraph checkpoints, or a custom Postgres-per-workspace), Salesforce/HubSpot/DocuSign connectors. Replaces or augments the contract admin and paralegal review layer.
