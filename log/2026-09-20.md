# 2026-09-20 — Agent Pattern Scan

## TL;DR
The freshest concrete pattern is Carvana's Slack-alert-to-PR triage agent: production warnings monitor themselves, and the agent verifies every release against a log baseline from the hour before the deploy. Runner-up is Qonto's in-account financial ops agent that prepares transfers and drafts invoices directly against live bank data. Both replace bespoke bots plus the human who used to babysit them.

## Patterns

### 1. Production-alert-to-PR triage agent
**Source:** [Carvana Claude Tag customer story, Sept 2026](https://claude.com/customers/carvana) — retail-science, verification and wholesale-platform teams route production monitoring warnings through Slack; Claude Tag replaced two homegrown Slackbots.
**Mechanism:** New warning posts to a monitored Slack channel → agent reads the alert plus the team's scoped view of the data warehouse and diffs the last deploy against a log baseline from the hour before it shipped → agent opens a PR with the proposed fix, tags a human for review, and either merges or hands off → also runs hourly sweeps that catch failing pipelines and stale feature flags before anyone pages.
**Why agentic:** It doesn't just surface the alert on a dashboard; it forms a hypothesis from logs, writes code, and pushes the change into a review workflow. The dashboard equivalent would just paint the graph red.
**Generalizable core:** Monitoring signal in any channel → agent enriches with pre-change baseline and scoped historical data → drafts a code or config change → routes for human sign-off before production.
**Deployability:** Slack + Claude Tag + a code repo with scoped warehouse read access. Weekend build for a single service with one alert type; multi-week for a fleet with per-team scoping and PR approval routing. Replaces the on-call engineer's first hour of triage and the internal-tools team maintaining Slackbots. Requires a codebase the agent can safely branch off of, so early-stage teams get value faster than legacy monoliths.

### 2. In-account financial operations agent
**Source:** [Qonto Claude Platform customer story, Sept 2026](https://claude.com/customers/qonto) — Qonto operates SMB business bank accounts for ~500k European small businesses; the agent runs inside the account rather than as a chatbot next to it.
**Mechanism:** In-app message from an account holder ("pay this invoice", "who owes me money") → agent reads the customer's actual transactions, statements, invoices, cards, and supplier records via Qonto's internal APIs → prepares a transfer, drafts an invoice or credit note, reviews pending supplier invoices, provisions a virtual card, or handles a team expense request → writes back into Qonto's ledger and returns confirmation. Complex actions run on Opus 4.5/Sonnet, simpler routing on Haiku, all through Bedrock with EU-compliance guardrails.
**Why agentic:** The agent touches real money and writes to the ledger, not just a summary tab. The financial dashboard equivalent shows the transaction and asks the owner to click.
**Generalizable core:** Natural-language request from the account owner → agent reads the full account state → performs the write action in the system of record → returns receipt.
**Deployability:** Claude via Bedrock (or direct API) + tool functions on top of your own APIs + tiered model routing. Weekend build for a single write action (e.g., "draft invoice from this email"); month-plus for a full multi-model, compliant deployment against a live financial ledger. Replaces the operations analyst or the founder's own after-hours admin queue. Only works if you already own the write APIs — reselling a bank connection through Plaid doesn't unlock this.

### 3. RFP-to-proposal drafting agent
**Source:** [Field Aerospace n8n case study, 2026](https://n8n.io/case-studies/field-aerospace/) — aircraft modification firm doing DoD and international contract work; proposal desk was two-week, three-to-four-person cycles.
**Mechanism:** New government solicitation PDF lands in a shared folder → n8n workflow triggers, agent extracts requirements section-by-section (15–20 min for even large docs) → agent drafts the proposal body against internal capability and past-performance content → outputs an 80% draft in about 25 minutes to a document store where the proposal lead takes over on pricing, risk, and evaluation strategy. Reported at ~$22k annual savings on this single workflow.
**Why agentic:** It reads unstructured RFP text, structures it into a requirements matrix, and produces a compliant response draft — not a template with fill-in blanks.
**Generalizable core:** Long unstructured document arrives → agent extracts a requirements matrix → drafts a compliant response by matching requirements against a private capability library → hands to a human for final judgment.
**Deployability:** n8n + Claude/GPT node + a vector store of past proposals + a shared drive as trigger source. Week-long build for the first RFP type; a month if you want compliance matrices, past-performance retrieval and multi-format output. Replaces the two-week capture-manager sprint that starts every proposal. Works for any bid-driven business: grants, government contracts, insurance tenders, construction bids, agency RFIs.

### 4. CI/CD failure first-responder agent
**Source:** [Anthropic engineering post, Aug/Sept 2026](https://claude.com/blog/ai-ci-cd-on-call) — Anthropic's own CI/CD on-call rotation now runs Claude Tag as first responder; team reports 14-min median SITREPs.
**Mechanism:** CI/CD alert fires → agent reads a repo-checked `oncall.md` file describing the team's escalation criteria (e.g., "if error rate >2% for >5 min AND not a known deploy window, page on-call; otherwise log for morning review") → agent pulls recent deploys, service graphs, and error logs → decides whether to wake a human or just append to a `lessons.md` file that every future investigation reads first. Root-cause writeup and the responsible engineer are tagged back into the incident thread.
**Why agentic:** The self-improving `lessons.md` file is the point. Each incident enriches the criteria the next agent applies, so the same class of flake gets auto-resolved silently on the third occurrence. A dashboard can't remember its own past.
**Generalizable core:** Alert fires → agent reads a plain-text policy file that describes what matters → checks against a growing memory file of prior incidents → decides to escalate, act, or record → writes the outcome back into the memory file.
**Deployability:** Claude Tag / Claude Code + a Slack incident channel + two repo-checked markdown files (`oncall.md`, `lessons.md`) + read access to logs and deploy history. Weekend build for one service; the value compounds only after a few weeks of accumulated lessons. Replaces the on-call engineer's 2 AM sanity check on whether a red graph actually matters. The pattern generalizes to any operational rotation with escalation criteria: security alerts, customer-support pages, ops-center incidents, compliance flags.
