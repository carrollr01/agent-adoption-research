# 2026-08-16 — Agent Pattern Scan

## TL;DR
Six patterns cleared the filter after a long dark stretch in the log. The standout is Erewhon's self-grading customer-service drafter: a first agent writes the reply, a second "English Tutor" agent diffs the sent reply against the draft and turns edit-distance into a live quality signal. It's the cleanest example this scan of a closed supervision loop that replaces QA sampling with a running metric.

## Patterns

### 1. Self-grading reply drafter with an edit-distance grader agent
**Source:** Erewhon customer story (Zapier), https://zapier.com/customer-stories/Erewhon — 10-store grocer in LA, built by one internal analyst; 70% of drafts sent unedited, ~1,500 labor-hours/yr recovered.
**Mechanism:** New Help Scout ticket fires → agent reads the customer's membership tier and purchase history from BigQuery plus a vector store of Erewhon's actual policies → drafts a tone-matched reply and writes it into Help Scout as a suggested response → a second "English Tutor" agent diffs whatever the human ultimately sends against the original draft, scores the edit distance, and files that score as a rolling quality metric.
**Why agentic:** Two agents with different jobs — one produces work, the other supervises it — writing back into the same system-of-record. There is no dashboard in the loop; the metric emerges from the actions taken.
**Generalizable core:** Inbound work-item → drafter agent produces the artifact and writes it into the queue → grader agent compares final human-sent version to the draft and turns the delta into a live quality signal.
**Deployability:** Zapier + Help Scout + a vector store + BigQuery + LLM. About a week for the drafter loop, another couple of days for the grader. Replaces first-draft CS work; the grader replaces manual QA sampling. Only useful once a policy corpus exists and is versioned.

### 2. Retrieval over a labeled winning-artifact corpus, then generate the artifact itself
**Source:** LegalOS (YC W26), https://www.ycombinator.com/companies/legalos — launch post https://www.legalos.ai/post/legalos-yc-w26; $1.5M ARR during batch, "dozens" of petitions filed, reported 100% approval on filings so far.
**Mechanism:** Employer submits a hire's CV, publications, press, prior filings → agents pick the visa category, retrieve over a corpus of ~12,000 previously-approved USCIS petitions (O-1, H-1B, EB-1A, EB-2 NIW, L-1, TN) → draft the petition narrative arguing the specific USCIS criteria, compile the exhibit list with pincites, and flag evidentiary gaps and anticipated RFEs → the finished I-129 / I-140 packet lands in the licensed attorney's review queue for sign-off. Cycle drops from a 2–4 week paralegal + associate drafting effort to ~48 hours.
**Why agentic:** The output is the filed legal artifact, not a scorecard or checklist. Choosing category, arguing criteria, and predicting RFEs are per-case judgments made against the retrieved corpus.
**Generalizable core:** Curated corpus of past-winning artifacts (with the criteria they satisfied) → RAG picks precedents for the incoming case → agent drafts the artifact and self-flags weak spots → human licensed reviewer signs.
**Deployability:** RAG over the corpus + LLM drafting chain + evidence-management UI + reviewer queue. Prototype in a weekend, quarter to make defensible. Replaces first-year associate / paralegal drafting hours. Moat and scaling constraint are the same thing: the labeled corpus.

### 3. Monitoring signal → root-cause → autonomous fix PR
**Source:** Sentry customer story (Claude), https://claude.com/customers/sentry — Sentry using its own Seer feature in production; the loop handles error volume against >1M RCAs/yr and reviews 600K+ PRs/mo.
**Mechanism:** Production error fires in Sentry → Seer produces a root-cause analysis with relevant repo context → a Claude Managed Agent takes the RCA, opens a branch, writes the patch, and opens a PR with the fix and its reasoning → developer reviews and merges.
**Why agentic:** No developer initiated this. The agent picks files, writes code, and creates a review artifact in the SCM in response to an automated signal. The output is a mergeable PR, not a suggestion in a chat window.
**Generalizable core:** Automated signal from monitoring → structured diagnosis with system context → autonomous code change proposed as a reviewable PR in the SCM of record.
**Deployability:** Claude Managed Agents + Sentry + GitHub, week-to-month build. Replaces the "triage bug, write the small fix, open a PR" slice of on-call. Test coverage is the safety net; the pattern is unsafe where tests are thin.

### 4. VCS-event-triggered fan-out of computer-use agents against a preview URL
**Source:** Launch HN: TesterArmy (YC P26), https://news.ycombinator.com/item?id=48586299 — June 26, 2026; docs at https://docs.tester.army/run/pull-request-testing. Reports "150 hrs/month saved" across seed-to-Series-C customers.
**Mechanism:** GitHub PR opens or a Netlify deploy-preview URL publishes → a webhook / GitHub Action spawns many cloud agents in parallel, each launching a real browser (or mobile device), each running one natural-language scenario → agents log in, handle OAuth callbacks and email/SMS OTPs autonomously, and evaluate pass/fail via a vision model → results post back as a PR comment with screenshots, video, and failure context.
**Why agentic:** The agents actively drive the app — click paths, credential handling, VLM-scored outcomes — instead of running a pre-recorded script. Adding a scenario is writing a sentence, not authoring Playwright.
**Generalizable core:** VCS event → fan out N ephemeral computer-use agents against the preview environment → post evidence-backed verdicts back to the artifact under review.
**Deployability:** Trigger.dev / Vercel + a headless browser pool + a VLM + inbox/SMS access for OTPs. Week to ship a single-flow version, month to make OAuth + OTP + mobile robust. Replaces QA/SDET regression maintenance. Enterprise scaling bottleneck is mailbox/SMS access for OTP fetching.

### 5. Vision-to-structured-inventory from ambient phone photos
**Source:** How I AI — Jesse Genet's five agents, https://www.chatprd.ai/how-i-ai/jesse-genets-5-openclaw-agents-for-homeschooling-app-building-and-physical-inventories — Lumi founder, "Sylvie" runs on its own Mac Mini as part of a five-agent household rig with least-privilege partitioning between agents.
**Mechanism:** Operator takes phone photos of a shelf, cupboard, or room and drops them to Sylvie → vision model enumerates visible items, tags each with category and suggested age range against a role-prompt schema → dedupes against prior entries and writes rows into a searchable per-location inventory DB.
**Why agentic:** Unstructured pixels become queryable rows and reconcile against prior state. A dashboard would only display already-tagged inventory; here the agent creates the taggable rows.
**Generalizable core:** Photo dropped to agent → vision extracts objects with schema → dedupe → write structured rows keyed by location into an inventory of record.
**Deployability:** Vision-capable LLM + SQLite / Airtable + a phone upload path. Weekend build. Replaces the "type it into the spreadsheet" step of any physical audit. Demoed at household scale by the guest — the skeleton drops onto small-store back-rooms, warehouse spot-checks, and walk-in audits with no architectural change.

### 6. Engagement-signed trigger → agent generates and self-deploys a per-client hosted artifact
**Source:** How I AI — Grace Clarke's Pipeline Operator (Aug 7, 2026), https://www.chatprd.ai/how-i-ai/claude-workflows-for-business-automation-and-managing-gmail; Lenny's writeup, https://www.lennysnewsletter.com/p/claude-code-for-normal-people-skills — solo consultant running the loop end-to-end.
**Mechanism:** New client signs / discovery notes land → Claude Code chains three small Skills (a `voice_guide.md`, a `proposal_maker.md`, an onboarding-page skill) against the raw notes → agent generates a branded interactive HTML proposal and companion onboarding page → deploys the HTML as a password-protected site via the Netlify CLI → URL emails back to the client. The finished artifact is a live URL, not a PDF or a slide deck.
**Why agentic:** The agent decides section structure and phrasing from unstructured notes and ships a real deployed artifact per engagement. Skills carry the style rules; the agent picks how to apply them.
**Generalizable core:** New-engagement trigger → small skill files carry brand and structure DNA → agent generates and self-deploys a bespoke per-client hosted artifact, URL returned to the client.
**Deployability:** Claude Code + Skills + Netlify CLI/API. Weekend build for one skill; a few days to chain three. Replaces the junior consultant / contract designer who used to hand-build client collateral per engagement. Tested solo; drops onto any agency or consulting firm shipping bespoke deliverables.
