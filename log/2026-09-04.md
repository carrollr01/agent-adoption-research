# 2026-09-04 — Agent Pattern Scan

## TL;DR
Six concrete patterns today, all from the last week. The most interesting is Rootstock's Summer '26 ERP release, which puts an agent between the sales-order form and the delivery-date field: instead of a rep pinging planners on Slack, the agent reads live inventory + open POs and writes a committed date back to the order. The mirror-image pattern handles supplier slips. Also notable: LunaBill's outbound voice callers navigating payer IVRs on behalf of hospital billers, and Corvera parsing retailer PO PDFs straight into NetSuite for CPG brands.

## Patterns

### 1. Sales-order delivery-promise agent inside the ERP
**Source:** [Rootstock Software — Summer '26 release, midmarket manufacturing pilots (Aug 2026)](https://erpnews.com/rootstock-pushes-ai-agents-into-production-workflows-with-summer-26-erp-release/) — Rootstock is a Salesforce-native manufacturing ERP; the delivery-promise agent is in active pilot with midmarket manufacturers as of the Summer '26 wave.
**Mechanism:** New sales order created in Rootstock that can't be fulfilled from on-hand inventory → agent reads current stock, active BOMs / component requirements, and every open purchase order's expected receipt date → computes a committed delivery date and writes it back to the sales-order record → replaces the inside-sales rep's habit of Slacking a planner or ops manager and waiting hours for a hand-verified promise date.
**Why agentic:** It's a state-change trigger on an ERP record, followed by a multi-source read across three separate object types (inventory, BOM, PO), followed by a durable write back to the originating record. Not a report, not a lookup — the order comes out of the flow with a real date on it.
**Generalizable core:** New inbound-commitment record → agent stitches upstream supply/capacity data → writes the answerable field back onto the record → replaces the human back-and-forth that normally gates the response.
**Deployability:** Weekend-to-week build for any shop already on a queryable ERP or ops DB — Rootstock/NetSuite/Odoo + Claude API with MCP over the ERP + a webhook/trigger on record create. Complexity climbs where the read-side data is fragmented (spreadsheets, siloed vendor portals). Augments an inside-sales or planning role; doesn't need dedicated ML headcount.

### 2. Purchase-order slip → downstream-impact expediter
**Source:** [Rootstock Software — Summer '26 pilots (Aug 2026)](https://erp.today/rootstock-ai-agents-manufacturing-erp) — same release, distinct agent.
**Mechanism:** PO's expected receipt date slips (supplier confirms a delay, or the promised date passes) → agent reads every sales order and work order whose materials trace back to that PO, plus alternative-supplier catalog data → writes an expediting recommendation onto the PO record listing which downstream orders will now slip and what alt-source options exist → replaces the buyer/expediter's manual cross-referencing across sales, production, and vendor lists.
**Why agentic:** The event isn't a person opening a screen — it's a data change on a supplier record propagating outward. The agent runs the ripple analysis every time and posts a proposal, not a dashboard tile.
**Generalizable core:** External event mutates a source record → agent walks the dependency graph downstream → writes a specific proposed action (not a summary) onto the originating record for a human to approve.
**Deployability:** Similar to #1; the harder engineering is modeling the dependency graph (BOMs and open-order pointers) so the agent can walk it reliably. Week to month build. Replaces the expediting/buyer role's most time-consuming task without eliminating the role.

### 3. Pre-dispatch cash-on-delivery verification agent
**Source:** [Cashfree Payments — "Relay" AI Super Agents, GA Aug 30, 2026 (Business Standard)](https://www.business-standard.com/companies/news/cashfree-rolls-out-ai-agents-for-merchants-to-automate-payment-operations-126083000455_1.html); [IBS Intelligence coverage](https://ibsintelligence.com/ibsi-news/cashfrees-relay-brings-ai-agents-to-smb-payment-operations/) — live with Indian SMB merchants on Cashfree's payment rails.
**Mechanism:** COD order placed in the merchant's storefront but not yet dispatched → agent reads the customer's prior COD success rate, contact history, and order value → places an outbound WhatsApp message or voice call to confirm intent → marks the order verified or cancelled in the merchant's OMS before the warehouse pulls it → replaces the ops-staff routine of hand-calling every large COD to weed out fake orders before packing.
**Why agentic:** The trigger is a specific storefront event with a time window (before dispatch, not after), the agent chooses which channel to use based on prior contact success, and the output is a state change on the OMS record — not a "call this customer" queue for a human.
**Generalizable core:** New inbound transaction on a fraud-prone channel → agent enriches with historical customer signal → runs an outbound verification loop on its own → writes verdict to the transaction record before the next system in the pipeline picks it up.
**Deployability:** Vapi/Retell for voice + WhatsApp Business API or Twilio for messaging + Claude API + a webhook off the storefront (Shopify/WooCommerce/direct DB). Week build. Replaces an ops-clerk task that many SMBs skip entirely and eat the loss on. Same skeleton fits any high-cancellation, high-fraud channel — free-trial signups, restaurant reservations at scale, ticketed events.

### 4. Chargeback-deadline dispute-filing agent
**Source:** [Cashfree Relay, same release (Elets BFSI, Aug 2026)](https://bfsi.eletsonline.com/cashfree-payments-launches-relay-ai-super-agents-to-automate-end-to-end-payment-operations-for-smbs/) — distinct agent from #3 inside the same product.
**Mechanism:** Inbound chargeback event where the network's filing deadline is approaching → agent reads the disputed transaction record + attached evidence bundle (delivery confirmation, communications, order metadata) → assembles the dispute response in the network's required format and files it before the deadline expires → replaces the merchant's last-minute paperwork scramble (or worse, the missed-deadline auto-loss).
**Why agentic:** The trigger is a countdown, not a person. The agent reads across systems (payments dashboard, order system, shipping proof), synthesizes into a network-specific format, and files. Money-movement or customer-visible actions require merchant approval; the agent itself does the assembly and filing.
**Generalizable core:** Countdown-on-record trigger → agent gathers evidence across multiple systems into a required external format → files with the counterparty on the merchant's behalf → replaces the "we ran out of time" auto-loss mode.
**Deployability:** Vertical-specific — the value is in knowing each payment network's evidence template. Month build if you're wiring up Visa/Mastercard/Stripe dispute flows from scratch; days if a vendor SDK exists. Same skeleton applies to any deadline-driven filing: insurance appeals, small-claims responses, tax notices, warranty claims, permitting responses.

### 5. Outbound voice caller for hospital A/R follow-up
**Source:** [LunaBill — YC F25 launch (Sept 2026)](https://www.ycombinator.com/launches/Ooq-lunabill-ai-voice-callers-for-healthcare-billing-teams) — piloting with hospital revenue-cycle teams and independent RCM firms; the pitch cites ~100% pilot-to-paid conversion and 10x claims-followed-up per biller in week 1.
**Mechanism:** Billing team uploads open-claims list (Excel/CSV) → agent reads claim ID, payer, patient, current denial or pending status per row, plus its own fine-tuned model of each payer's IVR tree → places live outbound calls to insurance payers at up to 100 concurrent → navigates the IVR, asks clarifying questions of the human rep, captures claim status and denial reason, opens an appeal in the same call where possible → writes a structured status + full transcript back into the billing system → replaces the biller's 30-minute status-check phone call, which reportedly eats 80% of a biller's day.
**Why agentic:** Voice is the trigger surface, but the loop is not the receptionist pattern — this is the agent as the *caller*, not the answerer, navigating a payer's own IVR to extract data. Batch trigger, per-call reasoning, per-call state write.
**Generalizable core:** Backlog of outbound inquiries needing another party's system to answer → agent places calls at concurrency the human team can't → captures structured outcome + transcript → writes back to the source-of-truth system → replaces the "one caller, one hold, one call at a time" bottleneck.
**Deployability:** HIPAA and SOC 2 raise the bar here; that's part of LunaBill's moat. In lower-stakes verticals, the same skeleton runs on Vapi/Retell + a call-outcome parser + a CSV/API back-write. Reachable analogs: pharmacy prior-auth chase, insurance premium-appeal chase, county-records status calls for title companies, supplier order-status calls for wholesalers, permit-status calls for GCs. Week-to-month build outside healthcare.

### 6. Retailer-PO parser wired straight into the ERP for CPG brands
**Source:** [Corvera — YC W26 launch, London (Sept 2026)](https://www.ycombinator.com/launches/PES-corvera-ai-agents-for-cpg-brands); [tech.eu, May 2026 raise](https://tech.eu/2026/05/05/london-founded-corvera-raises-42m-to-bring-agentic-ai-to-cpg-supply-chains/) — CPG brands selling into big-box retail and marketplaces.
**Mechanism:** Retailer buyer emails a PO (PDF, sometimes EDI-flavored PDF) to the brand's shared inbox → agent parses email body + attachment for SKUs, quantities, ship-to, terms → matches SKUs against the brand's catalog → creates the sales order in the ERP (NetSuite is called out) with exceptions surfaced to a human for approval. A sibling scheduled poll of Amazon Seller Central / Shopify pulls new settlement reports and reconciles them line-by-line against expected fees, chargebacks, and returns. Replaces the ops analyst's re-typing job and the eyeballing of Amazon settlement CSVs.
**Why agentic:** Inbound-email trigger, multi-modal parse (email + PDF), catalog-matching read, and a durable write to a downstream ERP record. Reconciliation runs on a schedule with a per-line agentic judgment on match/mismatch/dispute.
**Generalizable core:** Unstructured inbound document (email/PDF/portal) → agent parses and enriches against internal reference data → creates the downstream operational record → replaces the human's data-entry-plus-sanity-check loop.
**Deployability:** Any brand with (a) an ERP that has a decent API and (b) trading partners who send POs as email attachments — which is most SMB-to-midmarket CPG, distribution, industrial supply, and manufacturing. Zapier/Make + Claude API + ERP MCP or REST is a week build for a single retailer's PO format; complexity scales with the number of formats. Replaces one FTE of order-entry per ~200 orders/week. Same skeleton also fits: benefit-broker COIs into a policy admin system, freight BOLs into a TMS, construction subcontract change orders into a PM tool.
