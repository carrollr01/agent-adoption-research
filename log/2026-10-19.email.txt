# 2026-10-19 — Agent Pattern Scan

## TL;DR
Insurance and insurance-adjacent operations produced three distinct mechanism-level patterns this week: email-submission-to-draft-quote with human sign-off (CFC Lane Assist), inbound-document reconciliation against a system of record (Vertafore Policy Check), and weather-event-triggered multi-agent claim settlement (Allianz Project Nemo). A fourth from Figma: multiple design agents operating in parallel on a shared canvas rather than on separate tasks. Four strong patterns, none duplicating anything in the last 14 log files.

## Patterns

### 1. Email-to-draft-quote with underwriter approval
**Source:** CFC pilots agentic underwriting with Lane Assist (CFC, April 2026) — https://www.cfc.com/en-gb/knowledge/news/2026/04/cfc-pilots-agentic-underwriting-with-launch-of-lane-assist-and-quotes-first-policy/ — CFC is a specialty cyber insurer; the pilot runs inside their cyber underwriting team on real low-complexity submissions. Still live and expanding through autumn 2026.
**Mechanism:** A broker email arrives in the shared submissions inbox → the agent parses the email + attached submission form, pulls company data, risk indicators, and prior CFC history → applies CFC's codified underwriting rules → produces a quote recommendation (price, limits, conditions, rationale) → drops the draft into the underwriter's queue → underwriter approves or edits before any quote is sent to the broker. Collapses a 24-hour human triage-and-pricing loop to seconds of agent work plus whatever time the underwriter takes to review.
**Why agentic:** The agent reads an unstructured inbound message, decides what facts matter, retrieves context from multiple sources, and produces a priced recommendation rather than a status readout. A dashboard would show a submissions pipeline; this writes the next action into it.
**Generalizable core:** Inbound unstructured request in a natural channel → agent parses + enriches with internal rules and history → drafts the priced/scoped response → specialist human approves on the same channel before send.
**Deployability:** Email ingest (Gmail/Outlook MCP or IMAP) + a rules/retrieval layer (any vector store + a scoring prompt) + Claude or similar + a drafting UI the human lives in. A weekend build for a toy version; a month to get a defensible rules layer and an approval UI a specialist will actually use. Replaces the first-pass triage and pricing step of an underwriter, estimator, broker, intake analyst, or any role that reads an inbound request and composes a priced response. Scales down to small insurance brokerages, trade estimators, agencies writing proposals, and inbound sales teams at any size — no ML headcount needed.

### 2. Inbound-document reconciliation against a system of record
**Source:** Vertafore launches Policy Intake and Policy Check agents (Vertafore, 2026) — https://www.vertafore.com/resources/press-releases/vertafores-latest-ai-innovations-help-agencies-accelerate-carrier and Vertafore unveils four Velocity AI agents, Sept 23, 2026 (Insurance Edge) — https://insurance-edge.net/2026/09/24/say-hello-to-the-agentic-agency-from-vertafore/ — independent insurance agencies on AMS360; Vertafore reports up to 90% less policy-check time per line of business in early-adopter testing.
**Mechanism:** A carrier-issued policy document lands in the agency (email attachment or carrier portal pickup) → the Policy Check Agent extracts coverages, limits, named insureds, endorsements → diffs them line-by-line against what the AMS360 record says should be there → produces a mismatch list with proposed corrections (e.g., "endorsement X missing from AMS record," "liability limit shows $1M vs $2M on form") → the account manager approves each proposed change, which is then written back into AMS360. The Policy Intake Agent runs the mirror pattern inbound: unstructured policy PDF in, structured AMS fields out, with approval before write.
**Why agentic:** Two sources of truth, a diff, a proposed correction per mismatch, and a write-back action — the agent is doing the account manager's weekly reconciliation pass, not just surfacing anomalies on a report. The dashboard version of this is a "policy exceptions" report that nobody opens.
**Generalizable core:** New document arrives → agent extracts structured facts → diffs against the system of record → proposes field-level corrections → human approves write-back.
**Deployability:** PDF parsing (Reducto, LlamaParse, or Claude directly for low volume) + the record-system's API or a browser-based writer where no API exists + a diff/approval UI. Translates well outside insurance: bank statement reconciliation against accounting GL, lease amendments vs property management records, signed contract vs CRM opportunity record, medical claim EOB vs practice-management ledger, carrier BOL vs TMS freight record. Week-to-month build depending on how clean the extraction target is. Replaces or augments the reconciliation portion of bookkeeper, account manager, paralegal, or ops analyst roles.

### 3. Weather-event-triggered multi-agent claim settlement
**Source:** When the storm clears, so should the claim queue (Allianz, Nov 2025) — https://www.allianz.com/en/mediacenter/news/articles/251103-when-the-storm-clears-so-should-the-claim-queue.html and Allianz food spoilage claims agentic AI (Coverager) — https://coverager.com/allianz-introduces-agentic-ai-to-speed-up-food-spoilage-claims/ and Canstar 2026 Innovation Excellence Award page (Allianz Australia) — https://www.allianz.com.au/about-us/work-with-us/partners/news/allianz-wins-2026-canstar-innovation-excellence-award.html — Allianz Australia, extending the Project Nemo food spoilage workflow through 2026. Allianz cites ~80% reduction in processing and settlement time; small claims (under AUD$500) settle in hours.
**Mechanism:** A customer submits a food spoilage claim after a power outage → a seven-agent system fans out in parallel: one agent checks policy coverage and inclusions, another cross-references the stated outage against third-party weather and grid outage data, another runs fraud screening against prior-claim patterns, another calculates payout against documented contents and limits, others handle correspondence and audit logging → each writes its finding to a shared case record → a human adjuster reviews the consolidated case and approves the final payment decision → claims under AUD$500 are settled and paid within hours.
**Why agentic:** The novel part is that the trigger assembly combines a customer-filed claim with an external weather/grid signal, and the "reading" phase is itself parallelized across specialized sub-agents that each pull from different data sources. The adjuster isn't inspecting a dashboard of agent findings — they're approving a case the agents built end-to-end.
**Generalizable core:** External event signal + customer-reported event combine as trigger → orchestrator fans out to specialist sub-agents (coverage, verification, fraud, calculation) → each writes to a shared case record → human approves the consolidated recommendation before an irreversible action.
**Deployability:** This is the biggest build on the list — orchestrator (LangGraph, Claude sub-agents, or any workflow engine) + several specialist agents with their own tool access + a case-store + an adjuster approval UI. Reasonable scale for a mid-sized insurer, parametric payout product, warranty claim operation, or chargeback/dispute team. The weather-signal angle (external-world event as part of the trigger context) generalizes to flight delay claims, crop insurance, event-cancellation refunds, outage SLA credits, and shipping damage claims. Month-plus build; viable with a two-engineer team, no dedicated ML headcount needed because each sub-agent is a focused prompt against a specific data source.

### 4. Multiple agents working in parallel on one shared artifact
**Source:** Figma Design Agent (Figma) — https://www.figma.com/solutions/ai-design-agent/ and Figma Design Agent review (Flowstep, 2026) — https://flowstep.ai/blog/figma-agent-review/ and Figma adds AI agent to collaborative canvas (Framia) — https://framia.converge.ai/page/en-US/news/figma-ai-agent-collaborative-canvas-design — Figma launched the canvas agent on May 20, 2026; by autumn users can run multiple agents simultaneously on the same canvas, each scoped to a specific frame or component.
**Mechanism:** A designer selects frames or components and opens an agent panel → gives one agent a scope ("rework the mobile sign-up flow for brand voice v2") and spawns another with a different scope on a different part of the same canvas ("extract all current colors into a palette frame") → each agent operates in its own instructions and context but writes native Figma layers back into the shared file → the designer reviews both outputs side by side in the same canvas, picks what to keep, discards what to throw away. The parallel-on-shared-artifact pattern replaces the serial model of "ask the AI, wait, undo, ask again."
**Why agentic:** Each agent is doing scoped goal-driven work ("make the typography 10% larger across these three screens" is a goal with judgment, not a macro), writing production artifacts to a shared workspace, and multiple of them are doing it simultaneously without colliding. The old dashboard analogue would be a comments/annotations layer; this is parallel coworkers.
**Generalizable core:** Multiple agents scoped to different regions of one shared artifact → each works in parallel → each writes native output back to the artifact → human reviews the composed result and discards per-agent what doesn't land.
**Deployability:** The pattern itself ports beyond design: parallel agents on sections of a long document (one on each chapter, one on footnotes, one on glossary), parallel agents on a monorepo (one on each package, each opening its own PR), parallel agents on a spreadsheet model (one builds the revenue tab, one builds the cost tab, one builds the sensitivity tab), parallel agents in a BOM or CAD assembly, parallel agents in a complex Figma or Framer prototype. Requires the host workspace to have (a) stable region scoping, (b) a merge model that handles concurrent writes, (c) a review surface the human can scan. For custom build-outs, use Git branches as the merge model and Claude sub-agents as the parallel workers. Week-to-month build on top of an existing workspace that already supports regions. Replaces the pattern of a single human cycling through small AI prompts on different parts of a document or file.
