# 2026-10-09 — Agent Pattern Scan

## TL;DR
Four concrete patterns today. The most interesting is Puzzle's AI Close, which replaces the monthly accounting close altogether by having agents reconcile continuously throughout the month and leaving only review/approval for period end. Also strong: Carvana's Slack-alert-to-PR pipeline (Claude Tag), Claire Vo's Merge Mommy risk-scoring PR reviewer (Vercel Eve), and the Supermetrics MCP connector that lets marketers run paid campaigns from a Claude chat.

## Patterns

### 1. Alert-channel-to-pull-request on-call agent (Carvana / Claude Tag)
**Source:** [claude.com/customers/carvana](https://claude.com/customers/carvana) — Carvana (used-car retailer, ~22k employees). Replaced two homegrown Slackbots with Claude Tag; reports a 56% drop in alerts in one retail-science channel and a 65% faster answer time on their wholesale platform team.
**Mechanism:** Production monitoring alert posts into Slack → agent reads logs, the repo, runbooks and a baseline from the hour before the last release → identifies the owning team → posts a root-cause write-up in that team's preferred format and opens a draft PR with a fix → engineer reviews/merges. The agent also runs on an hourly schedule to look for failing pipelines and stale feature flags, not just inbound pages.
**Why agentic:** The agent decides which team owns the fire, which repo and log window to look at, and when to escalate; it's not a predefined runbook executor. It writes code back to the system that fired the alert, with human approval only at the merge gate.
**Generalizable core:** Inbound alert in any channel → agent assembles context from logs/code/history → drafts a specific remediation → human approves the write.
**Deployability:** Claude Agent SDK + Slack app + GitHub + whatever data warehouse scopes each team gets. Not a weekend build — the write-up suggests at least a few weeks of plumbing per team to wire warehouse access correctly. Replaces first-pass on-call triage, not merge authority. The hourly-sweep variant is the interesting generalization: a cron that pretends to be an alert so the same agent handles proactive drift as well as inbound pages.

### 2. Continuous month-end close (Puzzle AI Close)
**Source:** [puzzle.io/ai-close](https://puzzle.io/ai-close) and [puzzle.io blog, Jun 2026](https://puzzle.io/blog/ai-agents-month-end-close-guide) — Puzzle, an AI-native ledger used by startup finance teams and small accounting firms. Third-party review ([SoftwareConnect](https://softwareconnect.com/reviews/puzzle-accounting-software/)) and a [beancount.io write-up](https://beancount.io/blog/2026/09/25/puzzle-close-agents-month-end-reconciliation-accountant-signoff-guide) describe a 15-20-day close shrinking to 3-5 days with 98% transactions auto-categorized at early-adopter firms. Figures are vendor-reported.
**Mechanism:** New transaction lands in Stripe/Mercury/Ramp/Brex/Gusto feeds → agents match it to the ledger continuously, categorize it, flag exceptions, draft accruals and journal entries, and queue them for sign-off → accountant reviews drafts (bank/credit-card reconciliations, accrual review, uncategorized-txn review, variance checks) at an approval checkpoint rather than reconstructing the month from zero → nothing posts without approval.
**Why agentic:** The trigger is "new transaction arrives," not "last day of month." The agents choose which template applies, which account the entry belongs to, and when a transaction needs human escalation. The replaced artifact isn't a report; it's an entire monthly batch process.
**Generalizable core:** Treat the periodic batch job as a stream — fire the agent on each new record, hold outputs in a drafts queue, and let humans review at the usual cadence instead of reconstructing everything at once.
**Deployability:** Stack is live SaaS feeds + a ledger with templates + an approvals UI. Fits a weekend prototype if you only cover one feed and one entity (bank reconciliation off a Plaid feed into a Postgres ledger with a review table); a real deployment is a month-plus for multi-feed, multi-entity, audit-trail-grade. Replaces or augments the controller/bookkeeper's end-of-month compression. The same shape — "continuous drafts, periodic human review" — would transplant to legal matter billing, insurance claims closeouts, construction job-cost close, and payroll runs. Caveat: deterministic/same-input-same-output is a vendor claim; audit-firm acceptance of agent-drafted entries is still an open governance question.

### 3. Risk-scored PR triage and auto-approval (Merge Mommy on Vercel Eve)
**Source:** [chatprd.ai/how-i-ai/merge-mommy](https://www.chatprd.ai/how-i-ai/merge-mommy-vercel-eve-ai-bot-for-auto-reviewing-pull-requests) and the [Lenny's Newsletter episode writeup](https://www.lennysnewsletter.com/p/build-an-ai-code-review-bot-in-30), Aug 2026 — Claire Vo built it on Vercel Eve in a single Codex session. Deployed on her own team; Intercom's cited internal numbers (AI-approved PRs move 5x faster with a lower revert rate) suggest the pattern is spreading inside tech orgs.
**Mechanism:** CI finishes on a PR → agent scores it across six dimensions (change size, blast radius, reversibility, data/security impact, operational impact, test/CI completeness) → below 24 points, the agent approves it; above 64, it pings the author's lead in Slack with its reasoning and open questions; middle band gets commentary without approval. The agent also refuses to approve a PR it can't merge (open conflicts, failing checks).
**Why agentic:** The agent is choosing where human attention goes, not replacing it. Its output is a decision about which PRs need a person at all; the escalation message carries its reasoning so the human review starts hot rather than cold.
**Generalizable core:** Scored triage over an inbound queue — grade each item on a known rubric, auto-dispose the clearly safe tail, escalate the risky head with pre-written context so the human review starts informed.
**Deployability:** Vercel Eve template + GitHub webhook + Slack. Weekend build at the single-rubric level; the real work is tuning the dimensions and thresholds on your own historical data. Replaces reviewer-fatigue triage, not reviewer judgement. The same mechanism would move cleanly to: insurance claim intake (score and auto-approve the low-dollar routine ones, escalate the ambiguous), lending underwriting pre-screens, support ticket severity triage, grant-application first-pass review, HR applicant screens. Any queue where ~70% of items are low-stakes and ~5% genuinely need the senior reviewer.

### 4. Natural-language ad-platform operator via MCP (Supermetrics for Claude)
**Source:** [claude.com/customers/supermetrics](https://claude.com/customers/supermetrics) and [supermetrics.com/blog/supermetrics-for-claude](https://supermetrics.com/blog/supermetrics-for-claude-your-new-marketing-workflow) — Supermetrics (marketing data company, ~500 employees). Reports 250% MoM growth in active users since the Feb 2026 launch, and an agency customer (Layer) says a 10-hour report now takes 20 minutes. Vendor numbers.
**Mechanism:** Marketer asks Claude a question or gives a command in chat → Claude calls Supermetrics' MCP server → Supermetrics authenticates to Google Ads, Meta, Microsoft Ads, TikTok with the marketer's existing logins → returns live metrics for a question, or executes campaign/ad-group/ad/budget/targeting creates and edits for a write command → every new campaign starts paused, every change is logged, one-click undo. Fourteen tools total (7 read, 5 write, 2 undocumented) per third-party review.
**Why agentic:** It plans the data pull and the write (which platform, which account, which fields) from a plain-English instruction, then executes against four live SaaS APIs. The paused-by-default write is the governance primitive; the agent takes the action but gates deployment.
**Generalizable core:** MCP-mediated SaaS operator — one credentialed data broker between a chat agent and the vertical SaaS, with writes defaulted to a safe, reversible state (paused, draft, pending) and a human flip to go live.
**Deployability:** The pattern itself (vertical SaaS + MCP server + Claude chat) is a week's build with the Claude Agent SDK and MCP boilerplate. The hard part is the credential-brokering layer: Supermetrics was already doing that for 100+ ad platforms before adding the MCP endpoint. The role replaced is "agency media buyer running dashboards," not strategy. The same shape fits any domain where a vertical data vendor already sits between operators and raw APIs — property-management PMS, EHR, legal practice management, veterinary PIMS — if the vendor is willing to publish an MCP server with scoped writes.
