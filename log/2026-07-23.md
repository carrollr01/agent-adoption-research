# 2026-07-23 — Agent Pattern Scan

## TL;DR
Five concrete deployments logged today, all mechanism-level. The most interesting is Beacon Health's "record-once-replay-forever" EHR agent: a practice manager screen-records the workflow once, and the agent replays it across the entire patient panel without an API integration. That inverts the screen-watching-to-write-SOPs pattern already logged — here the recording IS the executable policy, not documentation of one.

## Patterns

### 1. Record-once-replay-forever EHR agent
**Source:** [Beacon Health](https://www.ycombinator.com/companies/beacon-health) — YC W26 primary-care operations agent, live against a 40,000-patient IPA as of Feb 2026. Two-person founding team.
**Mechanism:** Trigger is a panel-level event — a patient becomes due for a screening, referral, prior auth, or gap-in-care follow-up, surfaced by queries against the payer roster and EHR problem list. The agent reads the chart, the payer's prior-auth form, and the referral directory, then executes a browser workflow that a practice manager screen-recorded once (clicks, form entries, note writes) across the full panel. It writes back to the EHR (Athena, Epic, eClinicalWorks), submits to payer portals, and dispatches patient SMS/voicemail. Replaces the care coordinator's manual EHR navigation and portal work.
**Why agentic:** The agent selects patients, sequences a multi-step workflow per case, decides when to escalate to a human, and interacts with several systems no single one of which exposes a usable API.
**Generalizable core:** Record human workflow once in a legacy web UI → executable policy → agent replays across a cohort surfaced by a triggering event.
**Deployability:** Playwright or Browserbase browser automation + a step graph derived from the recording + per-step assertion checks + an exception queue. Month-scale build; the LLM piece is small — the hard parts are DOM-drift resilience, credentialed session management, and asserting on state between clicks. Replaces a back-office coordinator ($20–35/hr). Only makes economic sense in at-risk / value-based practices where gap closure carries P&L; fee-for-service clinics don't reward the same workflow. HIPAA/BAA surface is real.

### 2. Vision-to-estimate agent for physical quotes
**Source:** [PLAN0](https://www.ycombinator.com/launches/QLl-plan0-ai-powered-construction-cost-estimates-analytics) — YC-backed construction estimation agent; per YC's own launch, ~$20B of projects have run through the platform. Customers include real-estate developers, GCs, and lenders.
**Mechanism:** Trigger is a user uploading architectural plans (PDF or DWG) at project bid stage. The agent reads multi-page drawings — floor plans, elevations, MEP sheets — via multimodal vision, joins extracted quantities against a proprietary and partner-fed localized historical unit-cost database, maps line items to CSI cost codes, and produces an estimate plus scenario analytics (swap materials, stress-test against overrun history). Written to an exportable estimate spreadsheet and a queryable project object. Replaces a junior estimator's takeoff, collapsing 2–6 weeks of manual work into minutes.
**Why agentic:** Vision extraction, cross-sheet quantity reconciliation, cost-catalog matching, and scenario generation are chained autonomously; the estimator's role becomes review and adjustment rather than production.
**Generalizable core:** Unstructured visual/document artifact → vision extraction + proprietary reference corpus → structured, priced deliverable.
**Deployability:** Multimodal LLM (Claude vision or GPT-4o-class) + specialist detection for symbols and legends + a domain reference database the customer supplies or A3 curates + a review UI. Month-scale build. The moat is the reference data, not the model. Requires drawings standardized enough to parse and a defensible price/history corpus. The same skeleton — visual document + price DB → line-item quote — applies to cabinetry shops, sheet-metal fabricators, and print shops.

### 3. Inbox-triage agent for messy multi-attachment intake
**Source:** [FurtherAI submissions processing](https://www.furtherai.com/blog/from-basic-automation-to-ai-agents-transforming-insurance-submission-processing) — deployed at a top-tier US Managing General Agent, ~$1.5B written premium; ~2,000 hours saved in the first three months, ~$20B of TIV processed.
**Mechanism:** Trigger is a broker email hitting a shared submissions inbox with 100–200 page attachments — ACORD forms, statements-of-values, loss runs, engineering PDFs. The agent extracts structured fields from each PDF, validates completeness against a schema plus internal appetite rules, drafts a reply email asking for missing items, and routes the submission down one of three paths: auto-quote, escalate to an underwriter, or decline. Written to the policy administration system as a new row, to the submissions log, and back to the broker email thread. Average clearance drops from ~32 minutes to ~1 minute.
**Why agentic:** The agent chooses what to extract, decides what's missing, drafts human-readable follow-up, and routes autonomously across several workflow states.
**Generalizable core:** Inbound email with heterogeneous document attachments → extract to schema + gap-check → auto-reply for gaps + route to downstream workflow.
**Deployability:** Gmail or Microsoft 365 trigger + Claude with tool-use enforcing schema + validation layer + writes to a CRM/AMS (AMS360, Applied Epic, HubSpot for smaller shops). Week-to-month build depending on schema depth; expect 3–6 weeks of schema tuning per new document class. Not autonomous binding — a human still commits. Same skeleton fits wholesale distribution RFQs, personal-injury legal intake with medical records, freight brokerage quote packets, and commercial real estate loan submissions — anywhere humans re-key PDFs.

### 4. Inbound-form enrichment and routing agent
**Source:** [JBGoodwin REALTORS via Zapier](https://zapier.com/blog/jbgoodwin-realtors-automates-recruiting-with-zapier/) — 900+ agent Texas brokerage automating recruiting intake for ~300 hires/year.
**Mechanism:** Trigger is a candidate application arriving via form or email. Zapier's Email Parser extracts application fields; an AI step researches the candidate from public sources (prior brokerage, recent market activity), builds an enriched HubSpot contact with notes, writes a Zapier Tables row for pipeline analytics, and DMs a specific recruiter via Slack based on the candidate's market. Replaces the recruiter's data-entry-plus-prospect-research at the front of the funnel, previously ~25% of a recruiter's day.
**Why agentic:** The agent does open-ended enrichment — variable sources, judgment on what matters — not just field mapping, and the routing decision depends on the enriched profile.
**Generalizable core:** Inbound form/email → parse to schema + enrich from public web → structured CRM record + routed handoff to the human who owns the next step.
**Deployability:** Form or inbox trigger + Zapier/n8n/Make + LLM enrichment step (Claude, Perplexity search) + CRM write + Slack/Teams routing. Weekend-to-week build. This is a time-recovery pattern, not FTE replacement — value comes from the recruiter starting the first call already informed. Works identically for lead-form intake (services, real estate buyers), new-vendor onboarding, and event-signup triage.

### 5. Live-call co-pilot writing to CRM during the conversation
**Source:** [TTEC Digital / Compass Working Capital on Agentforce Contact Center](https://www.globenewswire.com/news-release/2026/07/23/3332068/0/en/TTEC-Digital-Deploys-First-Live-Salesforce-Customer-on-Agentforce-Contact-Center.html) — first live Salesforce customer on Agentforce Contact Center; nonprofit doing financial coaching; ~6,000 staff hours/year reclaimed. A new angle on the voice-agent pattern already in the log.
**Mechanism:** Trigger is a call connecting. The agent streams the live transcription, joins it against the client's full Salesforce record, and during the call it auto-populates CRM fields, creates follow-up tasks, schedules callbacks, and routes to the correct coach if the conversation shifts topic. Written to Salesforce. Replaces the coach's post-call data-entry ritual and the front-desk routing decision — the human stays on the call, the agent does the paperwork in parallel.
**Why agentic:** The co-pilot decides what to write, what tasks to create, and where to route the call, all while the human keeps talking to the customer. That's distinct from a passive transcript tool.
**Generalizable core:** Live conversation transcript stream → CRM record + policy rules → structured field writes + task creation, in-flight.
**Deployability:** Real-time transcription (Deepgram, AssemblyAI, Whisper streaming) + Claude with MCP to CRM + Twilio for the call leg, or Retell/Vapi with tool-use during the call. Week-to-month build. Replaces the "person taking notes while I talk" role — the associate or coordinator who used to sit in on calls. Distinct from prior voice-agent logs because the human remains the caller; the agent is a shoulder-surfing scribe with write privileges. HIPAA/PII audit logging is table stakes in finance and healthcare deployments.
