# 2026-11-21 — Agent Pattern Scan

## TL;DR
AT&T's process-first agent program is the most useful signal this run: they map a process against an industry reference framework before designing any agent, keep a small library of agents instead of thousands of task bots, and have them all call a single centrally managed business-logic layer. The other three patterns are smaller-scale variants of the same idea — event-triggered backfill with a verifier sub-agent, scheduled-poll plus one-click-approved form-fill-as-you, and structured document assembly from source-of-truth data.

## Patterns

### 1. Event-triggered frontline reassignment with a verifier sub-agent
**Source:** [Fountain launches Orchestra](https://venturebeat.com/orchestration/ai-agents-are-coming-to-help-hire-schedule-and-manage-frontline-workers-as-fountain-launches-orchestra) — Workforce platform's new agent builder, released Nov 17 2026 for frontline ops teams. Free for select existing customers, GA planned for early 2027.
**Mechanism:** A roster event (worker drops a shift) fires the agent. It reads the shift pattern, current staffing gap, overtime status, and contact preferences for eligible workers. It drafts and sends outreach through each worker's preferred channel, tracks responses, and books the backfill. A separate checker agent then evaluates whether the goal (shift covered) was fully, partially, or not met, and can issue up to three rerun recommendations before closing the task.
**Why agentic:** The primary agent reasons across several data sources and makes real outbound contact; the checker is an explicit second-agent gate on reruns, which is a workflow, not a display.
**Generalizable core:** State change in a system of record → agent assembles policy + preferences + eligibility → acts across channels → verifier scores the outcome and can force a retry.
**Deployability:** Mid-complexity on any workflow runtime (n8n, Make, Lindy, or Claude API + MCP tools wired to a scheduling DB and a messaging gateway). Week to month depending on how many channels are in scope and how strict the policy layer is. Replaces the ops person who manually texts around for coverage. The verifier sub-agent is the reusable piece — roughly a day of extra build and it keeps the primary agent honest without a human sitting over it.

### 2. Process-map-first, small-set-of-agents, shared business-logic layer
**Source:** [AT&T uses agentic AI to reinvent business processes](https://siliconangle.com/2026/11/14/att-uses-agentic-ai-to-reinvent-business-processes-from-the-ground-up/) and [AT&T has 500 agentic AI workflows running](https://saassentinel.com/news/at-and-t-has-500-agentic-ai-workflows-running-and-plans-to-triple-that-next-year) — AT&T, Nov 14 2026. ~500 workflows in production, 45B tokens/day, plan to triple next year. Concrete example: dedicated-internet provisioning time halved in buildings where fiber was already installed.
**Mechanism:** For a given process (e.g., "provision dedicated internet in an existing fiber building"), a new order lands in the order system. The agent reads the building's fiber inventory record, the customer's service profile, and the standard provisioning recipe. It writes the provisioning steps directly into mainframe and OSS systems rather than opening a ticket for a human to execute. Selection of which process to automate is itself a deliberate step — the Business Agent Foundry maps the process against an industry reference framework, identifies handoffs, legacy-system detours, and duplicated steps, and only then designs an agent to collapse them. All ~500 agents call a single centrally managed business-logic module rather than each re-encoding rules.
**Why agentic:** The agent writes directly into the mainframe system of record; it replaces the human who would otherwise execute the provisioning steps by hand. Oversight is audit-log review, not inline clicking-through.
**Generalizable core:** New record in system of record → agent reads inventory + customer profile + process recipe → executes writes into the legacy system → centrally managed rules layer resolves policy.
**Deployability:** Not a weekend build. The transferable piece for a small shop is the architecture rule: encode business rules once, in a module every agent calls, instead of letting each prompt re-state them. And start from the process map (handoffs, legacy-system detours, duplications), not from "where could AI help?" Replaces/augments the ticketed-work glue layer between legacy systems. Scale caveats: AT&T has dedicated platform teams, but the architecture decision scales down to two agents sharing a `rules.ts`.

### 3. Scheduled site scan with human-approved action-as-you
**Source:** [HiringNow on Product Hunt](https://www.producthunt.com/leaderboard/daily/2026/11/14) — Consumer AI job agent, Nov 14 2026 launch. Included here for the mechanism, not the vertical.
**Mechanism:** The agent polls a defined set of company career sites every few minutes using a headless browser. New postings are extracted and matched against the user's profile; matches surface in the user's queue with a one-click approve. On approval, the agent opens the employer's own application portal, fills every field from the stored profile, uploads the right resume variant, and submits as the user. State is tracked so the agent never double-submits for the same role.
**Why agentic:** The action is a real form submission against an external system that offers no API. The agent is the user's hand on the keyboard; the dashboard equivalent would be "here are jobs you could apply to" and leave the actual work to the human.
**Generalizable core:** Schedule-polled external source with no API → agent extracts new items → matches against stored profile → human one-click approves → agent completes the form as the user via browser automation.
**Deployability:** Weekend to week build using Playwright or Browserbase for submission, Claude for extract/match, plus a thin approve UI. Transfers to any vendor that requires portal submissions: insurance claim portals, bid/RFP portals, grant applications, licensing renewals, agency reporting systems. Caveats: some targets enforce anti-bot controls — either solve per-site or exclude. The one-click approval gate is what keeps this out of "runs a scraper that spams forms" territory.

### 4. Structured document assembly from source-of-truth data, human signs off
**Source:** [Anthropic customer stories (N26, Athena, Novo Nordisk referenced)](https://claude.com/customers) — Secondary coverage ([agenticaiarch](https://agenticaiarch.com/best-claude-agentic-ai-case-studies/), [thinkpeak](https://thinkpeak.ai/anthropic-claude-automation/)) reports that Novo Nordisk cut clinical study report drafting from ~10 weeks to minutes. Figures are from third-party summaries; verify against the Novo Nordisk page on claude.com/customers before quoting externally.
**Mechanism:** When a trial dataset is marked ready, the agent pulls statistical outputs, protocol documents, prior comparable study reports, and the current regulator's template. It assembles a full first draft already matching the regulator's section order, citation style, and data-presentation rules. A reviewer edits; the agent handles targeted revisions in place rather than regenerating from scratch.
**Why agentic:** The output is the deliverable. The agent writes the actual document the regulator receives, and the structural rules are enforced inside the agent, not applied by a human in a cleanup pass.
**Generalizable core:** Trigger says "input data is final" → agent pulls data + prior exemplars + template → produces the real deliverable document → human reviews and signs off instead of drafting.
**Deployability:** Week to month depending on how strict the output format is and how clean the source data is. Transfers to any document that is high-value, assembled from structured sources, and formatted to a rigid external standard: SOC 2 narratives, audit responses, insurance quotes, construction submittals, planning applications, grant reports. The pattern only pays off when the document is expensive to produce and the inputs are already structured — if the data has to be hand-collected first, the savings evaporate.
