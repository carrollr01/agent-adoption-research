# 2026-08-28 — Agent Pattern Scan

## TL;DR
Most interesting today: Vega's "Detection Skills" attaches the triage/investigation procedure directly to each SOC detection rule so the reasoning ships with the trigger — one large digital-commerce customer cut mean triage from 60 min to under 2 min. Also worth noting: a nightly outbound medication-adherence voice agent at a US mental-health clinic that writes back to the EHR over FHIR, and Notion's "task moves to Ready" trigger that spawns a Claude session grounded in the same workspace's docs. ## Patterns

### 1. Detection-attached triage playbook (SOC agent)
**Source:** [Vega Detection Skills (Cybersecurity Insiders coverage, Aug 2026)](https://www.cybersecurity-insiders.com/vega-introduces-detection-skills-the-new-open-standard-for-ai-reasoning-in-agentic-cyber-defense/) — new open standard launched at Black Hat USA 2026, built on Anthropic's Agent Skills format. Framework spec + one named production result at a large digital-commerce customer.
**Mechanism:** A SIEM detection rule ships bundled with a versioned "skill" that spells out the exact triage, investigation, and tuning procedure a senior SOC engineer would follow if the rule matched. On alert fire, the agent executes the attached skill: pulls context (host, identity, prior related alerts, network telemetry, ticket history), reasons through the analyst's decision tree, writes findings into an evidence workbook attached to the alert, and only pages a human when the outcome is ambiguous or high-severity. Replaces the tier-1 analyst's manual runbook lookup and initial evidence-gathering.
**Why agentic:** The agent chooses which tools/queries to run at each branch of the investigation based on what the previous step returned. Two identical alerts on different hosts run different investigative paths depending on what the environment reveals. Not a fixed playbook execution.
**Generalizable core:** Trigger rule with attached procedure → agent executes the procedure adaptively against live system state → writes a decision-ready artifact for a human → escalates only what's genuinely ambiguous. The novel structural move is that the reasoning-recipe lives with the rule, so both evolve together and you can version them as one thing.
**Deployability:** Requires a SIEM/detection platform that supports skill attachment (Vega natively; open-standard adoption pending elsewhere). Real prerequisite is having the runbook in the first place — the pattern converts implicit analyst knowledge into a versioned artifact. Complexity: month-scale for a first end-to-end deployment; scales down cheaply after skills exist. Role augmented: SOC tier-1 analyst; the customer figure quoted (60 min → <2 min) is at enterprise volume, but the pattern of "attach the runbook to the trigger" transfers to any operations desk with a runbook culture (NOC, IT service desk, on-call ops).

### 2. Nightly outbound medication-adherence voice agent (mental health clinic)
**Source:** [Agentic AI Workflows: Complete Production Guide 2026 (Bitontree, referencing a named USA mental-health clinic deployment)](https://www.bitontree.com/agentic-ai-workflows-guide) — 200+ patient calls per night, 32% adherence lift measured, zero compliance incidents cited in production.
**Mechanism:** Cron fires per-patient after clinic hours. Agent dials via Twilio, confirms identity, then runs a branching script whose next node depends on how the patient answers (confirmation, missed dose, side effects, distress/self-harm language). Deepgram handles ASR, ElevenLabs handles synthesis, LangGraph orchestrates the 14-node state machine with retries and state persisted in Postgres. On any of a defined set of clinical safety triggers (suicidal ideation, severe adverse reaction), it hands off live to an on-call nurse. Otherwise it logs adherence data back to the EHR via FHIR and closes the call. Replaces the nurse-call-back task and the retrospective adherence-audit report.
**Why agentic:** The path through the call graph is decided at each turn based on the patient's response, not read from a static script. The nurse-escalation decision is triggered by content, not by a menu selection.
**Generalizable core:** Scheduled outbound contact → branching conversation over real-time speech → state written back to the system of record → safety-condition escalation to a human specialist. Any recurring outbound-check workflow with a compliance floor fits (post-op check-ins, home-health visits, service verification calls, collections with hardship gates).
**Deployability:** Voice stack (Twilio + Deepgram + ElevenLabs) plus LangGraph + Postgres + LangSmith for tracing; a state-of-record integration (here FHIR). Weekend build for a proof of concept, month-plus for production with the safety-review, PHI, and human-escalation-routing hardened. Role replaced/augmented: adherence coordinator and nurse phone-time. Scale caveat: clinical/regulated deployment demands medical-director sign-off on the escalation triggers — not appropriate to ship without a domain expert authoring the safety rules.

### 3. Task-state trigger → in-workspace agent session (Notion + Claude Managed Agents)
**Source:** [Notion launches Claude-powered AI agents (Crypto Briefing coverage, 2026)](https://cryptobriefing.com/notion-claude-ai-agents-productivity/) — 1M user-created agents by May 2026, ~2,800 running internally at Notion itself. General availability, not an experiment.
**Mechanism:** When a task in a Notion database transitions to a "ready to start" status, that state change invokes a Claude Managed Agents session scoped to the same workspace. The agent picks up context from the connected pages the task links to — PRDs, API docs, design-system pages, prior related tickets — then produces the deliverable (draft doc, code change, data analysis, follow-up task list) and writes it back into the workspace, including assigning downstream tasks to the right teammate. A human still moves the task to "done" once they've reviewed.
**Why agentic:** The agent decides what context to pull from a linked graph of pages and what shape of output the task actually requires (a doc? a code diff? a spreadsheet of next actions?). It's not a pre-templated fill-in-the-blank; the output type varies with the task.
**Generalizable core:** Record status change in a workspace/ticketing tool → agent session hydrated from the same workspace's connected context → deliverable written back to the same workspace → downstream tasks routed to owners. The key mechanism is that the *system of record and the context source are the same surface* — no glue code moving prompts between apps. Applies to any workspace-native SaaS (Linear, Asana, Airtable, ClickUp) where the context and the trigger live in the same place. Note: overlaps in trigger class with the milestone-invoicing pattern logged 2026-05-28, but the action (produce arbitrary knowledge/code artifacts and route follow-ups) and the context source (same-workspace graph) are materially different — worth logging as a distinct pattern.
**Deployability:** Requires a workspace tool with agent-triggering hooks (Notion's own agents feature; equivalent hooks exist in Linear/Asana via Zapier/n8n/Make plus the Claude API). Weekend build for a scoped first agent inside a workspace you already run on; month-scale to build a fleet. Role replaced/augmented: junior program managers, coordinators, and the "someone go pull the requirements and write the first draft" role. No dedicated ML headcount needed — the platform handles the model side.

### 4. Composite cross-app conditional trigger (multi-signal escalation)
**Source:** [Gumloop — Trigger Gumloop Agents with any app (2026)](https://www.gumloop.com/blog/trigger-gumloop-agents-with-any-app) — pattern surfaced as a first-class trigger primitive on the platform; Gusto's partnership-review agent (30–45 min prep → <5 min, +31% win rate, +44% deal size) is a shipping customer using the same conditional-trigger substrate.
**Mechanism:** The trigger itself is a conjunction of signals across separate SaaS systems, not a single event. Example the vendor documents: fire only when *(open Zendesk ticket exists) AND (Stripe shows an overdue invoice > $5,000) AND (renewal is within 60 days)*. Only when all three hold does the agent run — it then enriches with the account's history (usage, past support pattern, prior escalations), drafts a Slack message to the account manager framed for the situation, and stops. Replaces the CS-ops query that used to reveal this account only after someone thought to ask.
**Why agentic:** The high-value work is upstream of the LLM: the *right accounts* only reach the agent because the trigger is a compound condition across systems. Once fired, the agent decides how to frame the escalation based on the specific signal mix (a churn-risk framing reads differently from a delinquent-payment framing). Not a fixed alert.
**Generalizable core:** Multi-signal conjunction across independent systems → agent enriches with account history → drafts a targeted human-shaped notification into the right channel. Any "this only matters when several things are true at once" situation qualifies: at-risk-renewal alerts, hiring bar-raiser triggers, fraud-review flags, upsell-ready flags, safety-stock alerts qualified by seasonality + supplier lead-time + open orders.
**Deployability:** Composite triggers are shipping on Gumloop, n8n (via Wait/If nodes), Zapier (paid Filter tiers), Make. The build effort is not the LLM call — it's mapping the right signal sources and thresholding the conjunction. Weekend build once you have API access to the source systems. Role replaced/augmented: the CS-ops or RevOps analyst who runs weekly cross-system queries. No scale prerequisites — the pattern works at any volume, and is arguably *more* useful for small orgs that can't afford a full-time analyst to run these queries manually.
