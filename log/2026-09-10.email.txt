# 2026-09-10 — Agent Pattern Scan

## TL;DR
Five concrete patterns surfaced today, largely from operators publishing production agent designs rather than vendor pitches. Standouts: a "meta-triage" pattern where a scheduled agent picks which items deserve another agent's cycles, and an @-mention-as-trigger pattern where an on-call engineer summons an incident-triage agent into an existing Slack thread instead of building a dashboard for it. Note: the last log is 2026-05-28, so this scan covers a longer window than usual — patterns below are all from the past ~2 weeks.

## Patterns

### 1. Mention-triggered incident first-responder in a shared chat thread
**Source:** https://claude.com/blog/ai-ci-cd-on-call + Carvana customer story, Sept 4 (https://claude.com/customers). Anthropic's internal on-call use case plus Carvana turning Slack alerts into production fixes. Claude Tag GA'd for Enterprise/Team on June 23; existing Claude-in-Slack workspaces auto-migrated Aug 3.
**Mechanism:** An engineer pages an incident channel, then @mentions Claude in the thread → agent pulls recent commits from GitHub, queries Datadog for error rates and latency deltas, checks PagerDuty for related open incidents, and returns a structured summary in-thread with a root-cause candidate, evidence links, and the responsible engineer already @-tagged. Read-only tools only; no writes to prod. Replaces the on-call's first 15–20 minutes of "what changed and where's the smoke."
**Why agentic:** The trigger is a human summoning it inside their existing conversation, not a webhook or a report render. The agent picks its own tool sequence based on what the thread says the incident is, and the output is evidence + a routing decision, not a chart.
**Generalizable core:** Human mentions the agent inside an existing work thread → agent reads the thread's context + queries the relevant systems-of-record → posts a structured evidence bundle and a suggested next action back into the same thread.
**Deployability:** Claude Tag + Arcade (auth broker) + read-only GitHub/Datadog/PagerDuty MCP tools, or the same shape in n8n/Zapier fronted by a Slack webhook. Weekend-to-week build depending on how many source systems. Replaces or augments the on-call engineer's opening triage; works anywhere there's a "we got paged, someone start looking" moment (site outages, refund disputes, safety alerts, restaurant POS failures, HVAC dispatch anomalies). No enterprise data volume required.

### 2. Scheduled meta-triage that routes work to another autonomous agent
**Source:** PR Sous Chef, Sept 1 (https://github.github.com/gh-aw/blog/2026-09-01-agent-of-the-day/) and Issue Monster, Sept 3 (https://github.github.com/gh-aw/blog/2026-09-03-agent-of-the-day/) — GitHub's own gh-aw fleet, in production against its own repo.
**Mechanism:** PR Sous Chef runs on a 15-minute cron (plus an on-demand /souschef slash command). It fetches every open non-draft PR, reads PR state + CI + comments, and — only when a PR has "genuinely gone quiet" — posts a targeted nudge to the Copilot coding agent to move it forward. Most cycles are read-only recon with no output at all. Issue Monster does the analogous job on the issue queue every ~40 minutes: scores open issues, picks a small batch of qualifying candidates, then either assign_to_agent (hands to Copilot), add_comment ("Issue Monster selected this for Copilot"), or noop. Replaces a human's "which of my 40 open items is worth spending an autonomous agent's tokens on."
**Why agentic:** The interesting decision isn't "do the work" — Copilot does that. It's the *selection* decision, made continuously against changing state (drift, staleness, dependencies), which is exactly what a dashboard can't do because the answer only matters when something changes.
**Generalizable core:** Scheduled scan of a work queue → score/qualify items against a threshold → dispatch the qualifying subset to a downstream doer (agent or human) with the reason attached; otherwise stay silent.
**Deployability:** gh-aw (free), n8n cron + LLM node + tool call, or Claude Managed Agents on a schedule. Week build. Replaces the lead/manager's "who should pick this up" call — good fit anywhere a shop has a growing queue (support tickets, sales leads, contract redlines, moderation flags, maintenance requests) and a downstream worker (human or agent) whose time isn't free.

### 3. Scheduled auto-cleanup agent that mutates the shared codebase
**Source:** Dead Code Removal Agent, Sept 7 (https://github.github.com/gh-aw/blog/2026-09-07-agent-of-the-day/) — GitHub's gh-aw repo.
**Mechanism:** Daily cron → runs Go's deadcode static analyzer over ./cmd/... and ./internal/tools/... → opens a PR that removes the unreachable functions it found *plus* any test code that only existed to exercise those functions. Self-caps at ~5 functions per PR so reviews stay small. When the analyzer output is ambiguous, the agent explicitly declines and logs why rather than force a risky delete. PR body includes a verification checklist.
**Why agentic:** The output isn't "here's a report of dead code" — it's a mergeable diff that a human can accept or reject. The agent negotiates with its own uncertainty: it defers when it isn't sure, which is exactly the judgment call the dashboard version pushes back onto the reader.
**Generalizable core:** Scheduled deterministic analyzer runs → agent turns the analyzer's findings into a bounded, reversible change proposal in the source-of-truth system → human approves or rejects. Refuses to act when confidence is low.
**Deployability:** Any static analyzer + Claude/GPT + repo write access; gh-aw templates the pattern for GitHub. Weekend build. Replaces quarterly "cleanup sprints" or the low-priority backlog that never gets touched. Same shape works far beyond code: analyzer-flagged duplicate CRM records, stale product SKUs, unused permissions, orphaned files in Drive, expired vendor contracts. The generalization is "we already have a detector; we've never had time to act on its findings."

### 4. Silent-until-drift dependency canary
**Source:** CLI Version Checker, Sept 8 (https://github.github.com/gh-aw/blog/2026-09-08-agent-of-the-day/) — GitHub's gh-aw repo, tracking its own toolchain.
**Mechanism:** Daily cron → parallel version lookups across 8 named CLIs (Claude Code, GitHub Copilot CLI, OpenAI Codex, GitHub MCP Server, Playwright CLI, MCP Gateway, Pi, threat-detect) and 8 named Docker images (actionlint, syft, grype, grant, zizmor, poutine, runner-guard, yamllint) using npm view, GitHub Releases API, and Docker digest checks. On a hit: pulls release notes, converts PR references to full URLs, categorizes changes into Breaking / Features / Fixes / Security / Performance, runs make recompile, and opens a PR with the categorized changelog and the rebuilt artifacts. On a miss: exits silently. No email, no ping, no dashboard tile.
**Why agentic:** The value is "you hear from it only when it needs you." A dependency dashboard would show the same data every day and get ignored; the agent inverts the attention economics by only surfacing when there's a decision to make, and packaging the decision (categorized diff + rebuilt artifact) so the human's job is just "approve or don't."
**Generalizable core:** Scheduled poll of a curated watchlist of external state → do nothing when state hasn't changed → when it has, package the change as a decision-ready artifact (with the routine downstream work already done) and route to a human.
**Deployability:** gh-aw or n8n scheduled trigger + HTTP nodes + LLM node for the changelog categorization + PR/ticket write. Weekend build. Replaces the "someone should check on X monthly" role. Skeleton reuses cleanly for competitor price monitoring, regulation/statute updates, franchise-agreement addendums, insurance carrier rate cards, permit fee tables, vendor terms-of-service diffs.

### 5. "Least-recently-audited rows first" periodic auditor
**Source:** ESLint Refiner agent, Aug 28 (https://github.github.com/gh-aw/blog/2026-08-28-agent-of-the-day/) — GitHub's gh-aw repo, auditing its own custom lint rules.
**Mechanism:** Daily cron → picks the two custom ESLint rules that have been least-scrutinized in prior runs → reads each rule's definition and searches the codebase for real call sites → validates that the rule's error messages still describe reality and that fixes previously applied to one rule have propagated to sibling rules → files a GitHub issue only when it finds a grounded bug, and posts a discussion summarizing everything checked (including the clean results and the queue of what's still pending).
**Why agentic:** The rotation logic is the interesting part. A human doing this by hand always audits the newest or loudest thing; the agent deliberately picks what everyone has stopped looking at, which is exactly where quiet bugs accumulate. And the "post a summary of what I looked at even if I found nothing" step keeps the humans calibrated on whether the agent is doing real work.
**Generalizable core:** Scheduled review of a large slow-moving corpus → pick the N rows with the oldest last-reviewed timestamp → deeply verify them against ground truth → surface findings but also post the null-result audit trail. Effectively converts a huge one-time audit into a rolling steady-state one.
**Deployability:** Simple: cron + Claude with tool access to the corpus + issue tracker write. Weekend build. Fits anywhere you have a compliance/policy/config surface too big to fully re-audit but too consequential to leave alone: KB articles, insurance policy templates, standard operating procedures, contract clause libraries, security controls, data retention tags, marketing claims across a large product catalog.
