# 2026-06-15 — Agent Pattern Scan

## TL;DR
Four concrete patterns surfaced today: event-driven agents that spawn on any business event (Adaptive's Triggered Agents), Microsoft's Expense Agent that builds and submits expense reports autonomously below configured thresholds, a Virtual Engagement Officer that cultivates lapsed donors over six-month arcs, and autonomous SEO ranking-recovery agents that monitor rank metrics and rewrite content when pages drop. The most novel mechanism is the long-running cultivation agent: it doesn't react to a trigger, it operates a multi-month relationship.

## Patterns

### 1. Event-spawned reasoning agents (any tool event)
**Source:** [Triggered Agents by Adaptive on Product Hunt](https://www.producthunt.com/products/triggered-agents-by-adaptive) — Adaptive shipped event-driven agents that spawn automatically when something happens in any connected SaaS tool. Launched June 2026.
**Mechanism:** A business event fires in a connected tool (new lead in HubSpot, new Stripe charge, new Linear ticket, new row in Airtable, new Slack mention). The event spawns a Triggered Agent that reads the event context plus surrounding history from connected accounts (CRM, calendar, email, docs), reasons about what should happen, drafts the output (email, purchase order, briefing, spreadsheet update, Slack message), and either acts directly or routes an approval step to a human. The agent runs the moment the event happens rather than when an operator remembers to check.
**Why agentic:** Each event spawns a fresh reasoning process that picks its own tools and writes back to whichever system the situation requires, instead of running a static if-this-then-that path. The same trigger can produce a refund, a draft email, or an internal briefing depending on what the agent infers from context.
**Generalizable core:** Event in any system of record → agent reads event plus enrichment context → reasons over playbook → drafts action, optionally routes for approval → writes to the system the situation requires.
**Deployability:** Adaptive hosts the platform. The equivalent custom build is a webhook listener (Cloudflare Worker, n8n, or Make) feeding Claude with MCP connectors to the relevant SaaS tools, with one-step human approval via Slack. Weekend build for a single event; week build for a multi-trigger control panel. Replaces the operator who currently watches a dashboard for the same events and manually drafts the follow-up.

### 2. Expense Agent that submits reports below a policy threshold
**Source:** [Expense Agent in Dynamics 365 Business Central](https://www.microsoft.com/en-us/dynamics-365/blog/it-professional/2026/04/27/expense-agent-dynamics-365-business-central/) — Microsoft shipped Expense Agent into Business Central in April 2026 as a configurable autonomous agent for SMB finance teams.
**Mechanism:** Receipts arrive (mobile upload, forwarded email, OCR scan). The agent extracts vendor, amount, date, and tax, categorizes the line against the chart of accounts, groups receipts into an Expense Report scoped to the period and employee, validates against the org's policy rules (dollar caps, category restrictions, missing-receipt limits), and either auto-submits the report for payment or escalates to a human when a rule is violated or a configured trust threshold is exceeded. Autonomy level is a per-org tunable: small expenses can clear without review, larger ones can be routed to a manager.
**Why agentic:** The agent decides whether each report is in policy and either commits the transaction or hands off to a human. It is not a passive form-filler — the autonomy threshold is the whole point.
**Generalizable core:** Documents arrive on a recurring channel → agent extracts and categorizes → policy check against configured rules and thresholds → auto-execute below threshold, escalate with a draft above threshold.
**Deployability:** Microsoft hosts the version inside Business Central. Same pattern can be built on Claude with MCP for QuickBooks/Xero, an OCR step (Claude vision or Mindee/Veryfi), and a simple rules table for the policy check. Weekend build for a single category, week build for a tunable policy engine. Replaces the bookkeeper who manually keys receipts and chases approvals, and the manager who rubber-stamps low-dollar items.

### 3. Multi-month autonomous donor cultivation agent
**Source:** [Spring Giving Days: Autonomous Fundraising 2026 Results](https://www.version2.ai/post/spring-giving-days-autonomous-fundraising-2026-results) — Version 2 AI reported a Virtual Engagement Officer (VEO) outcome where 755 lapsed donors were renewed and a higher-ed donor was cultivated one-to-one over six months before giving.
**Mechanism:** A donor record gets added to a VEO portfolio in the CRM (typical entry signals: lapsed beyond a threshold, attended an event but never gave, gave once at a small amount). The agent owns the relationship from there. It pulls past gift history, prior communications, program affinities, and any stewardship notes, then sends sequenced, personalized stewardship messages over weeks and months — thank-yous, impact stories, soft asks. It reads replies, adjusts cadence, escalates to a human officer when the donor signals readiness, and times an explicit ask to a moment like Giving Day. The output is a logged interaction history in the CRM plus a gift when the relationship matures.
**Why agentic:** The unit of work is a relationship, not a message. The agent decides what to send, when, and whether to escalate based on the donor's response pattern across months — there is no scheduled blast or single trigger.
**Generalizable core:** Contact enters a long-cultivation queue → agent owns ongoing relationship state → reads each response, decides next touch and timing → writes interactions back to CRM → hands off to a human when readiness signals appear.
**Deployability:** Verison 2 sells the hosted product. The custom equivalent is a Claude agent with persistent memory in a vector store keyed to the contact ID, scheduled wake-ups via cron or Temporal, and writes back into HubSpot/Salesforce/Bloomerang. Month-scale build to do well — the hard part is the memory and the tone calibration, not the messaging. Replaces a junior development officer's stewardship caseload. Translates outside fundraising to any context with a long sales cycle: lapsed dental patients, expired insurance leads, dormant SaaS trials, alumni outreach.

### 4. Threshold-triggered SEO ranking recovery agent
**Source:** [Autonomous AI Agents for SEO: How They Work](https://blog.revnu.app/blog/autonomous-ai-agents-for-seo-how-they-work) — Revnu and similar autonomous SEO platforms (Search Atlas, Frase) run continuous rank monitoring and trigger remediation when pages drop.
**Mechanism:** A monitoring layer polls Google Search Console and a rank tracker per URL. When a page's position drops past a configured threshold, an agent assembles context — the page content, the SERP snapshot of who now ranks above it, recent algorithm-update chatter, internal links, and the page's historical performance — then reasons about the likely cause (stale content, lost backlinks, intent mismatch, technical issue). It rewrites or restructures the page, regenerates schema, sometimes commissions supporting internal links, and pushes the change live via the CMS API (WordPress, Webflow, Sanity, Contentful). It keeps watching and re-iterates if rank doesn't recover.
**Why agentic:** The agent doesn't run on a content calendar. It runs in response to a measured external state change, decides on a recovery strategy based on diagnosis, and commits real changes to the live site. The loop closes when rank recovers, not when a checklist completes.
**Generalizable core:** External metric crosses a threshold → agent diagnoses cause from multiple data sources → executes a multi-step remediation → writes changes back to the production system → continues monitoring until the metric recovers.
**Deployability:** Revnu/Search Atlas are SaaS. Custom build is a Search Console + DataForSEO poll, Claude with web fetch and CMS MCP, queued via a scheduler. Week build for a single-site version, month build for an agency tool covering many sites. Replaces the monthly SEO retainer that produces a report and a punch list. The same threshold-triggered remediation skeleton applies to email deliverability (sender reputation drop → warming sequence), ad accounts (CPA crosses ceiling → creative refresh), or app store rankings.
