## Patterns

### 1. Inbound "buying agent" on the pricing page
**Source:** [How Anthropic's sales team rebuilt inbound with Claude Managed Agents](https://claude.com/resources/articles/how-anthropics-sales-team-rebuilt-inbound-with-claude-managed-agents) + secondary coverage ([Anthropic's Inbound Sales Agent: 2x Opportunities, $0.08 an Hour](https://imisofts.com/blog/anthropic-inbound-sales-agent/), [BigGo summary](https://finance.biggo.com/news/9b77ad17-5dbc-416b-8ad3-17aec63ee752)) — Anthropic's own sales dev team, running tens of thousands of inbound inquiries per month; agent handles thousands of conversations per day.
**Mechanism:** Visitor opens chat on the pricing page → agent (prompt + tool handful + Claude on Managed Agents) reads product docs, pricing rules, and security FAQ; asks about team size and use case → answers questions, suggests a plan; if deal is small, routes directly to self-serve checkout; if deal is above a threshold (team size, complexity, enterprise security asks) the agent writes an opportunity in the CRM, attaches the full transcript with its own qualification notes, and hands to a human AE. Replaces the SDR intake call and the "schedule a 15-minute discovery" email thread.
**Why agentic:** It's not a chatbot answering FAQs. The agent decides when a conversation is qualified-for-self-serve vs. qualified-for-AE, writes to the CRM, and completes checkout with real pricing. Decisions and tool calls land in two different downstream systems depending on what it concludes.
**Generalizable core:** High-intent inbound signal (pricing page, pricing calculator, demo request) → agent assembles product + policy context → either completes a bounded transaction or escalates to a human with a transcript-plus-notes package. Works for any funnel where there's a self-serve tier plus an assisted/enterprise tier and the triage happens on a form today.
**Deployability:** Claude Managed Agents handles the loop, memory and hosting ($0.08/session-hour + tokens); for a non-Managed-Agents stack, Vercel AI SDK or Mastra on a Next.js site with a thin tool layer over Stripe (checkout) + HubSpot/Salesforce (opportunity creation) + a vector store of pricing/security docs. Weekend prototype; two to three weeks to production with guardrails on what plans the agent can quote, enterprise-security questions it can answer, and spend/discount ceilings. Replaces the first-tier SDR qualification task; augments AEs by handing them a pre-qualified transcript.

### 2. Role-decomposed agent fleet with shared memory + scoped credentials
**Source:** [AI sales agents: inside an Anthropic rep's six Claude agents](https://lamadre.ai/insights/anthropic-sales-agent-fleet-shared-memory-scoped-credentials) and [One Anthropic Rep Runs Six Claude Agents (Banyan)](https://www.banyanoutcomes.com/attention/anthropic-japan-bdr-six-claude-agents/) — Shahboz Ibragimov, Anthropic BDR in Japan; vendor-reported ~60 hours/month saved.
**Mechanism:** One role is split into five single-purpose agents (lead routing, qualification, Salesforce update + first-touch email, inbox reply drafter, meeting summarizer) plus a sixth "coordinator" agent whose job is to update the other five's system prompts and the shared knowledge store. Each sub-agent has its own trigger (new MQL in Salesforce, new inbound email, calendar event ends, etc.) and reads from a shared Managed-Agents memory store so prior-touch context is available to every agent. Credential vaults give each agent only the API scopes it needs — the agent never sees the raw key, and access is revoked in one step without touching the others. Judgment-heavy agents run on Opus; rule-following ones run on Sonnet. A human reviews every outbound customer message.
**Why agentic:** Each agent is reactive to its own event and operates on data the others wrote; the coordinator agent literally edits the others. This is one role's workflow turned into a small running ecosystem rather than one monolithic "sales agent."
**Generalizable core:** Role → decomposed into narrow agents, each with its own event trigger → shared memory as the connective tissue → coordinator agent tunes the fleet. Pattern applies anywhere one person does a cluster of similar sub-tasks around shared context (recruiting, CS, PM, ops, bookkeeping).
**Deployability:** Claude Managed Agents gives this out of the box (memory scoping, scheduled agents, credential vaults). To build the same on a different stack: n8n or Trigger.dev for event handlers, a Postgres/pgvector store as the shared memory, per-agent service accounts for credentials. ~1 week for a two-agent version; weeks-to-a-month to add the coordinator pattern. Replaces/augments a role; useful for solo operators and small teams that can't justify a full headcount per sub-task.

### 3. Threshold-triggered facilities work-order drafter
**Source:** [OfficeSpace expands AI Canvas with one agent for the entire workplace](https://www.globenewswire.com/news-release/2026/11/17/3404794/0/en/officespace-extends-agentic-ai-leadership-expanding-ai-canvas-with-one-agent-for-the-entire-workplace.html) — OfficeSpace Software, launched Nov 17 2026 in beta to Plus-tier clients; Facilities Agent is coming soon.
**Mechanism:** Facilities ticketing system is the event stream. Trigger fires when repeat work orders accumulate on the same physical asset above a threshold (e.g., third ticket on the same HVAC unit in 30 days) or when an asset nears warranty expiry / end-of-life in the asset register. Agent reads the asset's full ticket history, warranty and vendor data, then drafts a work order with the recommended action (replace vs. repair, vendor to call, parts needed) and pings the facilities team to approve. Replaces the facilities manager's weekly "pattern-spotting" review of the ticket queue.
**Why agentic:** The trigger is a derived condition over a stream of records, not a single event; the agent reads history, makes a replace-vs-repair recommendation, and writes a draft back into the operational system. Not a dashboard — the human doesn't have to go looking.
**Generalizable core:** Threshold crossed in an event log scoped to a specific entity → agent assembles entity history → drafts remediation action → human approves. Direct variants: equipment failure clusters in field service; bug clusters on the same code module; account health warning on repeat support tickets from one customer; inventory SKU hitting its N-th stockout in a quarter.
**Deployability:** The OfficeSpace version is bundled, but the pattern is cheap to rebuild: scheduled job (Cloud Run / Lambda / n8n cron) hitting the ticket system's API, a rolling window counter, and an LLM step that produces the draft action. Weekend build for one entity type. Replaces the "pattern-noticer" part of any ops role; augments the person who still has to approve.

### 4. Continuous reconciliation close ("rolling close") agent
**Source:** [AI Agents That Close Your Books While You Sleep — Enterprise DNA](https://enterprisedna.co/resources/insights/accounting-ai-agents-workflow-automation/), [Month-End Close Automation with AI — DeepLedger](https://deepledger.ai/blog/month-end-close-automation-ai), [Puzzle.io: AI Agents for Accounting](https://puzzle.io/blog/accounting-agent-ai-automation) — pattern recurring across accounting-tool vendors through 2026; some vendors claim 70–80% cut in month-end reconciliation workload (vendor-reported).
**Mechanism:** Every new ledger entry (bank feed, card feed, Stripe payout, payroll run, AP invoice posted) is the trigger, not the calendar. Agent reads the entry, pulls matching candidates from GL and documents (invoices, contracts, receipts), applies classification/matching rules, and auto-reconciles the obvious ones. Anything it can't resolve goes to an exceptions queue with a drafted journal entry and the agent's reasoning attached. At period close, humans review only the exception tail instead of the entire ledger. Nothing posts without sign-off.
**Why agentic:** The shift is from a monthly batch task (humans grinding through reconciliations in week 1) to a continuous process (agent handling 80%+ throughout the month, humans adjudicating the residual). The agent decides which transactions are machine-resolvable and which need a person — that classification is the agentic part.
**Generalizable core:** Event stream of records → agent classifies each as auto-resolvable or needs-human → auto-resolves the first bucket, drafts + queues the second → human reviews only the queue at period end. Not accounting-specific: same pattern works for expense policy review (every submitted expense), compliance audits (every new access-control change), content moderation triage, and QA bug triage.
**Deployability:** QuickBooks/Xero + Stripe + Gusto feeds into an orchestrator (Zapier Agents, n8n, or custom Next.js on Claude API), with the matching logic in a tool layer and the LLM only in the classify-and-draft step. Week-ish build for a single ledger; months to harden to audit-grade. Replaces the junior-bookkeeper reconciliation task; augments the controller/CPA, who now spends their time on the exception queue rather than the full month.
