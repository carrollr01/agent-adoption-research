# 2026-06-26 — Agent Pattern Scan

## TL;DR
Four mechanism-level patterns surfaced in the last week's customer stories and YC W26 launches: a manufacturer RFQ-to-quote agent that checkpoints across weeks of human approvals, an ambient multi-agent literature monitor for rare-disease diagnosis, Anthropic's own Claude Tag rolling out in Slack as an ambient channel teammate (June 23), and a two-pass live-plus-offline-review architecture in production at a customer-support deployment. The standout is the two-pass architecture — most "support agent" pitches stop at the live conversation; running a separate reflective scoring pass after the conversation ends is a quality lever that's underused in SMB deployments and easy to copy.

## Patterns

### 1. Long-horizon RFQ-to-quote agent with multi-week checkpointing
**Source:** [Korso, YC W26 launch](https://www.ycombinator.com/launches/QKn-korso-ai-agents-for-manufacturing) — AI agents for manufacturing back-office, plug into existing ERP and CRM.
**Mechanism:** RFQ arrives via email or customer portal → agent reads pricing history, current cost data, and customer record from a mapped context layer over ERP/CRM/email/documents → drafts a quote and routes it for approval → tracks the quote across days or weeks of back-and-forth, chasing delayed responses, notifying the customer, and escalating to a human only when judgment is needed → writes back to ERP/CRM with full audit trail. Long-running orchestration with checkpointing so the workflow survives restarts and never loses progress on a multi-week deal.
**Why agentic:** The agent owns the workflow across weeks, not a single inference. Dry-run validation and secondary review gate critical writes, and the agent decides when to chase, when to wait, and when to escalate.
**Generalizable core:** Inbound request → context assembly across systems → draft of a downstream artifact → approval gate → durable multi-day chase loop with state checkpointed between human touches.
**Deployability:** Stack equivalent: Claude API + MCP connectors to ERP/CRM/email + a durable-execution layer (Temporal, Inngest, or Vercel eve as of June 17) for the multi-week state machine + per-tool dry-run wrappers. Month-plus build because the long-horizon orchestration and approval routing are where the work is — the agent itself is a small fraction. Replaces or augments a sales engineer / quote desk role.

### 2. Ambient multi-agent monitor over specialized sources
**Source:** [Garvan Institute customer story, Anthropic](https://claude.com/customers/garvan-institute-qa) — Australian biomedical research institute using Claude for rare-disease genetic diagnosis.
**Mechanism:** Patient case is registered → a team of specialized agents is spun up against the case, each scoped to a different source (one watches population genetic databases, another scans clinical registries, another monitors newly published literature) → agents run continuously, 24 hours a day, re-querying their sources → when an agent finds something potentially relevant to the case it pushes an update to the human curator → curator decides whether to act. The case stays open and being watched indefinitely; new evidence can arrive months after the original workup.
**Why agentic:** Persistent, ambient, multi-source. A literature search tool answers once; this fleet keeps watching every source on every open case and proactively surfaces what changes. The human shifts from researcher to curator of agent output.
**Generalizable core:** Open case / open question → fleet of source-specialized agents poll on schedule → flag-on-find pushes to human inbox → case stays under watch until closed.
**Deployability:** Claude API + per-source MCP tool (one connector per data source you want watched) + a scheduler + a notification surface (Slack / email / case-management UI). Week build for a working version against 3–5 sources. Useful caveat: only worth the build when (a) sources update on their own timetable and (b) the cost of missing a new finding is high. Scales down well — small business equivalents exist (a regulator changes a rule, a competitor posts a price, a key supplier updates a spec), but the value depends on whether the watched sources actually change.

### 3. Ambient agent embedded in a shared comms channel
**Source:** [Anthropic introduces Claude Tag, June 23 2026](https://www.anthropic.com/news/introducing-claude-tag) — persistent Claude teammate in Slack channels, beta for Team and Enterprise.
**Mechanism:** Admin adds Claude to a channel and connects it to the team's tools and data sources → anyone in the channel can @mention to delegate a task and walk away → Claude does the work asynchronously and posts back when done → in ambient mode, with no mention, Claude watches channel traffic and proactively surfaces relevant context, follows up on stalled threads, or pings the right person when a thread is going nowhere. Memory persists across the whole channel, not per user. Anthropic reports 65% of its own product team's code is written by an internal version of this pattern.
**Why agentic:** The proactive ambient behavior is the dividing line. A chatbot answers when asked. This watches, picks up tasks no one assigned, and writes back into the channel.
**Generalizable core:** Shared comms channel + connected tools + agent that monitors traffic ambiently → answers on @mention, surfaces context on detected signal, follows up on stalled work.
**Deployability:** For a custom build: Slack Bolt app + Anthropic SDK + MCP-connected tools + persistent memory store (Postgres or a vector DB depending on what you're matching) + an ambient-mode loop that polls channel history on a cadence and decides whether to speak. Week to two-week build for a narrow team. Real risk is the ambient mode being annoying — needs a strong silence-by-default policy and a clear opt-out. Replaces / augments the "shared Slack assistant" role and the team-lead "what's status on X" pinging.

### 4. Live agent + offline reflective scoring pass
**Source:** [Delight.ai customer story, Anthropic](https://claude.com/customers/delightai-qa) — AI customer support concierge running on Sendbird's 7B-monthly-conversation infrastructure, primary model Claude.
**Mechanism:** Customer message arrives → live agent handles the conversation end-to-end across multiple intertwined issues in one session (Delight's example: change plan, refund last month's overcharge, update payment method, all in one chat) with prompt-injection safeguards in-line → conversation ends → a separate offline pass runs over the transcript, classifying topics, scoring sentiment, and checking for hallucinations → the offline pass output feeds dashboards, regression test sets, and the queue of conversations a human reviews.
**Why agentic:** The live half is obviously agentic (multi-step tool calls into billing, plan, and payment systems). The interesting half is the second pass — running a scoring agent on every transcript turns "did this go well?" from a sampled human QA process into a structured signal on every conversation. Internal tooling for debugging and regression testing is itself built with Claude Code, and time-to-fix-and-deploy dropped from a week to one or two days.
**Generalizable core:** Live agent acts → offline reflective agent reads the transcript and scores it on fixed dimensions → low scores feed a human review queue or a regression test set.
**Deployability:** The two-pass structure adds maybe a day of build on top of any existing agent — it's a cron-style or queue-triggered Claude call against the stored transcript with a structured-output schema for the dimensions you care about. Cost is small per conversation. Useful anywhere an agent is doing customer-facing work and the cost of a silent bad interaction is high. Replaces a sampled human QA process; scales with conversation volume rather than with reviewer headcount.
