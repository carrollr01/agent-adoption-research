# 2026-08-06 — Agent Pattern Scan

## TL;DR
Six patterns today across distinct trigger shapes. The most interesting is Sentry Seer handing off to Cursor Cloud Agents: an error event becomes a merged pull request with no human between, via structured agent-to-agent handoff. Pango's plain-English policy-driven resolution routing and Notion's "Ready for Agent" kanban column are the two other patterns that read as new operational shapes rather than variations on already-logged mechanisms.

## Patterns

### 1. Policy-driven post-purchase resolution routing
**Source:** [Pango (YC S26)](https://www.ycombinator.com/companies/pango) — ~30 e-commerce brands live; one scaled from $6M to $100M ARR in 11 months with zero ops hires; claims 99% of returns/shipping ops automated.
**Mechanism:** Carrier webhook, customer email/portal submission, or refund request triggers the agent. It reads store order data (Shopify), carrier tracking API state, WMS inventory, past customer history, and merchant-defined policy rules written in plain English ("here's how I want to handle late deliveries vs. lost packages vs. wrong-size returns"). It picks between exchange-first offer, refund, reshipment, or carrier claim; issues the return label; updates the order; drafts and sends the customer message; escalates only exceptions. Writes to the Shopify order, carrier system, customer inbox. Replaces the returns coordinator plus post-purchase CX rep.
**Why agentic:** Not a rules engine. Merchant expresses policy in prose; agent interprets ambiguous customer intent and picks between five resolution branches per case. Traditional tools (Loop, AfterShip) require every branch pre-configured.
**Generalizable core:** External event webhook → read policy prose + order/inventory state → pick resolution branch → write to system of record + notify counterparty.
**Deployability:** n8n + Claude + Shopify API + carrier webhook = weekend build for a single merchant, week for multi-carrier. Full multi-tenant equivalent is a month-plus. Replaces the CX-plus-ops-coordinator hire that scales linearly with order volume.

### 2. "Ready for Agent" kanban column as delegation surface
**Source:** [Notion Custom Agents (private alpha, July 2026)](https://www.notion.com/help/use-claude-agents-in-notion) built on [Claude Managed Agents](https://claude.com/blog/claude-managed-agents). Engineering, marketing, ops teams reportedly delegate dozens of tasks in parallel per team.
**Mechanism:** Employee drags a task card into a "Ready for Agent" status column on a Notion database (batch drags supported). Agent reads the task description plus every Notion page linked to the card — design system, PRDs, past decisions, API docs. Spins up a long-running Managed Agent session, produces the artifact (code diff, slide deck, spreadsheet, mini web app), and posts progress in the task's comment thread. Writes attached files back to the card, optionally opens a linked GitHub PR. Replaces the "who has a spare hour to build X?" Slack ask.
**Why agentic:** Same column handles a slide request, a codegen request, and a market-sizing spreadsheet. Tool choice and step planning are autonomous; the column is the routing surface, not a per-task workflow.
**Generalizable core:** Task-board status change → read linked context pages → run open-ended tool-using session → attach artifact back to the card.
**Deployability:** Notion Custom Agents (buy). Custom equivalent is Claude Agent SDK + a kanban board's status webhook + a scoped RAG index over linked docs — weekend prototype, month for permissioned multi-user. Replaces the junior IC who catches one-off asks.

### 3. YAML-scripted alert-triage taskflow
**Source:** [GitHub Security Lab Taskflow Agent](https://github.blog/security/ai-supported-vulnerability-triage-with-the-github-security-lab-taskflow-agent/) ([repo](https://github.com/GitHubSecurityLab/seclab-taskflow-agent)) — open-sourced Jan 2026; has surfaced ~30 exploitable vulnerabilities in production repos since Aug 2025 by triaging CodeQL false positives.
**Mechanism:** New CodeQL alert fires (e.g., `js/xss`, GitHub Actions `untrusted-checkout`). A YAML file specific to that vulnerability class breaks the audit into ordered sub-questions ("is the tainted variable actually reachable?", "is the sanitizer sufficient?", "does the sink evaluate the tainted value?"). The agent walks each step, reads source code, traces call graphs and sink/source paths, and classifies each alert true-positive or false-positive with a reasoning trace. Writes the triage verdict back to the CodeQL alert; only likely-true findings surface to the human researcher.
**Why agentic:** YAML defines the *structure* of the audit; the LLM does the actual judgment at each node, and the code-reading path per alert is not pre-determined. A linter can't answer "is this exploitable in this codebase's control flow."
**Generalizable core:** Alert in scanner/monitor → read entity context + linked artifacts → walk YAML-defined decision protocol → write verdict back to the alert.
**Deployability:** Open-source starting point exists. Porting to another alert queue (Semgrep, Snyk, Dependabot, or Sentry error triage, or PagerDuty low-sev alerts) is a 1–2 week job for a domain expert who can author the YAML for that alert class. Replaces the L1 triager on any high-false-positive queue.

### 4. Agent-to-agent handoff: error event → root cause → merged PR
**Source:** [Sentry Seer + Cursor Cloud Agents integration](https://sentry.io/changelog/seer-can-now-trigger-cursor-agents-to-fix-your-bugs/); [Sentry "From 57 bugs to 1"](https://blog.sentry.io/57-bugs-to-1/). Live for any Sentry customer with a Cursor API key.
**Mechanism:** A Sentry issue matching a Seer Automation rule (new regression, severity/tag filter) triggers Seer. Seer reads stack trace, breadcrumbs, user-impact metrics, tracing/log context; produces a root-cause hypothesis; then calls the Cursor Cloud Agent API with the RCA bundled as structured context. Cursor spins up in the target repo, writes the code fix, and opens a PR against the branch. Writes to GitHub as an author-tagged PR. Replaces the "engineer reads the Sentry issue, reproduces, writes fix, opens PR" loop for the long tail of low-severity bugs that otherwise never get shipped.
**Why agentic:** Two distinct agents chained by structured handoff — one specialized in reasoning about an error, one specialized in writing code — with no human in between. Neither piece is a dashboard; the pipeline turns a monitoring event into a mergeable change.
**Generalizable core:** Detection event → agent A reasons about cause → structured handoff to agent B that writes the artifact → land the artifact in the downstream system of record.
**Deployability:** Shipped Sentry integration is a weekend to wire up (install + API key + Automation rule). Custom equivalent for any error tracker plus any coding agent = week. Beyond the bug-fix case, the same handoff shape applies to (a) alert → triage agent → ticket-drafting agent → filed Jira, or (b) inbound RFP → RFP-parsing agent → proposal-drafting agent → generated deck.

### 5. Milestone-triggered document drafting with human approval gate
**Source:** [Eve Legal — Agents for Plaintiff Law](https://www.eve.legal/use-cases/ai-agents-for-plaintiff-law); [LawNext coverage](https://www.lawnext.com/2026/06/eve-builds-on-ai-workforce-launch-with-eveos-an-ai-native-operational-platform-for-plaintiff-firms.html). Now on 1,400+ plaintiff firms, 200K+ active matters; cited outcome: 60 days faster settlement.
**Mechanism:** Case reaches a predefined milestone in the case-management system — medical records received, treatment complete, discovery deadline approaching. Agent reads the uploaded medical PDFs, case intake data, prior settlements on comparable injuries, and the insurer's historical valuation ranges. Drafts (a) a medical chronology, (b) a demand letter with a data-backed valuation, (c) discovery responses. Writes drafts back into the case management system, flagged for attorney review — nothing leaves the firm without sign-off.
**Why agentic:** Milestone-triggered without a human prompt, reads unstructured document troves, produces a full outbound artifact (not an answer), routes through a mandatory human approval gate.
**Generalizable core:** Case/deal/case-file milestone in a system of record → read unstructured document trove → draft outbound artifact into that system → human approves before it leaves.
**Deployability:** Buy Eve for legal. Same pattern is a week-build in any vertical with structured cases: insurance claims (claim milestone → medical records + policy → drafted settlement letter), immigration (RFE issued → prior filings + regulations → drafted response), mortgage underwriting (application milestone → income docs + rate sheet → drafted approval letter), clinical trial enrollment (screening complete → labs + protocol → drafted consent packet).

### 6. Autonomous month-end close with material-item escalation
**Source:** [Pilot Meridian AI Accountant](https://pilot.com/meridian); [Accounting Today](https://www.accountingtoday.com/news/pilot-launches-fully-autonomous-ai-bookkeeper). Launched Feb 2026, $99/mo GA, trained on Pilot's decade of bookkeeping over 7,000 startups.
**Mechanism:** Month-end date (cron) triggers the close, plus continuous transaction flow from connected bank/CC/Stripe/Rippling feeds triggers real-time categorization. Agent reads bank/CC transactions, receipts, vendor invoices, payroll runs, prior GL history, chart of accounts, prior period categorization patterns. Categorizes each transaction against learned policy, reconciles accounts, closes historical books during onboarding, produces P&L / balance sheet / cash flow. Pauses and asks the accountant only on material judgment calls (unusual transaction, missing docs). Writes to QuickBooks/NetSuite GL and a financials packet PDF. Replaces the outsourced bookkeeper.
**Why agentic:** Scheduled autonomous run produces a completed close, not a review queue; escalates only on material items via structured rules; writes to the ledger itself, not to a "please categorize these" dashboard.
**Generalizable core:** Period-end schedule + streaming records → categorize against learned policy → post entries to book of record → generate cycle-end deliverable with escalation on material items.
**Deployability:** SaaS-ready for bookkeeping ($99/mo). The pattern generalizes to any periodic close: payroll close, inventory reconciliation, ad-spend attribution, royalty statements, tax filings. Multi-week to multi-month build depending on how large the policy surface is for the vertical.
