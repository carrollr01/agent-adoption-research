# 2026-08-11 — Agent Pattern Scan

## TL;DR
Most interesting today is Erewhon's two-agent drafter+grader loop that quietly self-tunes support replies without human review of every case. A meta-pattern worth stealing: pair the doer with a scorer, log the delta between draft and human-sent, feed it back to the prompt. Six patterns total, spanning support, sales ops, coaching, PR review, RFQ intake, and permit portals.

## Patterns

### 1. Self-tuning drafter + grader loop for customer support (Erewhon)
**Source:** https://zapier.com/customer-stories/Erewhon — 10-store LA grocer, ~1,500 hours/year saved on member support.
**Mechanism:** New Help Scout ticket fires a 39-step Zap. Agent looks up the customer's membership tier and purchase history, retrieves relevant policy chunks from a vector store, and drafts a reply in either "member-warmth" or standard tone. Draft posts as a Help Scout draft for the human to send. Separately, a second "English Tutor" LLM compares the eventual human-sent reply to the original draft and logs the delta to BigQuery, which the team uses to retune the drafter prompt.
**Why agentic:** Two agents in a loop — one acts, one scores — and the scorer's output changes future behavior. No dashboard involved; the human just sends a better draft each week.
**Generalizable core:** Inbound message → agent drafts with retrieved policy + customer context → human sends the final → grader agent compares delta and writes it to a store that reshapes the drafter's prompt. Any workflow where a human is already reviewing agent output can bolt this loop on for free.
**Deployability:** Zapier + ChatGPT + Help Scout + BigQuery + a vector store. Week build for the first version, ongoing prompt-tuning discipline. Replaces the tier-1 agent's research-and-draft time and the team lead's manual QA sampling. No ML headcount needed.

### 2. Slack slash-command reference-customer finder (Samsara "Reffy")
**Source:** https://www.gumloop.com/blog/how-samsara-streamlines-marketing-and-sales-operations-with-gumloop — public fleet-ops company, marketing-ops team saving ~$80k/yr in ticket volume.
**Mechanism:** Seller types `/reffy Acme Corp` in Slack. Agent pulls the prospect's Salesforce record (industry, size, use case, deal stage), scans an Airtable library of hundreds of reference customers with prose attributes ("hesitant CFO", "cross-dock ops"), scores each candidate against the prospect narrative, and returns a ranked list in Slack with per-candidate reasoning.
**Why agentic:** Ranking is prose-similarity across situation narratives, not attribute filtering. A dashboard with dropdowns can't decide "this reference's CFO objection maps to that prospect's finance skepticism."
**Generalizable core:** Slack slash query → agent pulls the querying context object → semantic scan of a curated library → ranked list with prose reasoning returned in-channel. Applies to matching case studies, similar past projects, comparable candidates, comparable claims, comparable litigations.
**Deployability:** Gumloop + Salesforce + Airtable + Databricks + Slack. Week build. Replaces the 1–2 day marketing-ops ticket for reference-customer curation. Scales to any team that already has a Salesforce-Airtable-Slack triangle.

### 3. Per-motion post-call coaching agent (Gusto)
**Source:** https://www.gumloop.com/blog/how-gusto-accelerates-gtm-with-gumloop — payroll/HR platform, cited $1M ARR uplift in 90 days.
**Mechanism:** Gong call completion fires the workflow. Agent pulls the transcript, identifies which sales motion the rep is running (SMB new logo, mid-market upsell, partner-sourced, etc.), retrieves the rubric specific to that motion, scores the call, writes a coaching task list back to Salesforce, and DMs the rep in Slack with the single highest-leverage moment from the call.
**Why agentic:** Rubric changes per motion and per deal stage. Scoring requires reasoning about intent and objection handling, not counting filler words or checking talk-time.
**Generalizable core:** Event completion (call, meeting, session, interview, appointment) → agent selects the appropriate rubric based on context → scores + writes structured feedback to system of record → surfaces the one thing that matters in the actor's daily channel. Applies to any "post-event coaching" workflow: technicians after service calls, therapists after sessions, teachers after class observations, recruiters after interviews.
**Deployability:** Gumloop + Gong (via MCP) + Salesforce + Snowflake + Slack. Week build once rubrics exist. Replaces manager listening + weekly 1:1 coaching prep. Rubric maintenance is the real ongoing work.

### 4. Multi-dimension risk-scored PR reviewer with auto-approve routing (Vercel Eve / "Merge Mommy")
**Source:** https://www.lennysnewsletter.com/p/build-an-ai-code-review-bot-in-30 and https://github.com/vercel/eve — framework used internally at Vercel and by Intercom teams.
**Mechanism:** PR after CI checks pass. Agent reads the diff plus the blast radius across dependent services and change history. Scores across six independent dimensions — blast radius, reversibility, data security, ops impact, verification gap, change surface. Auto-approves and merges low-risk PRs; pings Slack with the specific dimension score for anything above threshold; logs everything for SOC 2 audit.
**Why agentic:** "Reversibility" and "data security implications" are judgment calls that require reasoning across the diff and the surrounding system. A linter cannot answer them; a dashboard can only display someone else's answer.
**Generalizable core:** State-change event → agent scores across N independent risk dimensions → threshold routing (auto-approve, human review, hard-block) → auditable log. This skeleton is the answer to a huge class of "someone senior has to eyeball every X" problems: loan approvals, refund requests, insurance claims, contract redlines, medical prior auth, marketing copy sign-off, permission grants. When a client says "we need visibility into approvals," this pattern replaces the dashboard they think they want.
**Deployability:** Vercel Eve framework + GitHub + Slack + audit log store. Week to month build depending on how many dimensions and how much domain context the rubric needs.

### 5. Vision-parsed RFQ intake to ERP quote module (job shops)
**Source:** https://leanware.co/insights/rfq-automation-job-shops-mgas — cited operator: Production Theory, custom-fab shop, ~30 employees.
**Mechanism:** RFQ email hits the shared quoting inbox or a customer-portal upload. Agent extracts line items and delivery terms from the email body, runs vision on the attached drawing to read the title block (tolerances, finish callouts, material spec), parses any spec-sheet PDFs, and writes a structured quote-module record directly into JobBOSS or Epicor with line items, quantities, delivery, material, and estimator-facing notes.
**Why agentic:** Multimodal — the drawing is the source of truth for tolerances, and the LLM has to reason about which drawing fields matter for pricing. Writes structured records into a production system, not a report.
**Generalizable core:** Inbound document bundle (mixed text + images + PDFs) → multimodal extraction against domain schema → structured write into a production system, escalate exotic cases to a human. Applies to insurance FNOL intake, legal e-discovery front doors, medical prior-auth packets, permit applications, procurement RFPs.
**Deployability:** Vision-capable LLM + ERP REST APIs + email or portal ingest. Month build for the first shop; per-shop tuning for drawing conventions. Estimator time saved: 45–90 minutes per RFQ, 60–120 hours per week at 30 employees. Hand-drawn sketches still route to human.

### 6. Cross-jurisdiction municipal permit portal filing agent
**Source:** https://www.skyvern.com/blog/automate-construction-permit-applications-inspection-forms/ — small GCs, electrical/roofing/HVAC.
**Mechanism:** Ops manager approves the estimate in the CRM. Webhook fires the agent. Agent opens the relevant city or county permit portal in a headless browser, reads the current form layout (vision on rendered pages, since portals change), maps CRM job data into the correct fields, uploads the scope PDF, submits, captures the confirmation, writes the permit ID back to the CRM.
**Why agentic:** Every jurisdiction has a different portal, portals change without notice, and field mappings shift year to year. In-loop reasoning about "which field is this" and "did the submission succeed" cannot be pre-scripted.
**Generalizable core:** Internal state change → agent navigates an external portal it has never seen before, using vision + schema + retries → writes the external reference ID back to the internal system. This is the "portal navigator" pattern. It shows up wherever the last mile of a workflow is somebody else's web form: state licensing renewals, vendor onboarding portals, carrier claim submissions, DME prior-auth portals, tax filings, grant submissions.
**Deployability:** Browser-use style agent (Skyvern, Browserbase, Playwright + LLM) + CRM webhook. Week per new jurisdiction. CAPTCHA and 2FA still human-in-the-loop. A back-office coordinator who spent 2–4 hours/day copy-pasting into portals becomes an approver instead.
