# 2026-10-23 — Agent Pattern Scan

## TL;DR
The most interesting mechanism this week is Anthropic Japan's "Nakama" BDR fleet, where a Coordinator agent reads a Slack feedback channel every 15 minutes and rewrites the other agents' prompts and shared knowledge base. The fleet is self-modifying, not just operational. Three other patterns worth banking: Anthropic's own inbound buying agent that passes a reasoned handoff to reps (not just a transcript); 1Password for Agents, which puts a cryptographic credential broker between the agent and the login form; and LangChain's internal paid media agent that replaced the ad agency line item.

## Patterns

### 1. Self-rewriting agent fleet with a Coordinator meta-agent
**Source:** [How an Anthropic Japan BDR runs his day with a fleet of Claude agents](https://claude.com/resources/articles/how-an-anthropic-japan-business-development-representative-runs-his-day) — Oct 16, 2026 writeup. One BDR, six working agents plus a Claude Tag companion, all running on Claude Managed Agents. Author estimates ~60 hours of weekly work replaced.
**Mechanism:** Each worker agent has a different trigger. Furiwake runs once each morning on the inbound lead queue and routes to a rep. Sabaki qualifies assigned leads, drafts first-touch emails, and updates Salesforce. Henji scans the inbox hourly and drafts replies (Opus is the escalation advisor). Shoudan refreshes opportunity records. Nokori runs at end of day on calendar and meeting transcripts to write summaries and follow-up drafts. The sixth agent, Coordinator, runs every ~15 minutes against a dedicated Slack channel where the BDR drops free-text change requests ("Sabaki keeps misclassifying trial users as enterprise") and the Coordinator edits the other agents' instructions and the shared knowledge base to incorporate the feedback. Versioned prompts, single shared memory store, Slack as the control surface.
**Why agentic:** The Coordinator is a meta-agent whose only job is to update the behavior of its peers from unstructured human feedback. The feedback loop that normally lives in a prompt engineer or an ops lead has been collapsed into a scheduled run.
**Generalizable core:** Scheduled meta-agent reads an unstructured feedback channel → updates the prompts and shared memory of peer agents → peers run on their own cadences against the updated instructions.
**Deployability:** Needs a hosted agent runtime (Claude Managed Agents here, but LangGraph + persistent store or any orchestrator with versioned prompts would do), a shared memory store, and a dedicated Slack channel. Week-plus build if the worker agents already exist; the meta-agent itself is the small part. Replaces the "prompt owner" role on an agent fleet, not individual contributors. Only pays off once there are enough worker agents that keeping their prompts fresh is a real tax.

### 2. Inbound buying agent with a reasoned handoff, not a transcript
**Source:** [How Anthropic's sales team rebuilt inbound with Claude Managed Agents](https://claude.com/resources/articles/how-anthropics-sales-team-rebuilt-inbound-with-claude-managed-agents) — Anthropic's own inbound funnel. Thousands of conversations per day. Built by one engineer in a few weeks.
**Mechanism:** Trigger is a prospect clicking Contact Sales / Pricing, hitting an in-product entry point, or landing from an Anthropic email. Customer picks "talk to the agent" or "talk to a human" up front. Agent reads the documentation and support knowledge base plus the prospect's existing Claude usage. It asks follow-up questions, answers pricing / security / data questions, recommends a plan and seat count, and routes each conversation to one of three endings: direct checkout, a quick answer, or a human handoff. The handoff is the interesting part: the receiving rep gets the full conversation plus the agent's stated reason for escalating, not a raw transcript. Escalated leads convert to opportunities at >2x the old form rate and close ~5 days faster; the share of conversations needing a human to close fell by about half.
**Why agentic:** It is not a chatbot that logs leads for later. It makes a routing decision, closes deals via checkout when it can, and when it can't it writes a structured reason-for-escalation that the human reads before the first call.
**Generalizable core:** Inbound prospect message → agent reads product + account context → recommends an action and takes it (checkout, answer, escalate) → on escalation, writes a reasoned handoff artifact for the human → human picks up pre-qualified.
**Deployability:** Any chat-widget surface + a hosted agent + a checkout path + a CRM. Claude Managed Agents, Lindy, or a Next.js + Claude API build with Stripe for checkout and HubSpot/Salesforce for the handoff. Week to a month depending on how clean the knowledge base is. Replaces the inbound BDR qualification tier. Needs real self-service pricing — pointless if every deal is custom-negotiated.

### 3. Credential-sealed login delegation to agents
**Source:** [1Password launches a way for AI agents to log in on your behalf without seeing your password](https://techcrunch.com/2026/10/22/1password-launches-a-way-for-ai-agents-to-log-in-on-your-behalf-without-seeing-your-password/) — launch Oct 22, 2026. [1Password's own announcement](https://1password.com/blog/1password-for-ai-agents). Launch partners named include Anthropic, OpenAI, Perplexity, Browserbase, Ramp, Town.
**Mechanism:** Trigger is a browser-using agent landing on a login form. The agent identifies itself to 1Password with a unique digital key, then requests a specific vault item ("log me into Shopify admin"). The user sees the request on their own device, approves per-login, and 1Password auto-fills the credential directly into the destination site. The agent never sees the password string. Once the site accepts the login, the credential is removed from the agent's context. Builds on an earlier Browserbase-integrated version (Secure Agentic Autofill) and a developer SDK for non-login auth.
**Why agentic:** Unblocks the single most common point at which browser agents get stuck or require a human present — the login prompt. The agent completes its task without a human having to type the password into the agent's context or share a reusable secret with it.
**Generalizable core:** Agent reaches a credential wall → requests the specific credential from a cryptographic broker with its own identity → human approves per-request on their own device → broker injects secret into the destination and withholds it from the agent.
**Deployability:** For businesses: pay for 1Password Business, give each agent its own identity, scope approvals per workflow. Weekend to wire up for a single workflow if the agent uses Browserbase or a supported browser-use harness; longer if building custom. Replaces the "human sitting next to the agent to click approve on 2FA" step. Caveat: once the agent is inside an authenticated session, 1Password doesn't constrain what it does there — session-level guardrails are still your problem.

### 4. In-house paid media agent that replaces the ad agency
**Source:** [How we built LangChain's GTM Agent](https://www.langchain.com/blog/how-we-built-langchains-gtm-agent) and [LangChain's open-sourced Paid Media Agent](https://www.neura.market/news/langchain-open-sources-paid-media-agent) — LangChain uses this on its own Google / LinkedIn / Meta spend. Reports paid media grew from 0 to 20% of marketing pipeline in six months and ~$5K/month saved by killing the agency line item. Open-sourced September 2026, discussed again on X Oct 20 as part of Caspar's "company harness" post.
**Mechanism:** Scheduled runs (weekly at minimum, daily for live campaigns). The agent pulls spend, impressions, conversions, and cost-per-acquisition from each ad platform's API; joins that against the CRM to see which clicks became qualified pipeline; writes a performance summary and a reallocation recommendation (shift budget from campaign A to B, pause underperforming creatives, raise bids on winning keywords); drops the summary into Slack and the reallocation into a pending-review queue a marketing lead approves. Memory is per-campaign and global. Human approves before any budget change is actually pushed.
**Why agentic:** It makes the "what should we change this week" call that an agency account manager would make, with the full data, and writes an approval-ready change set. The dashboards were already there; the agent is the decision step, not the display.
**Generalizable core:** Scheduled pull from vendor APIs → join against the business's conversion data → generate a reasoned change recommendation → write it to a human-approval queue → push on approval.
**Deployability:** Realistic stack: LangGraph or n8n for orchestration, direct ad-platform APIs, a CRM connector, Slack for the review surface. Week to a month depending on how clean conversion attribution already is. Replaces a retainer-funded agency account manager or an internal paid-media analyst for the reporting + recommendation layer. Does not replace creative work or strategic positioning. Scale caveat: pointless below ~$5K/month in ad spend because the time-to-value doesn't clear the build cost.
