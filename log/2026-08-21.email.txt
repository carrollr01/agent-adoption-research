# 2026-08-21 — Agent Pattern Scan

## TL;DR
The most interesting pattern today is Rindler's login-gated recurring web-task agent: cron fires, the agent signs into a vendor portal, pulls the report or submits the form, returns structured JSON, and self-repairs when the page layout changes. It unlocks a huge class of automations that RPA and Zapier couldn't reliably touch — anywhere a small team currently has one person doing a Monday morning portal round.

## Patterns

### 1. Login-gated recurring web-task agent (Rindler)
**Source:** [rindler.ai](https://rindler.ai/), [Product Hunt launch — August 2026](https://www.producthunt.com/products/rindler). Small ops teams and solo operators automating vendor-portal work that RPA couldn't hold on to.
**Mechanism:** Cron fires → agent loads a pre-mapped "site graph" for the target (Rindler ships ~1,000 sites so the agent calls a map instead of parsing the DOM cold) → signs in with stored credentials → pulls a report or submits a form → returns structured JSON → self-repairs when a page changes, updating the site map for the next run → writes JSON to the caller (Google Sheets, Slack, webhook).
**Why agentic:** The self-repair loop is the difference between this and RPA. When a portal moves a button, the agent reasons about the new layout instead of failing red. The recurring trigger + login-gated action + structured output makes it a real workflow node, not a chatbot.
**Generalizable core:** Schedule → agent authenticates → executes a bounded task on a system with no API → returns structured output → repairs its own script when the target changes.
**Deployability:** Rindler hosted, or roll your own with Playwright + Claude for computer use + a per-site schema. Weekend per site for a hand-rolled version. Replaces the ops person's Monday-morning portal check — utility invoices, ad-platform exports, state filings, insurance carrier portals, city permit sites.

### 2. Ecommerce returns triage agent — per-unit routing to best-margin outcome
**Source:** [digitalapplied.com — Returns Automation 2026](https://www.digitalapplied.com/blog/ecommerce-returns-automation-ai-triage-playbook), [usefini.com — Which AI tools auto-approve refunds](https://www.usefini.com/guides/ai-platforms-ecommerce-returns-refund-automation-2026), [US Tech Automations returns case studies](https://ustechautomations.com/resources/blog/automate-ecommerce-returns-case-study-2026). Brands doing 1,000+ returns/month; ~60–80% of cases fall through fully automated.
**Mechanism:** Return-scan or refund-request event fires → agent reads SKU rules, supplier rules, order + customer return history, unit condition photos, and payment method → picks one of {returnless refund, auto-restock, exchange, refurb channel, liquidation, fraud hold} → writes into OMS, WMS, payment processor, and the helpdesk case; ambiguous or high-value cases queue to a human.
**Why agentic:** Every unit is a fresh reasoning pass, not a rule-table lookup. The agent self-scores confidence and decides whether to act, escalate, or hold — that judgment surface is what the L1 clerk actually does.
**Generalizable core:** Per-record event → agent pulls history + rules + condition → picks one of N terminal outcomes → writes to system-of-record → human queue only for low-confidence cases.
**Deployability:** n8n or Make + Claude/OpenAI + Shopify/Cin7/ShipStation + Stripe. Week for a single brand; month if you're wiring three back-end systems. Replaces L1 returns clerk and refund approver. Only pays back at several hundred returns/month.

### 3. Vega Detection Skills — agentic SOC triage + pre-investigation on every alert
**Source:** [vega.io/blog/vega-introduces-detection-skills](https://vega.io/blog/vega-introduces-detection-skills), [Jerusalem Post coverage](https://www.jpost.com/business-and-innovation/article-904562). Anthropic reports Vega's platform returns 67% of analysts' time using the Claude Agent SDK.
**Mechanism:** SIEM/EDR detection fires → agent loads the matching Detection Skill (markdown-defined reasoning chain in Anthropic's Skills format) → pulls host, user, and process context, runs enrichment tools, correlates with recent alerts → auto-closes false-positive-shaped noise, or escalates to an incident with a pre-written investigation narrative → writes back into the SOAR case system.
**Why agentic:** Not a static SOAR playbook. Each triage is a reasoning trace over live tool calls, and the investigation skill drafts the analyst's first page before a human opens the ticket. Skills are versioned and shared like open-source rules.
**Generalizable core:** Noisy alert stream → agent runs a per-alert skill that assembles context and either resolves or escalates with pre-drafted next steps.
**Deployability:** Claude Agent SDK + SIEM API + SOAR case system. Month build for a real deployment; the hard part is the skill library, not the runtime. Replaces L1 SOC analyst triage. Fits any regulated-ops team with a noisy alert queue — fraud ops, trust & safety, quality control, network ops — not only security.

### 4. Bola AI — voice charting agent for dental exams
**Source:** [bola.ai — AI in dentistry 2026](https://bola.ai/blog/ai-in-dentistry-2026-hype-vs-practical-solutions/). Live in 10,000+ dental and hygienist practices; expanding through summer 2026.
**Mechanism:** Chairside microphone captures the hygienist saying pocket depths, bleeding points, and restorative notes during the exam → agent parses each utterance against the patient's active perio chart, tooth-numbering scheme, and prior visit history → writes structured perio depths, restorative notes, and CDT billing codes directly into Dentrix / Eaglesoft / Open Dental / Curve → confirms only on ambiguous entries.
**Why agentic:** The agent decides which field each utterance belongs to (tooth #, surface, code), reconciles against prior chart state, and files without a click. It's a workflow node, not a transcript search — the value is that billing and clinical fields land populated, not that the audio got captured.
**Generalizable core:** Field worker narrates the job → agent transcribes, matches to the system-of-record's schema, populates fields, files silently, escalates only on unresolvable ambiguity.
**Deployability:** Whisper-class transcription + Claude/GPT + your system's API. Weekend for a single-form use case (an inspection report, a safety walkthrough); month for a full FSM/PMS integration. Replaces the "paperwork tax" on any field- or chair-facing worker — inspectors, home health nurses, insurance adjusters, health inspectors.

### 5. Spaceflow — procurement RFQ + supplier-chase agent
**Source:** [spaceflow.tech](https://spaceflow.tech/), [yespress.io — Spaceflow YC S26 launch](https://yespress.io/spaceflow-yc-s26). Reportedly $400M in annual supplier spend already routing through it.
**Mechanism:** New purchase request lands in SAP (or email) → agent reads company purchase history, supplier scorecards, current inventory, and required delivery windows → qualifies the request → picks a shortlist of suppliers → drafts and sends RFQs → normalizes multi-round quotes back into a comparison → chases supplier confirmations → writes the awarded PO to SAP. Above-threshold actions hold for buyer approval.
**Why agentic:** The agent runs a multi-round negotiation loop over email, not a form-filler. Each round updates the state (which suppliers responded, which are stalling, how quotes compare) and decides the next outbound action.
**Generalizable core:** Inbound request → agent picks counterparties from a scored graph → runs a multi-round outbound loop, tracking state per counterparty → writes the outcome back to the system of record, with an approval hold at the money threshold.
**Deployability:** MCP + REST on ERP/CRM + a mail sender + Claude/GPT. Month for a real deployment; the harder work is the supplier graph and the state machine, not the LLM. Replaces junior-buyer RFQ busywork and the supplier-chase inbox. Same skeleton fits sales-side RFQ response, insurance broker quote pulls, freight rate-shopping.

### 6. Cryptoworth — reconciliation agent that investigates residual variance
**Source:** [Cryptoworth press release — Aug 6, 2026](https://www.prnewswire.com/news-releases/cryptoworth-introduces-ai-reconciliation-agent-built-for-enterprise-control-auditability-and-faster-close-302845079.html). Crypto CFO teams closing the books against on-chain, custodian, and exchange feeds.
**Mechanism:** Nightly sync pulls balances from on-chain wallets, custodians, and exchanges → agent auto-matches the high-confidence transactions → residual variance goes to the investigation loop, where the agent classifies each remaining delta as duplicate / missing / excluded-per-rule / unexplained → for unexplained items it proposes an adjusting journal entry with a rationale → holds for human approve/reject → on approval, writes the entry to the ledger of record with a reversible audit log.
**Why agentic:** The value isn't the auto-match (any rule engine does that). It's the residual-investigation loop: the agent forms hypotheses about why a delta exists, tests them against the data it has, and produces a proposed journal with reasoning. That is what the senior accountant currently does by hand.
**Generalizable core:** Two systems of record that should agree → agent matches the easy items, investigates the residual, classifies each unexplained delta, proposes a resolving action → human approves → agent writes back with a reversible audit trail.
**Deployability:** Any ledger + a matching library + Claude/GPT + your GL. Week for a single-pair reconciliation (Stripe vs QuickBooks, Shopify vs bank, ad-spend vs invoice), month for multi-source. Replaces the "trace the delta" work that dominates month-end for any finance team with more than one source of truth. Fits inventory reconciliation, cash-vs-bookings, and any two-ledger problem.
