# 2026-06-20 — Agent Pattern Scan

## TL;DR
Three concrete patterns surfaced from YC P26 demo day (June 16) and recent platform launches: a manufacturing quote-desk agent that handles inbound RFQs end-to-end, an emoji reaction as a trigger primitive that turns "I'll deal with this later" into instant agent delegation, and a month-end close platform built around editable SOP documents that the agent runs and pauses at owner-defined gates. The emoji-as-trigger pattern is the most reusable: it works anywhere a human is the bottleneck between "I noticed something" and "someone needs to act."

## Patterns

### 1. The manufacturing quote-desk agent that runs RFQ → quote → follow-up unattended
**Source:** Korso (YC P26), https://www.ycombinator.com/companies/korso — from the YC Spring 2026 batch that wrapped on June 16, building "the intelligence layer for manufacturing" for small and mid-size manufacturers.
**Mechanism:** Trigger is an inbound RFQ landing in shared email or the customer portal. The agent parses the request, reads pricing history and current material/component costs from the ERP, drafts a quote, and routes it to a human for approval before sending. After the quote goes out, the same agent monitors order status across ERP and transport systems, chases delayed responses, notifies the customer when supplier ETAs slip, and escalates only when a step requires judgment. Output writes back to ERP, CRM, and email threads, with a full audit trail of every action. Replaces the daily triage work of a sales engineer or order coordinator.
**Why agentic:** It's a long-running workflow that spans weeks per RFQ, with checkpointing so a quote-to-close cycle survives the agent restarting. Not a dashboard or a chatbot — the agent moves the RFQ forward on its own and only stops when human approval is the next required action.
**Generalizable core:** Inbound document in any channel → agent enriches with historical pricing/context → drafts response → human approves → agent then babysits downstream timeline and escalates exceptions. Works for any business with a quote/proposal/estimate funnel that today gets done in spreadsheets and email threads.
**Deployability:** ERP + CRM + email connectors over MCP, Claude API or similar for parsing and drafting, a workflow engine like n8n or a custom Next.js shell for the approval UI. Week-build for a single quote type, month-build to cover a real catalog. Replaces or augments the quote desk; needs a real pricing history to read from, so brand-new businesses without quote archives won't get the same leverage.

### 2. The emoji reaction as agent trigger
**Source:** Notion Custom Agents — Slack triggers, https://www.notion.com/product/agents — generally available on Business and Enterprise plans, with the Slack trigger surface (new message, emoji reaction, @mention) shipping in the May/June 2026 update cycle.
**Mechanism:** Trigger is a specific emoji reaction landing on a Slack message (e.g. 📌 in #customer-issues, 📨 in #sales-leads). The agent reads the message, the surrounding thread, and any linked Notion pages or HubSpot/Linear records, then runs the workflow attached to that emoji: create a Notion task with the right owner and project, draft a reply in the thread, file a CRM note, schedule a calendar follow-up, or open a Linear ticket. Every run is logged with what fired it and what it did. Replaces the human step of "see message → context-switch → file the work in the right system."
**Why agentic:** The emoji is a delegation primitive. The agent decides what context to assemble, which downstream system to touch, and what to write — it's not just a saved-reply macro. Different emojis can fire different agents on the same message.
**Generalizable core:** Lightweight gesture in an existing tool (emoji, label, star, calendar tag) → agent reads surrounding context → executes a multi-step routing/filing/drafting workflow → writes to one or more systems of record. Removes the friction between noticing and acting.
**Deployability:** Off-the-shelf on Notion Business if the team already lives in Notion/Slack. For teams outside Notion, the same pattern reproduces in n8n or Make with Slack reaction webhooks plus a Claude API call plus the relevant destination connectors — weekend build for the first emoji, then incremental. Replaces or augments any internal coordinator role that today exists to "make sure things get filed."

### 3. The accounting close agent run from editable SOP docs with per-step autonomy gates
(variation of 2026-05-19 month-end close entry — new angle: SOP-as-Skill documents and per-step pause-for-review, instead of pure calendar-trigger automation)
**Source:** Ramp Stack for accounting firms, https://ramp.com/stack — launched in 2026 specifically for accounting firms running close work for many SMB clients; coverage in the Accounting Today launch piece, https://www.accountingtoday.com/news/ramp-launches-stack-made-specifically-for-accounting-firms.
**Mechanism:** The firm writes its close procedures as editable "Skill" documents — one per recurring task (reconciliations, journal entries, schedule roll-forwards, variance analysis, payroll allocation). Trigger is either a calendar event (e.g. close day) or an upstream event (bank feed updated, payroll report dropped in a folder). The agent reads the relevant Skill, prior GL history, and the source data, then executes: posts a recurring journal entry to QuickBooks autonomously, runs a reconciliation and halts when it finds a discrepancy outside tolerance, drafts a variance commentary for partner sign-off. An Advisor Console shows close status across every client. Replaces the staff-accountant grind of running the same close steps client by client, while letting the partner decide per-step where the agent runs alone and where it pauses.
**Why agentic:** The SOP is the prompt. Edits to the Skill doc change agent behavior on the next run, so the firm tunes the agent the same way it would train a new hire. Variance and reconciliation gates make the human the exception handler, not the operator.
**Generalizable core:** Recurring multi-step business process → encoded as an editable plain-language SOP → agent reads SOP + source data → executes autonomously where tolerance is clean, halts and surfaces exceptions where it isn't → human handles only the exceptions, with a portfolio-level status view across all clients/entities. Works for any professional-services firm running the same workflow across many clients: bookkeeping, payroll, tax prep, HR admin, even agency billing cycles.
**Deployability:** Ramp Stack is buy-not-build for accounting firms specifically. For other professions, the pattern is roughly a Notion or Google Doc that holds the SOP, a Claude API agent that reads it on a schedule and runs through the steps with tool calls, and a per-step gating config that decides what auto-posts vs. what queues for review. Month-build for one firm's worth of skills, ongoing tuning as Skills evolve. Replaces routine staff hours, augments the senior reviewer.
