# 2026-07-06 — Agent Pattern Scan

## TL;DR
Three novel patterns today, each with a different non-chat trigger class. Notion 3.6 (released July 1) makes a kanban column state change the trigger for delegating work to an external agent. Incident.io and its peers use a PagerDuty-style alert as the trigger for an agent that pulls logs, deploys, and code changes into a single Slack post. Dust customer Malt shows an @mention in a shared Slack channel triggering a cross-source retrieval agent that answers with citations. The common thread: the trigger surface is moving off "someone types in a chat window" and into the operational systems people already live in.

## Patterns

### 1. Kanban column as agent trigger
**Source:** [Notion 3.6 release notes, July 1, 2026](https://www.notion.com/releases/2026-07-01) — External Agents API moved out of alpha; teams drag task cards into a "Ready for Agent" column and Claude Code, Cursor, Codex, or Decagon picks them up automatically, works in parallel, and reports back into the same card. Notion says early customers routinely queue 30–40 cards at once.
**Mechanism:** Trigger is a card entering a designated Notion column (or the equivalent status change on a database view). The agent reads the card body, linked docs, referenced meeting notes, and any database rows joined to the card. It produces the artifact the card describes (prototype code, spec doc, slide draft, spreadsheet analysis) and writes it back as attachments and comments on the same card, with an activity log the human reviewer can scroll through inline. Replaces the project manager step of "assign this to a person who then goes and does the linked-context reading themselves" and the intern/junior work of first-draft artifact production.
**Why agentic:** No prompt is written. The state transition itself is the trigger, the linked graph of Notion content is the context, and the output is a durable artifact attached to the record rather than a chat reply. Dozens run in parallel and coordinate through the board rather than through a shared conversation.
**Generalizable core:** State change on a record in the team's operational system → agent reads the full linked context of that record → produces the artifact the record describes → writes it back to the same record for inline review.
**Deployability:** Notion External Agents API plus Claude Code / Cursor / Codex on the agent side. Notion Workers ($10 per 1,000 monthly credits after August 11) handles the runtime. This is a week-build if you already have the agent, mostly wiring the API and defining the trigger column. Replaces or augments a PM's routing role and the first-draft phase of any IC role that produces content the PM can already scope in a task card. Scale caveat: works best where task descriptions are already high-quality, so useful for teams that already write good tickets.

### 2. Alert-driven cross-system incident investigator
**Source:** [Metoro's roundup of AI incident tools](https://metoro.io/blog/top-ai-incident-response-tools) documents the pattern across incident.io, Cosmos, and PagerDuty AIOps; Cosmos claims an 81% reduction in on-call investigation effort in internal testing, with teams cutting per-incident triage from 30–45 minutes to about 5 minutes of human review.
**Mechanism:** Trigger is an alert firing in PagerDuty, Datadog, or the equivalent monitoring system. The agent reads the alert payload plus recent logs, recent metrics, the last N deploys, related GitHub PRs, service dependency map, and often the linked runbook or SOP in Confluence. It posts a single investigation summary into the incident's Slack channel with candidate root cause, correlated timeline, and suggested next action, tagged for the on-call human to confirm or override. Replaces the first 30 minutes of an SRE opening five browser tabs and typing in Slack "what changed."
**Why agentic:** An operational event fires the workflow. The agent decides which of several telemetry systems to consult and in what order, correlates evidence across them, and writes a decision-oriented summary rather than surfacing raw dashboards. The human's job shrinks to verification and choosing the fix, not gathering evidence.
**Generalizable core:** Monitoring or alerting event → agent pulls correlated signals from every connected observability source → posts a prioritized diagnosis in the team's real-time channel → human confirms and acts.
**Deployability:** incident.io, PagerDuty AIOps, or Cosmos out of the box for engineering teams. n8n has a template that does the security-alert version (NixGuard AI → Slack/Jira). Weekend build for a starter version on n8n if your monitoring already sends webhooks. Replaces the first-pass triage work of an on-call engineer. The skeleton generalizes cleanly to non-engineering alerts: a manufacturing quality-control anomaly, a negative-review threshold, a bank-transaction fraud flag. Scale caveat: value scales with how many independent signal sources the agent can reach, so it pays back most in shops that already have decent observability.

### 3. @mention as cross-source Q&A trigger
**Source:** [Dust customer story: Malt](https://dust.tt/blog/slack-ai-agents) — Malt, Europe's largest freelance marketplace, embedded a Dust agent called Malty AI in their Slack workspace. 100% of the customer experience team uses it daily and support ticket close time has been cut in half.
**Mechanism:** Trigger is an @mention of Malty AI in any Slack thread. The agent reads the message plus the enclosing thread, then queries Malt's Notion knowledge base, connected internal docs, and the public FAQ set. It replies inline in the thread with a synthesized answer plus links back to the underlying sources. If the answer requires a policy call it doesn't have data for, it names the human owner instead of guessing. Replaces the small but constant cost of interrupting the person who "owns" a domain to answer a one-off question, and replaces the search-across-five-tools loop when the answerer isn't sure where the doc lives.
**Why agentic:** The agent chooses which knowledge sources to consult per question rather than running a fixed lookup, cites what it found, and knows when to defer to a named human. That routing decision is what makes it more than a search box.
**Generalizable core:** Employee question in a shared channel → agent retrieves and synthesizes from every connected knowledge source → answers in-thread with citations or escalates to a named human owner → replaces cross-team interruption.
**Deployability:** Dust or a similar agent platform with Slack + Notion/GDrive/Confluence connectors; can also be built on Claude Agent SDK + MCP servers for the source systems if a team wants to own the stack. Week-build once the source-of-truth docs are consolidated and reasonably well tagged. Replaces or augments the "internal helpdesk" role that many teams distribute informally across senior ICs. Scale caveat: quality depends entirely on how well-curated the underlying knowledge base is. Teams with scattered, out-of-date docs get an agent that confidently repeats outdated policy.
