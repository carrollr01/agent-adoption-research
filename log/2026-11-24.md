# 2026-11-24 — Agent Pattern Scan

## TL;DR
OpenCode 2.4.0 (shipped yesterday) turns the agent itself into the scheduler: a running agent can register its own cron jobs, shell runs, and MCP-push-triggered actions, which collapses the Zapier-style orchestrator out of the stack. Intercom's auto-approve-low-risk-PR gate and Hyperagent's PR-to-demo-video pipeline are both worth noting as production agentic flows that replace specific human tasks rather than acting as reporting layers.

## Patterns

### 1. Self-scheduling agent that registers its own triggers
**Source:** [OpenCode v2.4.0 release](https://github.com/anomalyco/opencode/releases/tag/v2.4.0), [OpenCode changelog](https://opencode.ai/changelog/v2.4.0), [AlphaSignal writeup](https://alphasignal.ai/news/opencode-2-4-0-lets-ai-agents-run-themselves-on-schedules-and-events) — Anomaly's OpenCode CLI (v2.4.0, shipped 23 Nov 2026) added an `/automation` command that lets a live agent schedule future prompts, Code Mode scripts, or shell commands. The agent itself decides what to schedule, mid-session.
**Mechanism:** Trigger is one of: cron expression, fixed interval, one-shot timer, or push event from a connected MCP server (MCP Events beta, with heartbeats and auto-reconnect). Context read is whatever the authored prompt/script reads at run time; shell actions require one approval at creation time, not per run; each run records exit code and output back into the session log. Writes to: whatever the prompt or shell command targets (repo commits, API calls, external services). Replaces: the external orchestrator (Zapier, n8n, cron+webhook plumbing) a team would otherwise stand up to make an agent run on a schedule or event.
**Why agentic:** The scheduler is created from inside the agent's reasoning, not from a UI; an agent can set up "every 4 hours, re-scan these repos and open a PR if X" without a human writing the cron entry. The MCP-push path makes an agent reactive to external system events without polling.
**Generalizable core:** Agent output includes registering its own future invocation (cron / event subscription) → each firing re-reads live context → acts on repo or external system → human sees result in the session log, not a dashboard.
**Deployability:** CLI-native and already shipping — weekend-build to wire a self-managing repo-maintenance or monitoring agent, though AlphaSignal flags the feature as experimental and warns that shell/MCP-triggered actions can change external systems without an interactive confirmation per run; credentials should be narrowly scoped. Augments a DevOps engineer; replaces the Zapier/Make layer.

### 2. Auto-approve-low-risk-PR gate at Intercom
**Source:** [Brian Scanlan on How I AI (chatprd.ai)](https://www.chatprd.ai/how-i-ai/how-intercom-doubled-engineering-output-brian-scanlan-ai-workflows-for-claude-code), [Brian Scanlan at AI.engineer](https://ai.engineer/talks/4_VQBbs2iQA-building-ai-double-throughput-your-engineering) — Intercom, Senior Principal Engineer Brian Scanlan describes the mechanism; company reports ~20% of Rails-monolith PRs now auto-approved.
**Mechanism:** Trigger is a new PR opened on the Rails monolith. The agent reads the diff plus a set of structured signals: change size, which paths are touched (flagged sensitive paths get kicked to a human), whether the change sits behind a feature flag, and output from over 100 internal Claude Code skills/hooks that encode engineering patterns. If all signals pass, the agent writes an approval on the PR in GitHub and lets CI run; otherwise it hands off to a human reviewer. Session data flows to S3, skill invocations to Honeycomb, so the gate's behavior is observable. Replaces: the first-pass human reviewer for a defined slice of mechanical changes.
**Why agentic:** The agent takes a state-changing action on a GitHub PR (approval) based on reading the diff and policy context; it's not a review dashboard surfacing suggestions to a human.
**Generalizable core:** New artifact submitted for review → agent reads artifact plus codified policy signals → approve-or-escalate decision written back into the review system → human handles only the escalations.
**Deployability:** Claude Code + GitHub Actions/CI + a repo-local skills library; the policy signals (sensitivity-tagged paths, feature-flag registry, sensitive-change list) are the actual work. Rough build: a month for a small codebase to codify the rules; longer to match Intercom's 100+ skills. Replaces/augments: first-pass reviewer time. Scale caveat: Intercom runs 300–400 daily engineer users on this, but the pattern works at a much smaller size if the ruleset is narrow.

### 3. Pull-request-triggered demo video agent
**Source:** [Hyperagent on X announcing Sizzle](https://x.com/hyperagentapp/status/2118390806407000376) — Hyperagent (Airtable), launched 5 Nov 2026; running a 25-startup pilot.
**Mechanism:** Trigger is a merged (or new) PR in a connected product repo. The agent reads the PR title/description and diff, then opens the product in a controlled sandbox account using its own computer, drives the UI to exercise the new states, captures those states as screens, reconstructs selected interface states as animated scenes, and edits them into a polished marketing demo video. Output is the finished video, delivered to the team. Replaces: a marketing designer or video editor producing release/launch demos.
**Why agentic:** The agent operates the product, not a template; the content is derived from what actually changed in code, with no human-authored storyboard. A dashboard of "features that shipped this week" is a passive artifact; this ends with a file the team can post.
**Generalizable core:** Code or system change lands → agent interacts with the real product in a sandboxed identity → captures observed behavior → generates finished external-facing artifact → delivers to the owning team.
**Deployability:** Not off-the-shelf — this is Hyperagent's platform plus a non-admin sandbox product account with synthetic data, and the underlying computer-use plus rendering pipeline is non-trivial. Month-plus build if self-hosted (computer-use agent + video renderer + sandboxed test env). The sandbox-account discipline (never shared production creds) is the deployability gotcha. Replaces: release-demo creation work for product marketing.

### 4. Personal chief-of-staff agent handling approval queues and real-world actions
**Source:** [How I AI, 23 Nov 2026 episode (chatprd.ai index)](https://www.chatprd.ai/how-i-ai) — Ankit Maheshwari, CTO of Innovaccer, running OpenClaw on a Mac Mini at home.
**Mechanism:** Trigger classes are: inbound approval requests from the connected work tools (expense/PO/HR queues etc.), scheduled check-ins, and voice commands. The agent reads the request context, cross-checks policies and the user's prior decisions, then either acts (approve/deny, place a lunch order, initiate a phone call, control home devices) or surfaces the item to the user. If the user doesn't respond within a defined window, the agent interprets silence as consent and proceeds — a mechanism design choice the host flags as a caution. Writes to: approval systems, order APIs, phone/voice stack, home automation. Replaces: an executive assistant's queue-grooming and action-on-defaults work.
**Why agentic:** Multi-system, multi-modality (text, voice, physical devices), with policy-plus-history-driven decisions that end in real-world actions. A dashboard version of this would just show pending approvals.
**Generalizable core:** Inbound requests across heterogeneous systems → agent reads request plus user's policy and prior-decision history → act-or-escalate, with a time-bounded default if the user is unreachable → write action back to each originating system.
**Deployability:** OpenClaw is Mac-hosted (consumer hardware is the point); stack is a local LLM harness, MCP connectors into the target systems (approval tool, ordering, home automation, telephony). Weekend-to-week build for a narrow slice (one approval queue plus email), month-plus for the full "life OS." The silence-is-consent default is a design hazard — a safer variant surfaces time-sensitive items via push and defaults to escalate on no-response. Augments: chief of staff / EA; replaces: small-decision queue grooming.
