# 2026-10-01 — Agent Pattern Scan

## TL;DR
The most interesting shape today is Amazon Seller Assistant workflows, which exposed "standing orders" to marketplace sellers: a plain-language rule the agent executes 24/7 against seller account state, with an audit trail of every action it took. It is a general pattern — give an operator a text box, let the agent interpret the policy and run it against a live account forever — that generalizes well beyond Amazon.

## Patterns

### 1. Multi-channel intake agent that lands orders in the ERP without a form
**Source:** Choco OrderAgent + OpenAI case study — https://choco.com/us/stories/suppliers/orderagent-the-ai-order-processing-engine-thats-powering-the-future-of-food-distribution — Choco runs this across ~21,000 food distributors / 100,000 buyers and reports ~8.8M orders/year processed and ~50% reduction in manual order entry.
**Mechanism:** Trigger is a new order arriving in any format a restaurant actually uses — supplier email with a PDF attached, SMS, voicemail, phone call, photo of a handwritten pad, text message. Agent extracts line items, matches them against the distributor's product catalog, builds a structured ERP order payload, scores its own confidence, and either writes it straight into the distributor's ERP (Autopilot) or holds it in a review queue with the fields it was unsure about highlighted. Replaces the human sales-desk clerk who used to retype paper and voicemail orders into the ERP all morning.
**Why agentic:** The agent decides per-order whether to auto-post or queue, and it goes back and forth between the raw input and the catalog until the items reconcile. It is not a form that collects a schema — the schema is reconstructed from each order.
**Generalizable core:** Inbound request in any human channel/format → agent reconstructs a structured record against your catalog/entities → confidence-gated write to system of record, else to a review queue.
**Deployability:** Needs a vision/multimodal model, an entity resolver against the customer's catalog, and a write path into one ERP or CRM at a time. Weekend build for a single-SKU wholesaler on Claude + a Twilio/Gmail inbox + Airtable "review queue". A week build to add voicemail transcription and PDF parsing. Replaces or augments the order-entry clerk at any distributor, wholesaler, parts counter, or service company with a shared inbox.

### 2. Standing-order marketplace monitor the operator writes in English
**Source:** Amazon Seller Assistant workflows announcement — https://www.retailgazette.co.uk/?p=212965 — and SellerSprite breakdown — https://www.sellersprite.com/en/blog/amazon-ai-seller-assistant-agentic-2026 — launched at Amazon Accelerate on Sept 23, 2026, free across Seller Central, runs on Bedrock (Nova + Claude).
**Mechanism:** The seller writes a rule in plain English — "if a top-20 ASIN drops below 4 stars, pull the three most recent 1- and 2-star reviews, draft a response to each, flag the SKU for me, and if the issue is sizing, hide the variant until I review." The agent polls the seller account on its own cadence, and when any clause fires it reads the relevant state (reviews, prices, inventory, Buy Box status), takes the specified action (edit listing, re-price within guardrails, draft a reply, open a case), and appends every decision to an audit log the seller can scroll later.
**Why agentic:** The rule is interpreted, not compiled. The agent decides when it has enough context, which tool to call, and what to leave for the human — the same instruction can fire against different account state and produce different actions each time.
**Generalizable core:** Operator writes a standing policy in natural language → agent polls a live system of record on a schedule → when a clause fires, it reads context, acts within guardrails, and writes an audit entry.
**Deployability:** Weekend build on n8n or Make with a cron node, a Claude call, and whatever API fronts the system (Shopify, HubSpot, Square, Salesforce). The hard parts are the guardrails (price floors, action allow-lists, rate limits) and the audit log. Replaces the virtual assistant or junior ops person who used to log into the dashboard every morning and check the same ten things.

### 3. Enterprise-system change agent with scope, test, and rollback
**Source:** Assemble (YC S26) launch page — https://www.ycombinator.com/launches/RSr-assemble-agents-for-enterprise-it — agents that do dev work inside Salesforce, SAP, Workday, NetSuite, and custom apps for internal IT teams.
**Mechanism:** Trigger is a change request filed in Jira or Slack ("add a 'preferred language' field to the lead object and surface it on the account page and in the renewal report"). The agent walks the target system's metadata to find every object, flow, report, and permission that touches the change, drafts the modifications in a sandbox, runs the system's own test suite plus a generated regression check, and posts a diff for the IT lead to approve. Approved changes deploy to production; rejection or a post-deploy failure triggers a one-click rollback using the trace it captured on the way in. Replaces the Salesforce admin or NetSuite consultant who used to spend two days clicking through a dependency map before touching anything.
**Why agentic:** The agent decides which objects and flows are in scope — it is not a template. Each run produces a different plan because each enterprise instance is customized differently.
**Generalizable core:** Change request against a configurable SaaS system → agent reconstructs the dependency graph live → drafts and tests in sandbox → human approves a diff → one-click rollback via the captured trace.
**Deployability:** Month build and up — depends entirely on the target system's metadata API and sandbox story. Realistically it needs a dedicated connector per system (Salesforce Metadata API, Workday Reports-as-a-Service, SAP RFC). Role replaced: the admin/consultant backlog, not the admin themselves.

### 4. Commerce agent as the reasoning layer on top of the merchant's checkout
**Source:** Anthropic Claude Commerce Agents blueprint — https://claude.com/blog/claude-for-commerce-agents — and MarkTechPost coverage — https://www.marktechpost.com/2026/09/03/anthropic-released-claude-commerce-agents-an-apache-2-0-blueprint-for-shopping-and-merchant-agents-across-retail-travel-telecom-and-entertainment/ — open blueprint released Sept 2, 2026; integrated across Shopify, Priceline, Visa, Mastercard, with reported 35% larger baskets and 60% higher checkout completion in the pilots.
**Mechanism:** Trigger is a shopper message inside the merchant's own chat ("I need a tent for 3 people, under $400, that packs down small"). The agent calls catalog-search, personalization, and multi-item-planning skills to assemble a cart, renders products and comparisons inline in the chat, and when the shopper is ready it hands the cart to the merchant's existing checkout. The agent explicitly never holds payment credentials — its tool graph has no "charge" verb. Replaces catalog search, outbound comparison tabs, and most of the pre-sale support ticket volume.
**Why agentic:** It is a multi-step plan per conversation (search → shortlist → compare → cart → handoff), the agent remembers prior turns and prior visits, and the guardrails are architectural (no payment tool exists) rather than prompt-based.
**Generalizable core:** User intent inside the merchant's own surface → agent plans a multi-item solution against the catalog with personalization → packages the result into the merchant's existing transactional flow, no new payment surface.
**Deployability:** Week build to a prototype for any store already on Shopify or Stripe Checkout — the blueprint is Apache-2.0 and ships with a safety harness and vertical examples. Deploys on Claude API, Bedrock, Foundry, or Vertex AI. Role augmented: the pre-sale chat rep and the merchandiser; role replaced: the "related products" widget.

### 5. Continuous-capture pipes: scheduled agents that read your own screen history
**Source:** Screenpipe (Mediar, YC S26) Launch HN mirror — https://hn.nuxt.dev/item/49024620 — and DEV writeup — https://dev.to/tekmag/screenpipe-the-open-source-screen-recorder-that-gives-ai-agents-persistent-memory-of-your-work-3l2e — local-first on macOS/Windows/Linux, source-available, 400+ releases since 2024.
**Mechanism:** Screenpipe records the operator's screen (OCR + OS accessibility APIs) and microphone to a local SQLite index. "Pipes" are small agents defined in a markdown file with a schedule and a prompt — e.g. "every Friday at 4pm, read everything I did in Figma and Linear this week, draft the status update to #design-review, and open the draft in Slack." The pipe queries the local history via an MCP server, assembles the context, calls a model, and writes the output back to a tool (Slack, Notion, Linear, email). Replaces manual status write-ups, process documentation ("how do you do that again?"), and the "I had the answer in my browser tab yesterday" problem.
**Why agentic:** The trigger is not an inbound event — it is the operator's own accumulated work. The agent decides what slice of history matters for the task, and the same pipe produces different output every run because the history is different every week.
**Generalizable core:** Continuous passive capture of a worker's activity → scheduled agent queries that history for a task-specific slice → drafts output into a destination tool, operator confirms or edits.
**Deployability:** Weekend build on top of Screenpipe itself; the heavy lifting (capture, OCR, local index, MCP) is the open-source project. Caveats: local-only by design, so no multi-device or team-wide version yet, and it only sees what the person actually did on their machine — useless for roles whose work lives in other people's inboxes. Role augmented: knowledge worker who writes recurring status updates, SOPs, or handoff docs from memory.
