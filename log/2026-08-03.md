# 2026-08-03 — Agent Pattern Scan

## TL;DR
Most interesting pattern today is Frigade Skills: an in-app agent that learns a web product by clicking around it as a new user would, then executes tasks for end users through the product's own UI. It flips the "give the agent an API spec" assumption — the agent treats the app itself as the API, which makes the same pattern portable to any web app a business already owns without wiring integrations.

## Patterns

### 1. In-app agent that learns a product by using it, then acts inside it for end users
**Source:** [Frigade Skills launch, Y Combinator, June 2026](https://www.ycombinator.com/launches/RLV-frigade-skills-the-in-app-ai-agent-that-learns-your-product-and-acts-for-your-users) — SaaS product-adoption vendor releasing an agent that operates inside any customer-facing web app.
**Mechanism:** Trigger: an end user asks the in-app assistant for something in plain language ("cancel this subscription", "move all invoices from Q2 to a new folder"). Read: Frigade has already crawled the product's UI as a fake user, catalogued every reachable action into named "Skills", and had the vendor's team approve which Skills are safe to run. Act: the agent picks the Skills that satisfy the request and drives the product's own UI to execute them. Write: the actions land in the vendor's application state directly, no new API. Replaces: the user having to learn the UI, the support agent walking them through it, the onboarding tour, and — for the vendor — the roadmap slot for a "bulk action" or "one-click" feature.
**Why agentic:** The agent is discovering the product's action surface autonomously (crawling the UI without a spec) and then acting through it on live user intent. Not a chat that surfaces a help doc; it actually clicks the buttons.
**Generalizable core:** UI-native agent → learns any web app by using it → executes user asks through the same UI. Removes the "we need an API/MCP for that" prerequisite for automation projects.
**Deployability:** JS snippet plus a browser-driving runtime (Playwright or similar). Weekend prototype scale for a single-screen automation; week or two to harden approval flow and permission scoping. Replaces or shrinks front-line support, and lets small teams add "AI actions" to a product they don't own the backend of.

### 2. AI-SRE that investigates a production incident from a Slack mention
**Source:** [IncidentFox — Claude's Corner (YC W26), March 2026](https://www.startuphub.ai/ai-news/claudes-corner/2026/claudes-corner-incidentfox-yc-w2026) plus [product docs](https://incidentfox.mintlify.app/how-it-works).
**Mechanism:** Trigger: either a PagerDuty/Datadog alert fires, or an engineer types `@incidentfox investigate high latency in payments-service` in Slack. Read: the agent's Planner pulls context from ~40 connected observability and infra tools — logs (Datadog), pod state (Kubernetes), recent deployments (GitHub / Argo), cloud events (AWS), similar past incidents. Act: the Planner delegates to specialised sub-agents (K8s troubleshooter, AWS debugger, anomaly detector) and synthesises their findings into a root-cause narrative with a suggested remediation. Write: replies in-thread in Slack with the diagnosis plus a proposed fix; the human on-call approves before any state-changing action runs. Replaces: the first hour of a human SRE's incident triage — the "gather logs, check the diff, look at the last deploy, check the dashboard" tour that on-calls do at 3 a.m. before they know what's actually wrong.
**Why agentic:** Multi-tool investigative loop that plans, delegates, and iterates rather than showing a single dashboard. The Slack mention is a natural-language work item, not a form.
**Generalizable core:** Alert or @-mention in the team's channel → agent assembles context from every connected system → posts a diagnosis and proposed action back in-thread → human approves execution. This shape works for any "something is broken, someone needs to figure out why" workflow (customer complaint triage, failed batch job, revenue anomaly).
**Deployability:** Claude Agent SDK plus MCP connectors for each data source; a Slack bot as the front door. Week-to-month build to wire the connector set and prompt the sub-agents; the core loop is copyable at any scale. Replaces the first-responder investigation phase of an on-call role; the human still owns the fix decision.

### 3. Bug-triage harness that turns a Sentry error into a filed ticket with a reproduction
**Source:** [ChatPRD blog — Claire Vo on the custom Claude Agent SDK harness](https://www.chatprd.ai/how-i-ai/how-i-built-a-custom-ai-harness) and [Lenny's Newsletter, July 2026](https://www.lennysnewsletter.com/p/what-a-harness-is-and-how-to-build).
**Mechanism:** Trigger: a new (or newly-frequent) error fires in Sentry for ChatPRD, Claire Vo's PM-tooling SaaS. Read: the agent uses opinionated adapters over the Claude Agent SDK to pull the Sentry event (stack trace, user context, breadcrumb trail), the relevant code from GitHub, related Linear tickets, and Vercel deployment history to identify which release introduced the regression. Act: it runs a root-cause analysis loop, drafts a reproduction, and produces a Linear ticket already populated with a suggested fix location and priority. Write: a Linear issue linked back to the Sentry event and the GitHub commit range. Replaces: the founder/on-call engineer's manual "look at Sentry, correlate to the deploy, guess the file, open a ticket" chore that happens after every error spike.
**Why agentic:** It's a scoped harness — permissions encoded, tools whitelisted, a specific end-state artifact (a well-formed ticket). It investigates and writes a durable artifact, not a dashboard summary.
**Generalizable core:** Structured event in system A → agent assembles cross-system evidence → produces a filed, actionable artifact in system B. Same shape works for support ticket triage, sales-lead qualification, or contract review — pick a boundary event, pick an artifact.
**Deployability:** Claude Agent SDK + MCP connectors for Sentry, Linear, GitHub, Vercel; Ink for the terminal UX if you want interactive review. A weekend build for a solo operator willing to hardcode their stack; a week to make it reusable. Replaces a chunk of the first-response engineer's day at any small SaaS.

### 4. Per-channel performance agents that turn campaign data into approval-ready actions
**Source:** JAKALA Claude case study (April 2026), via [The Neuron writeup](https://www.theneuron.ai/newsletter/how-spotify-runs-claude-across-20m-lines-of-code/) and multiple third-party summaries. JAKALA is a European marketing/data-consulting firm running media for global brands.
**Mechanism:** Trigger: continuous — new performance data lands in the client's ad accounts (Google, Meta, TikTok, programmatic DSPs). Read: each specialist agent (search, shopping, programmatic, social, creative diagnostics, incrementality) connects via MCP to its assigned ad platform and to JAKALA's internal geo-intelligence engine, joining spend and outcome data. Act: each agent flags anomalies against its own baseline and proposes concrete actions — bid changes, audience shifts, creative rotations, budget reallocations. Write: proposals route into a human "pod" queue for review, approval, and push-to-platform. Replaces: the 40–60% of a senior planner's week spent assembling reports, cross-referencing spreadsheets, and stress-testing hypotheses before they made a call.
**Why agentic:** Each sub-agent has a specialist scope, a defined action space, and produces an approvable proposal rather than a chart. The human's job compresses to "approve or edit", not "figure out what to look at".
**Generalizable core:** Continuous stream of domain data → per-channel specialist agent → flag + propose action → human approves in a queue → action pushed to source system. Same skeleton fits inventory reordering across suppliers, ops KPI review across store locations, or portfolio management across positions.
**Deployability:** Claude Agent SDK + one MCP connector per channel + an approval-queue UI (Slack, Linear, custom Next.js). Enterprise-scale as JAKALA runs it, but a two-channel version is a week's build for an SMB agency running Meta + Google for one client. Replaces the report-assembly half of an analyst or planner role; the recommendation half stays human until trust builds.

### 5. Coding agent triggered from Slack that iterates in a sandbox until CI is green
**Source:** [Spotify Engineering — Honk (Code with Claude), June 2026](https://engineering.atspotify.com/2026/6/code-with-claude-coding-is-no-longer-the-constraint), summarised at [The Neuron](https://www.theneuron.ai/newsletter/how-spotify-runs-claude-across-20m-lines-of-code/) and [ZenML LLMOps DB](https://www.zenml.io/llmops-database/scaling-ai-driven-code-automation-and-engineering-productivity-at-spotify). *Related to but distinct from 2026-05-15 entry #2 (Ink deployment agent) — that pattern provisioned infrastructure; this one authors code and verifies it against real builds.*
**Mechanism:** Trigger: engineer messages an internal Slack bot with a task ("bump this dependency across services X, Y, Z", "implement this Figma frame"). Read: repo state, Figma export, CI logs, iOS simulator screenshots, whatever internal tools the requesting team has exposed. Act: the Claude Agent SDK session spins up in a per-request Kubernetes pod with restricted permissions, edits the code, runs verification builds on Linux and macOS, iterates on failures, and only opens a PR when its own CI is green. Write: a GitHub PR plus a Slack thread with the state history; contributed to 1,500+ merged PRs across a 20M-line codebase. Replaces: the first-draft implementation pass a mid-level engineer would have done manually.
**Why agentic:** Verification tool is inside the loop — the agent doesn't just write code, it tries to compile/test and self-corrects. That's the difference between "AI code generation" and "autonomous coder".
**Generalizable core:** Natural-language work item → sandboxed, ephemeral agent runtime → verify-in-the-loop with the same tools a human would use → produces a reviewable artifact. The pattern transfers to any workflow with a fast, cheap ground-truth check (linter, unit test, dry-run API call, staging DB query).
**Deployability:** Anthropic's Claude Agent SDK is the same primitive Spotify built on; a small-team version fits in a single VM or a Fly.io micro-VM rather than a K8s cluster. The hard part isn't the agent — it's the sandbox and the tool-permission set. Weeks-to-months to build a production-safe harness; the payoff scales with how repetitive the "first draft" work is. Enterprise scale documented; the pattern is applicable at any team size.
