# 2026-07-22 — Agent Pattern Scan

## TL;DR
Deliverect's April 2026 KFC Netherlands pilot is the standout: an agent designed, launched, and optimized a promotional offer with no human touch and lifted one-day sales 118%. The reusable core — read live demand + capacity signals, decide which segment gets which offer right now, push it out through the ordering surface — turns "marketing calendar" from a weekly meeting into an event-driven loop.

## Patterns

### 1. Autonomous promo agent that decides offers from live capacity and order signals
**Source:** Deliverect debuts AI agents after KFC pilot boosts sales 118% (https://completeaitraining.com/news/deliverect-debuts-ai-agents-for-restaurants-after-kfc-pilot/) — Deliverect launched its "AI workforce" in April 2026 after a KFC Netherlands pilot where an agent ran a promotion end-to-end and lifted sales 118% in a single day; the layer sits on top of Deliverect's order/menu integrations and uses n8n for the workflow substrate.
**Mechanism:** Trigger is a rolling window over live order volume, kitchen capacity, day-part, and CRM segment membership. The agent reads current throughput + segment history, decides which cohort gets which offer at what price, writes the promo to the menu/ordering system across delivery platforms, then reads back conversion data and revises. Replaces the weekly promo-planning meeting and the agency loop that used to design and A/B test each campaign.
**Why agentic:** Not a dashboard telling a marketer "sales are soft at 2pm" — the agent picks a specific offer for a specific segment and ships it, then adjusts based on what happened. Decision plus action plus learning inside one loop.
**Generalizable core:** Live throughput/capacity signal crosses a threshold → agent reads customer/segment history → picks an intervention from a bounded catalog → pushes it to the customer-facing surface → measures response and adjusts. Works anywhere a business has a customer-visible catalog it could re-price or re-merchandise in real time (e-com, subscription, hospitality, ticketing, ride-share).
**Deployability:** n8n-hosted workflows plus an LLM decision node plus API writes to the merchandising system. Multi-week build if you already have clean order/segment feeds; multi-month if the segment data lives in five places. Replaces marketing coordinator work and outside creative-agency retainer for tactical promos. Depends on having a customer-facing surface you can actually re-configure on the fly — brands stuck behind long CMS lead times will struggle.

### 2. SOC triage agent that opens the case, calls the right expert, and re-runs the feed check every 5 minutes
**Source:** n8n Vodafone case study coverage — 33 workflows in production (https://addrom.com/revolutionizing-cyber-defense-how-vodafone-achieved-2-2m-savings-with-n8n-cybersecurity-automation/) — Vodafone Cyber Defence's pipeline of 33 n8n workflows and many sub-workflows, active since August 2024, delivering £2.2M cost avoidance and 5,000 person-days saved (roughly £300K/month ongoing). Enterprise scale but the mechanism carries down.
**Mechanism:** Trigger 1 is a new alert landing in the intake queue → agent immediately marks the case as "in progress" in Cabana (their case tool), enriches it with related telemetry, identifies the right SME from a routing table, drafts and sends the outreach email, and parks the case pending human decision. Trigger 2 is a schedule: a feed-health workflow that would take an analyst 10 minutes per feed now runs every 5 minutes across all feeds and only opens an incident on drift. Replaces L1 SOC analyst triage plus the daily feed-health round.
**Why agentic:** Every alert becomes a case that's already been enriched, labeled, and routed to a named human — the agent is doing the analyst's first pass, not showing a dashboard for a human to work off.
**Generalizable core:** Inbound event lands in queue → agent stamps state + enriches context → looks up the right owner → drafts the handoff message → escalates only what needs a human. Plus a paired scheduled sweep that turns "someone should check X daily" into "the agent checks X every 5 minutes and only pings on drift." The paired pattern (event trigger + scheduled sweep) is the reusable idea, not the security use case.
**Deployability:** n8n plus an LLM node plus a routing table plus write access to the case system. A single workflow of this shape is a week of build. The Vodafone shape (33 workflows sharing sub-workflows) is a multi-month program. Replaces triage-tier analyst headcount; the cost bar depends on having a case system with an API.

### 3. Estimating agent that reads photos, drawings, and site videos and returns a priced proposal
**Source:** Handoff launches AI agent for instant construction estimating from drawings, photos, and more (https://www.wjhl.com/business/press-releases/ein-presswire/829126233/handoff-launches-new-ai-agent-for-instant-construction-estimating-from-drawings-photos-and-more/) — YC-backed Handoff, targeting remodelers and general contractors; early customers report proposal turnaround dropping from hours to minutes.
**Mechanism:** Trigger is a file drop into a chat thread — drawings, site photos, or walkthrough videos. Agent runs computer-vision takeoff (component detection, dimensions, material counts), joins against a localized construction-cost database, produces a priced scope, and writes it out as an estimate, proposal, change order, or invoice depending on where the project is. Writes into Handoff's own record system and generates a ready-to-send document. Replaces the junior estimator's manual takeoff plus the office admin's proposal formatting.
**Why agentic:** Not "AI reads the PDF and shows highlights" — the agent picks the artifact type (estimate vs proposal vs change order) from where the project stands, prices the whole scope, and produces a document ready to send. One request, one artifact out.
**Generalizable core:** Multi-modal artifact arrives (PDF/photo/video) → agent extracts structured entities → joins to a priced/localized reference table → composes a bounded document at the correct stage of the workflow → writes it back where the recipient expects it. Any bid/proposal/quote business with a well-defined pricing catalog and a document template fits (roofing, landscaping, HVAC install, cabinetry, print, custom apparel).
**Deployability:** The hard parts are the reference pricing DB and the takeoff accuracy — not the LLM. Weekend build if you can borrow a pricing feed; multi-month if you're standing up your own. Replaces junior estimator hours and shortens sales cycles. Requires enough historical bid data or a licensable cost DB to price accurately; solo operators without one will hit ceilings.

### 4. Two-agent shared-profile loop where every interaction updates the substrate the other reads
**Source:** Klaviyo launches Composer and Customer Agent as paired agents (https://www.klaviyo.com/newsroom/CRM-agents) — public beta announced June 30, 2026. Both agents write to and read from the same real-time customer profile inside Klaviyo's CRM.
**Mechanism:** Customer Agent is triggered by an inbound conversation on any surface (web chat, email, SMS, WhatsApp) — it resolves the request, and as part of resolution writes preferences, product interests, and intent signals back to the customer profile. Composer is triggered by a campaign moment (send window, event, cohort change) — it reads the updated profile, picks a segment, drafts the campaign, and launches. The next inbound conversation lands on Customer Agent with the campaign context already on the profile.
**Why agentic:** Two agents, no orchestrator, no message bus — coordination happens because both write to and read from the same customer record. Each interaction changes the substrate the other agent reads from on its next tick.
**Generalizable core:** Shared canonical record as coordination surface. Agent A does work → mutates record → Agent B triggered later reads mutated record → does downstream work → mutates it further. No inter-agent messaging needed. Works anywhere two functions share a customer/asset/case object (support + billing, ops + finance, dispatch + service).
**Deployability:** If you're on Klaviyo, this is a config task. Rolling your own is a multi-week build: define the canonical record schema, decide which fields each agent may write, add lightweight write locking, and stand up both loops. The interesting piece is the pattern, not the tool. Replaces internal handoff meetings and the "sync between marketing and support" role. Caveat: needs a real single source of truth for the customer record — multi-system shops with copied CRM data will not get clean coordination.

### 5. Dispatch triage agent that auto-assigns routine jobs and only escalates exceptions
**Source:** AI Dispatching in 2026 (Teambridge) (https://www.teambridge.com/blog/ai-dispatching-2026-manual-scheduling-boards-done) and Symphona field service use cases (https://www.simplyask.ai/blog/top-10-ai-agent-use-cases-for-field-service-operations-in-2026) — sector-wide pattern in HVAC, plumbing, and telecom field service; dispatcher-to-technician ratios reportedly moving from 1:8 to 1:20+ where deployed, ~3 hours/day of dispatcher time reclaimed.
**Mechanism:** Trigger is a new work order dropping into the queue (from a call, form, or upstream system) or a live change event (technician callout, traffic delay, SLA clock). Agent reads technician availability, skills, current route, SLA constraints, and location; assigns the job or re-sequences the route; sends the customer confirmation; and writes the assignment back to the FSM system. Only escalates to a human dispatcher on defined exceptions — callouts, emergencies, jobs outside standard parameters, or ambiguous scope.
**Why agentic:** The agent is doing the assignment, not surfacing options to a dispatcher who then clicks. The dispatcher only sees the queue when it's actually a judgment call.
**Generalizable core:** Inbound work item → agent reads a bounded pool of resources (people, slots, assets) → matches on constraints → commits the assignment → escalates only defined exceptions. Any resource-matching queue with clear rules fits: legal intake to attorneys, insurance claims to adjusters, patient triage to specialists, hardware repair to techs.
**Deployability:** A week of build on top of an FSM system with a decent API (ServiceTitan, Housecall Pro, Jobber). Replaces most of a dispatcher's assignment work. Real gating factor is exception definition — if you can't cleanly enumerate "when to escalate," the agent either over-escalates and delivers no value or under-escalates and creates messes.
