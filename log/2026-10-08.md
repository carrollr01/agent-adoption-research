# 2026-10-08 — Agent Pattern Scan

## TL;DR
Three qualifying patterns today. The strongest is AppFolio Realm-X Maintenance Performer, which turns a tenant photo into a diagnosed, prioritized, vendor-dispatched work order with a short clarifying dialogue in between — a multimodal, action-taking intake agent sitting inside the vertical SaaS that already holds the data. Also qualifying: Avoca's multi-brand voice front office rollout at Sila Services (acquisition-driven standardization of inbound AI inside ServiceTitan), and Gong's native call-transcript follow-up email agent (now a built-in Assistant skill rather than a glue-code workflow).

## Patterns

### 1. Image-triaged maintenance intake agent inside the vertical SaaS

**Source:** [AppFolio Realm-X Maintenance Performer demo page](https://www.appfolio.com/product-demos/realm-x-performers) and [HousingWire coverage of AppFolio's Realm-X agents](https://housingwire.com/articles/appfolio-enhances-ai-property-management-tools) — property-management platform rolling out an agent that handles resident maintenance requests end-to-end as a native Realm-X Flows component, running across AppFolio's installed property manager base.

**Mechanism:** Resident submits a maintenance request (text + photo) through the AppFolio resident portal → agent reads the message, runs image recognition on the photo to identify the issue type, and asks clarifying questions in a short conversation, walking the resident through simple fixes before escalating → if it still needs a technician, the agent writes a work order, classifies urgency against the property manager's emergency rules, picks the right vendor by issue type / severity / time of day, and texts them directly from the work order record → logs a summary and keeps the human property manager in supervising view.

**Why agentic:** It is not a form that creates a ticket. The agent takes multimodal input (free-text + image), carries on a diagnostic conversation, decides whether a human technician is needed, picks the vendor, and dispatches — all actions, not displays.

**Generalizable core:** Inbound request with photo/attachment in any channel → agent diagnoses from image + text, asks clarifying questions, triages against rules → routes to the right third-party / takes a bounded action → writes back to the system of record.

**Deployability:** Native inside AppFolio Realm-X Flows, no custom build. Equivalents outside property management are a week-to-month build: Twilio or Front for intake, Claude or GPT-4o for vision + dialogue, a vendor/contractor directory with routing rules, and the vertical SaaS API (Jobber for home services, Dentrix for clinics, Toast for restaurants). Replaces the front-office person who reads a photo of a leaking sink or broken oven, decides whether to send someone, and makes the dispatch call. Scale caveat: image-recognition quality on amateur photos still misses, so the emergency-rule rails and the "walk them through simple fixes first" step are load-bearing.

### 2. Acquisition-rollout voice front office inside the trade's ERP

**Source:** [Avoca's Sila Services customer page](https://www.avoca.ai/customers/sila-services) and [casestudies.com writeup of the same deployment](https://www.casestudies.com/company/avoca/case-study/sila-services-handles-130000-calls-per-quarter-with-avoca) — Sila Services, a multi-brand HVAC / plumbing / electrical holding company that grows through acquisition, running Avoca's voice AI as its standard front office across 40+ brands. Reported: 130,000+ quarterly calls, 22% of total revenue booked by the AI, transfer rate under 10%. Figures are vendor-reported.

**Mechanism:** Inbound call to any Sila-owned brand's main number → Avoca answers 24/7, reads the brand-specific playbook configured during that brand's rollout and ServiceTitan's Adjustable Capacity Planning calendar to know what capacity is open, asks the caller the right questions for the service line → books the job directly into ServiceTitan with the right job type, duration, and tech bucket → hands off the small residual (<10%) to a human CSR with context attached.

**Why agentic:** The repeating unit of value isn't the receptionist bot — it's the acquisition rollout mechanism. Each new brand plugs into a shared agent configured to its own standards: Sila's "AI configuration playbook" standardizes a formerly weeks-long onboarding of each new brand's CSR team into a few days of agent fine-tuning.

**Generalizable core:** Acquirer owns a shared agent configured per-brand → each acquisition's inbound traffic (calls / forms / web chat) routes through the brand-tagged configuration → bookings and transactions write to the acquirer's common operational system → replaces the per-acquisition CSR onboarding and standardization cost.

**Deployability:** For a multi-location SMB rollup, this is Avoca-like voice stack (Twilio or Retell + Claude/GPT + vertical SaaS API) plus a brand-tagged configuration layer. Variation of the voice phone-number agent pattern logged 2026-05-24 — new angle is the acquisition-standardization use case, where the AI is the operational glue that makes "add-on acquisitions" cheap because front-office consolidation is now a config change rather than a staffing project. Replaces the brand-level operations manager who typically owns post-close integration of phone and dispatch. Scale caveat: ServiceTitan-native, so the mechanism copies cleanly to any vertical SaaS that holds the schedule (DaySmart for salons, PetDesk for vet clinics, Dentrix for dental DSOs).

### 3. Native call-transcript follow-up email agent inside the conversation-intelligence tool

**Source:** [Gong Assistant agent docs](https://help.gong.io/docs/agent-use-case-and-examples) — Gong's follow-up email agent now ships as a native Assistant skill on every plan as of July 2026, replacing the Zapier-plus-Claude glue workflow that reps and ops teams were running up to that point.

**Mechanism:** Call ends → Gong ingests the transcript and already has it tied to the account/opportunity in HubSpot or Salesforce → the agent reads the transcript for topics discussed, agreed next steps, and commitments the rep made → produces a draft follow-up email following the rep's instructions (tone, template, which commitments to call out) → draft lands in the rep's email client for review and send.

**Why agentic:** It is reusable prompts that run on each call rather than a one-off summary. The agent reads the specific commitments and action items a human rep made in the conversation, and writes a draft tied to those commitments — not a generic recap.

**Generalizable core:** Event ends (call, meeting, visit) → agent reads structured context (transcript + CRM record) → drafts the follow-up communication that reflects what was actually said and agreed → human reviews and sends.

**Deployability:** For a non-Gong shop, this is a weekend-to-week build: a call recorder with transcript export (Fathom, Fireflies, or a Twilio-recorded Zoom), Claude API, and a Gmail or Outlook draft creator. Replaces the rep's post-call write-up. Scale caveat: works well for SMB sales teams because the main cost is call-recording minutes, not model tokens. The pattern copies into any field or client-visit workflow where the "visit" is recorded or transcribed — dental hygiene appointments logged in the practice management system, home-health aide visits recorded for care coordination notes, consultant client calls that need next-step emails to multiple stakeholders.
