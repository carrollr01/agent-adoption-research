# 2026-10-14 — Agent Pattern Scan

## TL;DR
Most interesting today: an AmLaw 100 firm's monthly compensation memo run (via Athena) now generates and distributes all 400 memos overnight with zero manual intervention, including the two-person verification step. The pattern — scheduled trigger drives a system-prompt-defined workflow that produces personalized documents and routes them to a system of record — generalizes well beyond legal to any recurring, templated, cross-record document distribution.

## Patterns

### 1. Overnight scheduled batch of personalized documents, distributed end-to-end
**Source:** [Athena case study](https://claude.com/customers/athena) — AmLaw 100 law firm compensation cycle; Athena reports 10,000+ autonomous workflows per week across customers, 100,000+ output assets per month.
**Mechanism:** Monthly cron trigger (overnight run) → agent reads prior-cycle Excel sources and firm-specific compensation rules encoded as natural-language system prompts → generates all 400 individualized compensation memos → distributes each to the correct partner's secure SharePoint folder → absorbs the former two-person verification step via Claude explaining its reasoning per memo for audit. Replaces: Excel-macro operators, manual PDF generation and upload, and the human verification pair that previously signed off every cycle.
**Why agentic:** Not a template-fill. The run reasons across the comp model's edge cases per partner (origination credits, carry-forwards, dispute flags), produces a bespoke document, and routes it correctly without a human in the loop that cycle.
**Generalizable core:** Scheduled trigger → agent reads firm-specific rules + per-record data → generates one bespoke document per record → writes to the correct per-record destination with built-in audit trail.
**Deployability:** Claude API with Athena's workflow runtime, or Claude Agent SDK + MCP connectors to SharePoint and the source system; week-to-month build for the first cycle, including the test harness. Replaces 1–2 operations roles per cycle plus the verification time of two seniors. Caveat: works because the firm's rule set is stable and the output goes to internal recipients; opens an audit question for externally-facing analogs.

### 2. Threshold-tiered autonomous resume screening with real-time ATS writeback
**Source:** [GoPerfect Inbound Screening](https://www.goperfect.com/inbound-screening) — vendor product deployed into Greenhouse, Lever, Workday pipelines; vendor-reported, not independently measured.
**Mechanism:** New applicant lands in the ATS → agent reads job description, resume, and screening rubric → scores 1–5 with written reasoning → routes by band: >4.0 auto-advanced, <3.0 auto-declined with a personalized reply explaining fit gaps, 3.0–4.0 held in a "needs human" queue → writes score, disposition, and reasoning back to the ATS in real time. Thresholds and the rubric are role-adjustable.
**Why agentic:** The agent takes an irreversible outbound action (the decline email) on its own in the low band, not merely surfacing a ranked list for the recruiter.
**Generalizable core:** Inbound record in queue → agent scores against role-specific rubric with reasoning → three-way route (auto-act / auto-reject / human) → write disposition back to source system.
**Deployability:** Claude API + ATS webhooks (Greenhouse/Lever REST, Workday Studio) + a prompt that encodes the hiring rubric; weekend to week build. Replaces: 60–80% of first-pass recruiter screening time. Caveats: EEOC/EU AI Act exposure on auto-decline paths — the auto-reply content and audit trail become the compliance artifact, not an afterthought. Build the explainability log alongside the first prompt, not after.

### 3. Jobsite photo arrival triggers milestone verification and safety observation agent
**Source:** [Procore Photo Analyst Agent](https://www.procore.com/ai/agents/photo-analyst) ([2026-10-15 Groundbreak release notes](https://www.businesswire.com/news/home/20251015796723/en/Procore-Advances-the-Future-of-Construction-with-New-AI-Innovations-at-Groundbreak-2025)) — productized agent inside Procore.
**Mechanism:** Field worker uploads daily photos from the mobile app → agent reads the images against the project's active schedule and spec library → compares installed state against scheduled milestone → runs a defect/safety classifier (non-compliant installation, unsafe field conditions, missing PPE) → writes two things back into Procore: a milestone completion update and a corrective-action observation assigned to the responsible sub. Replaces: superintendent walkthrough and the end-of-day photo review that normally happens hours later.
**Why agentic:** It opens tickets. The output isn't a chart of "percent complete" — it's a work item in the daily log that reroutes the next day's crew assignment.
**Generalizable core:** New media artifact arrives → agent reads it against a structured reference (schedule, SOP, policy, inventory list) → classifies deviation → creates a work item in the system of record assigned to the responsible owner.
**Deployability:** Procore customers get it as a native product; equivalent custom build with Claude + vision + a schedule/spec corpus is a 2–4 week project. Replaces/augments: superintendent and project engineer review passes. Scale caveat: Procore's version requires their project data model and schedule structure to work; standalone builds need the project schedule machine-readable somewhere.

### 4. Multi-channel escalation ladder for recurring customer outreach
**Source:** [Enterprise DNA — veterinary recall workflow](https://enterprisedna.co/resources/insights/medical-agentic-ai-healthcare-workflow-redesign), [Provet agentic PIMS](https://www.provet.com/blog/agentic-ai-veterinary-software) — veterinary practice management stack; vendor-sourced.
**Mechanism:** Daily job scans practice management system → agent reads each pet's protocol and visit history → identifies overdue items (vaccines, follow-ups, med refills) → chooses contact channel per owner's historical responsiveness, defaulting to SMS → sends personalized message referencing the specific pet by name and the specific overdue item → on no response within configured window, escalates to email → still no response, escalates to a scheduled live call (or a voice agent call where allowed) → logs every attempt and outcome back to the PIMS record. Provet variant keeps a human approval step for the first message; mature deployments remove it.
**Why agentic:** The channel decision is dynamic per owner based on past response data, and the escalation ladder progresses on its own — nobody manually triages the "haven't responded in 5 days" bucket.
**Generalizable core:** Scheduled sweep of a system of record → agent builds a per-recipient outreach plan from history → walks a cost-tiered channel ladder with auto-escalation on silence → logs every step back to the record.
**Deployability:** Claude API + PMS/CRM API + Twilio for SMS/voice + an email provider; week build. Replaces: the recall/retention coordinator role in a mid-size practice. Pattern applies verbatim to dental hygiene recalls, auto service reminders, HVAC maintenance plans, SaaS renewal nudges, and donor retention — anywhere a scheduled relationship touch gets missed because nobody owns the follow-up ladder.

### 5. Autonomous payer phone calls with IVR navigation for medical billing status
**Source:** [SuperDial — healthcare AI agents](https://www.superdial.com/reference/best-ai-agents-for-healthcare) — RCM/revenue cycle teams in medical billing; vendor-sourced, production.
**Mechanism:** RCM worklist flags a claim that needs status (aged N days, denial received, prior auth pending) → agent dials the payer's provider line → navigates the IVR tree (member ID, DOB, claim ID, tax ID) → waits on hold → asks the human agent for claim status in a scripted conversation → extracts the disposition (paid, denied, pending, additional info required, reprocess) → writes a status note into the practice management system and reroutes the claim to the appropriate internal queue (appeal, correct and resubmit, patient balance). Replaces: billing specialists making 20–40 payer calls per day with 30–60 minutes of hold time each.
**Why agentic:** The agent conducts a real phone conversation with an insurance company rep, including navigating voice menus and extracting structured data from unstructured speech, then writes the business outcome to the system of record.
**Generalizable core:** Record flagged for external status check → agent initiates outbound voice call → navigates external IVR/human conversation → extracts a structured outcome → writes it back and routes the record to the next-stage queue.
**Deployability:** Voice stack (Vapi, Retell, Bland, or Twilio Voice + Claude) + the practice management API + a payer-specific script library; month build per payer family. Replaces: the "status check" rung of the billing team. Caveats: HIPAA posture required; some payers block automated callers and require pivot to portal scraping; call recording consent varies by state. The ladder of value climbs beyond healthcare — carrier-contacting agents fit freight dispatch, insurance subrogation, utility outage calls, warranty claim status.
