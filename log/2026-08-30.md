# 2026-08-30 — Agent Pattern Scan

## TL;DR
Three concrete patterns worth logging: a case-lifecycle state machine that drives multi-party outbound calls and SMS in personal injury law, a consumer finance agent that negotiates on the user's behalf over text and adds every solved edge case to a shared self-improving library, and a solo consultant who replaced her proposal deck and CRM with interactive HTML artifacts generated by Claude on new-prospect events. The PI legal pattern is the most interesting today because the trigger is not a message or a threshold but a state transition inside a domain-specific process graph.

## Patterns

### 1. Case-lifecycle state machine driving multi-party outbound comms (PI law)
**Source:** [EvenUp Communication Agents](https://www.evenuplaw.com/blog/communications-agents-eliminate-admin-work/) — voice and SMS agents deployed inside personal injury firms; reclaim 9+ hours per case across active caseloads.
**Mechanism:** Trigger is a state transition in the firm's case management system (case opened, treatment started, records requested, pre-settlement). On each transition the agent picks the correct outbound job — open the insurance claim with the carrier, confirm liability and coverage, check in on the client's treatment progress, chase medical providers for records, verify medical provider balances before settlement — then places calls or sends SMS to the right counterparty for that stage, and writes transcripts, summaries, and alerts back to the case file. What it replaces: the paralegal or case manager who otherwise sits on hold to insurance carriers and medical offices for hours per case.
**Why agentic:** The agent is not answering an inbound call or firing a scheduled blast. It's reading where each case is in the process, deciding which counterparty to contact for that stage, holding a real conversation with that counterparty, and updating case state based on what came back — a different job at each stage, not one job on repeat.
**Generalizable core:** State transition in a process-of-record system → agent picks the stage-appropriate outbound job → holds voice or SMS conversation with the right external party → writes structured result back to the record. Works for any domain with a well-defined case, matter, or job lifecycle (insurance claims, healthcare prior-auth, construction jobs from bid through closeout, immigration filings, warranty claims).
**Deployability:** Twilio for voice and SMS, an MCP or API connector into the practice-management system that owns case state, Claude for stage-appropriate script selection and transcription analysis. Week to month build for a vertical-specific version; the hard work is enumerating stages and defining what "counterparty contacted successfully" writes back. Replaces or augments paralegals, case managers, or coordinators. Scale caveat: relies on a system-of-record whose state transitions can be watched — firms still running on shared spreadsheets need that plumbing first.

### 2. Consumer-facing negotiation agent with a self-improving edge-case library
**Source:** [Rocket Money's Rowan](https://www.rocketcompanies.com/press-release/rocket-moneys-rowan-rewrites-what-ai-can-do-in-personal-finance/) — Claude-powered agent monitoring live bank data for millions of Rocket Money users, launched with a customer story on Anthropic's site the same week.
**Mechanism:** The agent watches linked bank and card feeds continuously. When it spots a savings signal — a recurring bill that could be renegotiated, an unused subscription, cash sitting idle — it sends the user an SMS proposing a specific action. The user replies in plain language and the agent executes: calls or web-forms the biller to negotiate a lower rate, walks the cancellation flow for the subscription, moves money into savings. Where it hits a cancellation flow it hasn't seen (a hidden retention step, a captcha, a phone-only path), it diagnoses the obstacle, solves it once, and adds the solution to a shared library so the next user with that same provider gets the fixed flow automatically.
**Why agentic:** Two layers. The user-facing layer is trigger-and-act on transaction data, not a dashboard showing spend categories. The infra layer treats each edge case as a durable knowledge write — the agent modifies itself as it works, so every solved cancellation becomes a permanent capability for everyone.
**Generalizable core:** Continuous data stream watched for opportunity signals → agent SMS-proposes a specific action → user approves in plain language → agent executes the action against external systems on the user's behalf → any unfamiliar path the agent solves is written back to a shared solution store so the whole fleet inherits it. The self-improving edge-case library is the reusable idea: any agent that touches unpredictable external UIs (portals, phone trees, insurance sites, government forms) can be built this way.
**Deployability:** Consumer-scale banking connections (Plaid or equivalent) and voice/browser automation for the negotiation side are the moat, so the full pattern needs real engineering headcount. The shared-solution-library pattern by itself is a weekend to a week to bolt onto an existing agent using any store (a JSON file, a vector DB, an MCP server) — replaces the developer who otherwise hand-codes every new edge case. Scale caveat: the library only earns its keep with enough throughput to hit the same edge cases repeatedly; a two-user agent doesn't benefit.

### 3. Interactive HTML artifacts replacing PDFs and CRM screens for a solo consultant
**Source:** [Grace Clarke on How I AI](https://www.chatprd.ai/how-i-ai/claude-workflows-for-business-automation-and-managing-gmail) — solo consultant who cut 20 hours a week of admin by rebuilding her proposal, pipeline, and inbox tooling in Claude Code.
**Mechanism:** New-prospect event (a discovery call transcript, an intake form) triggers her "Pipeline Operator." The agent reads the prospect context, the offer catalog, and prior-engagement notes, then generates a live interactive HTML proposal — not a PDF, not a slide deck — that the prospect can navigate, price out, and select from. When the prospect interacts with the proposal, the pipeline state updates in a custom inbox/pipeline app she also built with Claude, which replaces both the generic CRM and Gmail. Onboarding materials for accepted proposals are generated the same way.
**Why agentic:** The proposal itself is generated per prospect from context, and the pipeline state is a byproduct of prospect interaction with that generated artifact rather than a dashboard she updates manually. The agent produces a new tool per engagement, not a template fill.
**Generalizable core:** Inbound intent signal → agent assembles context → agent generates a purpose-built interactive artifact for that specific counterparty → counterparty's interaction with the artifact writes state back into the owner's system → the owner never re-keys any of it. Applies to sales proposals, patient intake, RFP responses, custom quotes, product configurators, personalized onboarding — anywhere a static document or dashboard is currently doing a job an interactive artifact could do better.
**Deployability:** Claude Code plus a lightweight backend (any Node/Next.js or even a static host) for the generated pages plus a data store the artifacts write into. Weekend to a week for a single-workflow version; a solo operator can genuinely build this. Replaces or augments the small business owner's proposal writer, admin, and CRM subscription. Directly relevant to A3 Dev's own posture — this is a working example of an owner-operator swapping dashboards for generated interactive artifacts and doing it themselves.
