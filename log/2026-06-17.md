# 2026-06-17 — Agent Pattern Scan

## TL;DR
Three concrete patterns today. The standout: a parent built a Claude Cowork agent that uses her own Gmail archive as the context store, so when she decides to return a product the agent finds the receipt, reads the retailer's policy, drafts the request, and submits it. The same "personal-inbox-as-knowledge-base" mechanism is the part worth stealing for any SMB.

## Patterns

### 1. Inbox-as-context returns agent
**Source:** [How I AI, episode with Nicole Ruiz, June 11, 2026](https://podcasts.apple.com/us/podcast/how-i-ai/id1809663079) and Ruiz's [Substack writeup on Lenny's newsletter](https://www.lennysnewsletter.com/p/shopping-with-claude) — a writer/parent built a household-grade Claude Cowork system covering brand vetting, budget tracking, and full returns automation.
**Mechanism:** Human says "return this." Agent searches Gmail for the matching order confirmation and receipt, pulls the order ID, total, and date, fetches the retailer's return policy from its trusted-vendors project, drafts the refund request (or fills the retailer's web form), then submits and files the confirmation back into a tracking project. Replaces the 15-30 minute drudge of digging through inbox threads and filling identical return forms across a dozen retailers.
**Why agentic:** The trigger and authoritative state both live in unstructured email. There is no dashboard to look at; the agent has to read, decide which order matches, navigate a different return UX per retailer, and act. The human only confirms.
**Generalizable core:** Outbound action request → agent assembles context from the user's own email/file archive → fills external form or drafts external message → writes outcome back to an internal tracking record.
**Deployability:** Claude Cowork with Gmail connector + browser tools, or Make/n8n with a Gmail trigger + Claude API + Browserbase. Weekend build for a single retailer flow, week build to generalize. Replaces administrative assistant or office-manager time. Scales down to one user — does not need enterprise data.

### 2. Issue triage workflow defined in plain-English Markdown, compiled to CI primitives
**Source:** [GitHub Agentic Workflows public preview, June 11, 2026](https://github.blog/changelog/2026-06-11-github-agentic-workflows-is-now-in-public-preview/) — GitHub shipped a system where you describe an agent's job in natural-language Markdown and the platform compiles it to standard Actions YAML.
**Mechanism:** Issue is opened or reopened in a repo. Compiled workflow boots a sandboxed runner with read-only repo permissions, hands the agent the issue body, lets it grep the codebase and scan recent issues for duplicates, then has it post a triage comment and apply labels. Same pattern ships for CI failure analysis (failed workflow run as trigger, logs and PR diff as context, comment with diagnosis as action) and docs updates. Replaces the maintainer's manual first-look triage and the on-call engineer's first-pass CI log review.
**Why agentic:** Authored as instructions ("read the issue, find duplicates, label it") rather than a state machine. The agent decides which labels apply and whether to ask the author for more detail. It runs unattended, on every issue, with no human in the loop.
**Generalizable core:** Plain-English playbook → compiled to an event-driven job on existing infrastructure → executes against a permissioned read of internal state → writes a structured action back to the same system. Same shape works for ticket triage in Zendesk, lead routing in HubSpot, or claim intake in any insurance back-office tool — the novelty is letting an ops person write the playbook in prose and have the platform generate the wiring.
**Deployability:** GitHub Actions native if you already use it; the broader pattern fits Temporal, Inngest, or n8n with a "natural-language → workflow" compile step. Week build to copy this for a non-GitHub system. Replaces the junior engineer or community manager doing first-touch triage. Caveat: read-only sandbox and per-action approval gates are load-bearing; do not skip them.

### 3. Contract redline agent inside the document editor
**Source:** [Freshfields and Anthropic co-build deployment of Claude for Legal](https://www.freshfields.com/en/our-thinking/news/news-search/2026/04/freshfields-and-anthropic-team-up-to-co-build-ai-legal-workflows-deploying-claude-across-the-firm-globally) — Claude for Legal launched with practice-area plugins and tracked-changes redline working directly inside the Word sidebar; Freshfields runs it on live client matters across 5,700 users.
**Mechanism:** Attorney opens a contract in Word. Claude for Word reads the document, cross-references each clause against Westlaw / LexisNexis / the firm's precedent library via iManage MCP, drafts tracked-changes redlines with a margin comment on each one explaining the risk and citing the precedent, and produces a risk summary. The attorney accepts, rejects, or asks for an alternate clause draft — all inside Word, no copy-paste between tools.
**Why agentic:** The agent decides which clauses are risky, picks which precedent to cite, drafts replacement language, and verifies each citation against the authoritative source. Not a dashboard showing "high-risk clauses"; the output is the marked-up document itself, ready to send.
**Generalizable core:** Domain document open in domain tool → agent fetches authoritative reference plus institutional precedent → annotates the document in-place with tracked changes and citations. Same skeleton works for medical chart review inside the EHR, engineering spec markup in CAD, or financial statement review inside Excel.
**Deployability:** At enterprise scale Claude for Legal plus iManage plus Westlaw plus Microsoft 365. The small-firm version: Claude API plus a Word add-in plus a Google Drive folder of precedent contracts plus public statute search. Month build at small-firm scale. Replaces the junior associate's first-pass contract review (1-3 hours per contract). Scale caveat: works at any firm size, but the verification step against an authoritative source is non-optional — without it, the redline is unsigned.
