# 2026-09-01 — Agent Pattern Scan

## TL;DR
Rowan is the most interesting today: Rocket Money shipped a consumer-facing agent that watches account activity continuously, texts the customer whenever it spots a saveable dollar, then executes the negotiation, cancellation, or transfer on approval. It moves the personal-finance product from "monthly report" to "always-on operator."

## Patterns

### 1. Proactive personal-finance agent that texts on spotted savings
**Source:** [Rocket Companies press release](https://www.rocketcompanies.com/press-release/rocket-moneys-rowan-rewrites-what-ai-can-do-in-personal-finance/) — Rocket Money launched Rowan, an Anthropic-powered agent, for its ~4M paying subscribers.
**Mechanism:** Rowan pulls linked account activity continuously → identifies a saveable action (recurring bill above market, forgotten subscription, roundup opportunity) → sends the customer a plain-text SMS → on a natural-language reply, executes the action (calls or web-flows the vendor to renegotiate, cancels the subscription, opens the savings transfer). When it hits an edge case (an unusual cancellation flow, a vendor that added a phone gate), it diagnoses and writes the fix into its runbook so every future customer benefits.
**Why agentic:** No user has to open the app. The trigger is a change in the customer's data, not a dashboard visit; the action is a real vendor interaction, not a recommendation card.
**Generalizable core:** Continuous read of a customer's transactional data → threshold-triggered nudge on the channel the customer already checks → customer approval by natural-language reply → agent executes on the third-party system.
**Deployability:** Claude API with a broad set of connectors (banking data provider, telephony for outbound calls, browser automation for cancellation flows), plus SMS as the user-facing surface. Week-plus build for a narrow bill class; a month-plus if you want to handle the long tail of vendor cancellation flows. Replaces the "monthly financial review" task and the customer's own admin time. Scale caveat: works because Rocket Money already has the bank-linkage relationship — starting a new deployment cold requires solving data access first.

### 2. Seven-specialist multi-agent pipeline for storm-triggered small claims
**Source:** [Allianz newsroom](https://www.allianz.com/en/mediacenter/news/articles/251103-when-the-storm-clears-so-should-the-claim-queue.html) and [The Digital Insurer case study](https://www.the-digital-insurer.com/gen-ai-library/allianz-project-nemo-claims-genai-case-study/) — Allianz Australia's Project Nemo, live for food-spoilage claims and being extended to motor and health under an Anthropic partnership.
**Mechanism:** A new claim (uploaded receipts, damage description, policy number) hits the pipeline → a Planner agent maintains process state and hands off to six specialists: Coverage (checks the policy for spoilage cover), Weather (verifies a qualifying storm at the address on the loss date), Fraud (runs pattern checks), Payout (calculates settlement), Audit (records the reasoning trail), and Cyber (enforces data-handling guardrails). For claims under AUD $500, the pipeline drafts a full settlement recommendation that a human adjuster approves in the last step. Small claims close in hours instead of days.
**Why agentic:** Each step is a specialist LLM with its own tools and its own read of the case, not fields on a form. The Planner routes between them and holds the state a case worker would normally hold in their head.
**Generalizable core:** Standardized inbound event → planner agent orchestrates a fixed cast of narrow-scope specialist agents (each with one tool and one job) → drafts a decision → human approves at a single point.
**Deployability:** Claude API with an orchestration layer (LangGraph, custom, or Claude's dynamic workflows), plus internal policy and weather data APIs. Month-plus build to do it well because the value is in the specialist prompts and the audit trail, not the plumbing. Replaces the first-pass adjuster's queue work on high-volume, low-complexity claim types. Scale caveat: mostly worth it when there's a repeatable claim class with a clear settlement ceiling.

### 3. Agent-controlled scientific instrument recovery
**Source:** [QuEra press release](https://www.quera.com/press-releases/quera-computing-uses-ai-to-automate-a-critical-quantum-computer-subsystem-enabling-the-acceleration-of-commercial-grade-quantum-computing-deployments-from-quera) and [Anthropic Model Hardware Standard preview](https://www.anthropic.com/news/model-hardware-standard-research-preview) — QuEra used Claude via Anthropic's new Model Hardware Standard to automate laser recovery on their neutral-atom quantum computers.
**Mechanism:** Lasers drift → an MHS-standardized device driver publishes state (frequency, lock quality, dropouts) → a Claude-powered controller reads the state, decides a recovery sequence, and issues commands back through the same driver within predefined safety limits. Recovered laser lock in 695/700 trials, cut residual noise 5x, eliminated dropouts overnight. The same standard was used to run a HHMI Janelia imaging workflow in a day instead of days, and a Genentech protein assay that recovered from real tip-pickup and fluid-detection failures without a human.
**Why agentic:** The agent isn't drafting a report about the laser — it is holding the laser on target, watching for drift, and executing the fix. What used to require a PhD walking to the lab at 2am now happens autonomously with an audit log.
**Generalizable core:** Standardized read/write interface over a physical instrument → agent perceives state and acts within safety bounds → replaces on-call specialist recovery of a narrow but high-value physical process.
**Deployability:** Claude API plus MHS drivers for the target hardware — MHS is a research preview today, so this is realistically month-plus and requires early-access enrollment or a custom analog. Replaces the on-call scientist or the operator watching a rack. Scale caveat: only relevant where you already have programmable, sensor-rich hardware and a specialist doing repetitive supervision on it — for now, mostly labs, semi-fab, industrial pilots, robotics.

### 4. New-client intake drafted end-to-end for a paralegal to edit
**Source:** [Automaton implementer's writeup on Cowork for law firms](https://automatonagency.com/insights/claude-cowork-for-law-firms) — reports across firms adopting Anthropic's Cowork legal plugin.
**Mechanism:** A new prospective-client packet arrives (intake questionnaire, engagement referral email, uploaded IDs) → Cowork reads the packet, pulls the firm's templates and prior matter conventions from Confluence or SharePoint, and produces first drafts of the engagement letter, fee agreement, conflict-check questionnaire, and scope-of-services attachment. A senior paralegal reviews for 20 minutes and edits from there; previously the same intake took ~90 minutes of drafting from templates.
**Why agentic:** Cowork isn't a chatbot the paralegal talks to about intake — it reads the packet, decides which templates and clauses apply given the client's facts, and produces the deliverables in the firm's actual document formats. The paralegal enters at the review step, not the drafting step.
**Generalizable core:** New-entity onboarding packet arrives → agent assembles context (templates, prior similar entities, policy) → drafts the full set of required boilerplate documents → human reviews at a single edit-and-sign step.
**Deployability:** Claude Cowork plugin plus the firm's document store integration (SharePoint/Confluence/iManage). Weekend build if you already have templates and Cowork licenses; week-plus if you also want conflict-check automation. Replaces the paralegal drafting hour on every new matter. Scale caveat: only worth it above ~5 new matters a week; below that the human is already efficient.
