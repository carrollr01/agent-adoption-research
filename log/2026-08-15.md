# 2026-08-15 — Agent Pattern Scan

## TL;DR
Notion shipped "Meeting-note-summarized" as a trigger for Custom Agents on July 31, turning the moment an AI-transcribed call finishes into a first-class workflow entry point. That's a new trigger class worth stealing — the artifact-completion event as fan-out signal. Also: Cyera + Claude Enterprise put a policy agent in-line on every prompt, and SafeSend Gather is quietly running the CPA intake loop as an autonomous multi-day chase.

## Patterns

### 1. Meeting-note completion as agentic trigger
**Source:** [Notion release, July 31 2026](https://www.notion.com/releases/2026-07-31) — Notion added "meeting note summarized" as a fireable trigger for its Custom Agents (live to all Business/Enterprise tenants, meeting-notes-heavy teams the target).
**Mechanism:** AI Meeting Notes finishes transcribing/summarizing a call → the completed note fires a Custom Agent → the agent reads the full note (attendees, decisions, action items, linked project/CRM record) → executes a fan-out: updates the project tracker row, drafts a recap to Slack or a follow-up email via Notion Mail, creates engineering tickets from feedback items, updates the deal record. Writes back into Notion, Slack, Notion Mail, and any connected system in the agent's config. Replaces the manager task of retyping the same meeting into five places.
**Why agentic:** Same note produces different actions per meeting because the agent reasons over the content (customer feedback → tickets, internal decision → tracker update, external prospect → CRM + follow-up email). No hard-coded flow — the agent decides which downstream systems apply.
**Generalizable core:** Completed artifact of type X → agent parses it → fans out per-system updates the artifact implies.
**Deployability:** Notion Business/Enterprise + Custom Agents ($10 per 1,000 Notion Credits) + whatever it connects to. Weekend build to wire one meeting type end-to-end. Replaces the manager/AE/PM task of manually distributing meeting outputs. Same pattern works with any "completed artifact" trigger: a signed contract, a filed ticket, a completed intake form, an inspection report — the trigger doesn't have to be a meeting.

### 2. In-line prompt DLP as governance agent
**Source:** [Cyera + Anthropic integration, May 2026, still expanding](https://www.businesswire.com/news/home/20260521071103/en/Cyera-Extends-AI-Security-to-Anthropics-Claude-Enterprise) — Cyera's Omni DLP now sits between employees and Claude Enterprise; named users include Paramount, Chipotle, Valvoline.
**Mechanism:** Employee submits a prompt to Claude Enterprise → Cyera intercepts before the model sees it → reads the prompt text + attached files + the user's data-access map → applies sensitivity policies (PII, source code, financial data, customer records) → decides allow / redact-and-forward / block-with-reason → logs the decision → returns modified prompt to Claude. Replaces after-the-fact access reviews and manual redaction training.
**Why agentic:** The decision is per-prompt policy reasoning against a live data map, not a static regex or DLP blocklist. Same prompt from two different users can resolve differently based on who is allowed to see what.
**Generalizable core:** Every LLM call → policy agent inspects → decides allow / redact / block against org data-sensitivity map → returns modified prompt to model.
**Deployability:** Enterprise-only right now — needs Cyera + Claude Enterprise contracts, and a real data-classification map to enforce against. Month-long compliance rollout. Not SMB-relevant today, but the pattern (agent-as-gate in front of an LLM call) is portable down-market: an SMB version could be a middleware Zapier/Node step that runs cheap classification on prompts before hitting a paid model.

### 3. AI client intake and document matching for tax firms
**Source:** [SafeSend Gather docs](https://safesendgather.zendesk.com/hc/en-us/articles/31437549429907-Document-Request-List-Overview) + [Canopy Smart Intake AI expansion](https://www.businesswire.com/news/home/20250916360485/en/Canopy-Smart-Intake-Expands-to-Include-AI-Driven-Document-Requests) — running at hundreds of US CPA firms; SafeSend reports 55% reduction in staff time spent chasing paperwork.
**Mechanism:** Preparer starts a new engagement in tax software → agent reads the prior-year return + engagement type + client's prior-year missing-doc history → generates a personalized document request list (W-2s that appeared last year, K-1s, mortgage interest, etc.) → sends it through the client portal → watches uploads → auto-matches each uploaded file to the correct line item on the request list → nudges the client on missing items on a cadence → hands the packaged, labeled folder to the preparer when complete. Replaces the admin who used to build the list, chase the client, and sort/label every upload.
**Why agentic:** The list is generated per-client from historical filings, not a template; the classifier decides which line item each upload satisfies; the nudge cadence adapts to how the client has responded historically. Multi-day, multi-turn, decision-per-document.
**Generalizable core:** New engagement created → agent builds bespoke intake list from prior history → chases and classifies uploads until complete → hands packaged bundle to human.
**Deployability:** Vertical SaaS (SafeSend/Canopy) does the heavy lifting; a firm can be live in a week. SMB CPA scale is exactly where it's running. Replaces admin/paraprofessional intake time. The same shape works for any recurring engagement with a per-client document list — insurance renewals, loan applications, onboarding for a bookkeeping client, contractor prequal packages.

### 4. After-hours voice agent that closes the dispatch loop
**Source:** [Vapi HVAC deployment writeups, Texas mid-sized operator](https://www.digitalapplied.com/blog/voice-ai-agents-business-elevenlabs-vapi-retell-bland); [Ksolves Vapi HVAC case study](https://www.ksolves.com/case-studies/ai-ml/vapi-voice-ai-assistant) — before deployment, ~40% of after-hours calls hit voicemail; after, they're answered, triaged, and scheduled with an on-call tech.
**Mechanism:** Inbound call outside business hours → voice agent picks up → looks up caller number against the CRM (existing customer vs new) → runs a triage script (no heat, water leak, smell of gas → emergency; noisy unit, thermostat won't program → next-business-day) → for emergencies, quotes the after-hours dispatch fee, gets verbal accept, checks the on-call rotation, books the slot in the dispatch calendar, texts the on-call tech the address plus a one-line issue summary, texts the caller a confirmation with ETA. Replaces the answering service and the dispatcher's morning triage backlog.
**Why agentic:** Multi-turn conversation with a real judgment call on urgency, live reads of the on-call schedule to pick the right tech, and writes to three systems in one call (dispatch calendar, tech SMS, customer SMS). Not a phone tree — it commits work.
**Generalizable core:** Off-hours inbound event → voice agent enriches with customer and schedule context → decides urgency → commits a human on-call and confirms with the requester.
**Deployability:** Vapi or Retell + a scheduling system (ServiceTitan, Housecall Pro, Jobber, or Google Calendar for the low end) + Twilio for SMS + a small CRM lookup. Week to two weeks to build for one operator. Fits any trades/services SMB with an on-call rotation — plumbing, electrical, veterinary emergency, locksmiths, tow. Voice-agent-for-reception patterns have been logged before; the new angle here is closing the dispatch loop (write to calendar + notify tech + confirm customer) rather than just answering and taking a message.
