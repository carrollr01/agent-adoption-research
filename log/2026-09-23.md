# 2026-09-23 — Agent Pattern Scan

## TL;DR
Six patterns cleared today. Most portable skeleton: tabular column-questions over a document set (Thomson Reuters CoCounsel), which is the same mechanism as procurement bid review, resume screening, RFP triage, and underwriting intake. Runner-up in scale: Carvana's alert-to-RCA-and-PR agent cut alert volume in one channel 56%.

## Patterns

### 1. Tabular column-questions over a document set
**Source:** https://www.thomsonreuters.com/en-us/help/cocounsel/legal/cocounsel-legal/tabular-analysis/review-documents — Thomson Reuters CoCounsel Tabular Analysis for discovery/diligence review, up to 10,000 documents by up to 100 column-questions per pass; the first live implementation of OpenAI's Astra-for-Law legal-tuned GPT-6 config (announced 2026-09-17).
**Mechanism:** Attorney uploads a doc set and defines column-questions (e.g. "governing law," "termination trigger," "cap on liability"). Agent iterates docs × columns, retrieves against a citation-grounded legal index, and emits per-cell answers with source citations into a filterable table stored on the matter. Re-runs cells when questions are edited mid-review. Replaces the first-pass associate/paralegal tagging pass.
**Why agentic:** the agent decides retrieval strategy per (doc, question) pair, runs a million-cell plan, and self-heals on question edits — not a report.
**Generalizable core:** upload a corpus + define a set of column-questions → agent fills a cited grid, one row per doc, one column per question, all searchable.
**Deployability:** the extraction loop is a weekend build over Claude + a vector store + a spreadsheet UI (Anthropic's Files API and structured outputs are enough). The moat is the citation-grounded index. Applies far outside legal: procurement contract review, RFP response scoring, insurance submission intake, resume/CV screening against a job spec, VC data-room diligence, HR handbook harmonization across acquisitions.

### 2. Production alert → root-cause + draft PR
**Source:** https://claude.com/customers/carvana — Carvana runs "Claude Tag" against production Slack alert channels for retail science, verification, and wholesale-platform teams. Reported result: 56% drop in alert volume in the retail-science channel.
**Mechanism:** A monitoring alert lands in a designated Slack channel. Agent reads the alert payload, recent merged PRs on the affected service, warehouse queries, log baselines from before the last deploy, runbooks, and domain systems (e.g. VIN lookup). It posts a formatted RCA in-thread, opens a draft PR with the proposed fix, files follow-up tickets, and adds logging where blind spots were found. Replaces the on-call engineer's first hour of triage.
**Why agentic:** the agent picks which tools to invoke, plans a multi-step investigation, and produces a code artifact (the PR) rather than a status tile.
**Generalizable core:** monitoring event → agent assembles code + telemetry + prior-change context → posts diagnosis and opens a fix artifact for human approval.
**Deployability:** Slack + GitHub + logs/warehouse via MCP + Claude Code SDK; week-to-month build depending on how clean the ownership/runbook metadata is. Scale caveat: works best when service ownership and recent-commit signal are clean; noisy monorepos need better change-scoping. The mechanism generalizes beyond SRE: any structured alert stream (fraud flag, compliance signal, safety violation) into a system with editable history.

### 3. Voice memo → invoice in the accounting system
**Source:** https://www.producthunt.com/products/smash-voice-to-invoice — SMASH voice-to-invoice for plumbers, electricians, HVAC techs; iOS app + Chrome/Gmail extension.
**Mechanism:** Tech taps record on the phone after a job and describes what was done ("replaced the 40-gallon Rheem, added an expansion tank, two hours labor for Sarah at 214 Maple"). Agent transcribes, disambiguates against the pre-synced customer contact list and line-item catalog from Xero or QuickBooks Online, drafts a quote or invoice, and on send pushes a new invoice object plus contact-ledger update into the accounting system. Replaces the end-of-day office-desk typing session, or the admin who otherwise chases the tech for line items.
**Why agentic:** free-speech input, catalog + customer disambiguation, and a decision on quote vs. invoice all happen without form fields.
**Generalizable core:** unstructured voice at the point of work → agent matches against a synced catalog of entities → writes a structured record into the system of record.
**Deployability:** weekend build over Whisper (or Deepgram) + Claude + Xero/QBO SDK. Real friction is the ongoing customer/product catalog sync, not the LLM. Copies to mobile home-health charting, mobile pet-grooming van invoicing, on-site inspection reports (plumbing rough-ins, roofing measurements), courier proof-of-delivery notes.

### 4. Post-purchase ops loop for e-commerce
**Source:** https://www.ycombinator.com/companies/pango — Pango (YC S26), $550K round, 30 global Shopify brands live; claim ~99% of returns/shipping ops automated, delivery-support tickets down 70%.
**Mechanism:** Shopify webhook fires on order event (return-requested, delivery exception, carrier-tracking anomaly). Agent reads the order, WMS inventory state, live carrier status across 100+ carriers, return-reason history for the SKU, and per-country policy. It decides exchange-first vs. refund vs. reroute, chooses a carrier/label, issues the refund in the right currency, pushes customer messaging into Klaviyo (email) and Gorgias (support inbox), and writes state back to Shopify and the WMS. Replaces the returns coordinator and the tier-1 shipping-support rep.
**Why agentic:** per-order policy + inventory decision across four+ systems, not a fixed Zapier path.
**Generalizable core:** system-of-record event → agent reads policy + inventory + downstream state → picks one branch of a decision tree → writes to every affected system + drafts the customer message.
**Deployability:** Shopify webhook + carrier APIs + WMS + Klaviyo/Gorgias. Weekend for a single-carrier PoC; production build is a month because per-country policy is the hard part. Same skeleton transplants to appointment-change ops for clinics (reschedule vs. cancel vs. waitlist-promote), field-service dispatch reshuffles, and hotel overbooking recovery.

### 5. Voice roleplay training agent
**Source:** https://claude.com/customers/impel — Impel (automotive AI) rolled a voice-based roleplay agent to 150+ customer-facing reps; built in ~3 weeks. Reported ramp time cut from 3–6 months to 1 month, escalations down 20% on new-product rollouts.
**Mechanism:** New product launch or new-hire onboarding triggers a "practice" session assigned to a rep. Agent reads ~150k historical Gong dealer calls and the Salesforce instance to build persona and objection banks, then opens a live voice session in-character as a specific customer type (e.g. GM prepping for a floor meeting). It turn-takes over STT/TTS, scores the call against a rubric (objection handling, rapport, product knowledge, close), and drops a scorecard into Slack for the manager. Replaces the VP or solutions engineer who used to shadow reps for weeks.
**Why agentic:** open-ended two-way conversation with in-context grading; not a scripted eLearning module.
**Generalizable core:** past-call archive + CRM context → agent plays a synthetic counterparty in live voice → scores the human on a rubric → writes the scorecard to the manager.
**Deployability:** Vapi/Retell/LiveKit + Claude + Gong (or Fireflies, Gong-alternate) API + Salesforce (or any CRM). Week for v1; the harder work is rubric-alignment, which took Impel 1–2 months. Copies to insurance-claim adjuster training, healthcare cold-outreach (payer calls, referring-physician calls), inbound support agents, admissions counselors at colleges, front-of-house restaurant training on difficult guests.

### 6. Cross-document consistency checker for engineering deliverables
**Source:** https://www.usetorus.com/ , https://www.ycombinator.com/companies/torus — Torus (YC S26), profiled in the 2026-09-03 Forbes YC roundup; targeted at EPC and infrastructure engineering firms.
**Mechanism:** An engineer uploads or updates a P&ID, heat-and-material balance, spec sheet, or equipment datasheet into a project workspace. Agent parses every parameter (pump flow rate, line diameter, material grade, pressure rating), cross-references it against every other doc in the project set, and flags mismatches (e.g. pump datasheet spec vs. line list vs. instrumentation datasheet). Writes flag comments back into the doc set and a status feed for the PM. Replaces the junior engineer's cross-doc reconciliation pass and the QA/checker cycle before design review.
**Why agentic:** doc-relevance selection + typed extraction + equivalence reasoning, not a diff tool.
**Generalizable core:** doc uploaded → agent parses fields → compares against every other doc in a bounded set → posts structured mismatch flags where the docs live.
**Deployability:** PDF/CAD/XLS parsing + vector store + Claude reasoning + a doc-management integration (SharePoint, Aconex, Procore). Month-plus build; the field ontology is domain-specific per firm. Same skeleton fits construction submittal packages vs. approved specs, medical device design-history-file consistency, franchise-brand compliance across store operations manuals, and clinical-trial protocol-vs-CRF cross-checks.
